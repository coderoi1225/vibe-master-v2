## 왜 이걸 하나

AI에게 화면을 만들어 달라고 하면 매번 색이 다릅니다. 간격도 다릅니다.
어제 만든 화면과 오늘 만든 화면이 **같은 서비스로 안 보입니다.**

이유는 단순합니다. **AI는 내 브랜드 색과 간격을 모릅니다.**
말해 주지 않으면 매번 자기가 아는 흔한 값을 씁니다.
그리고 대화는 사라집니다. 새 대화를 열면 어제 말한 색은 없던 일이 됩니다.

그래서 **파일에 적습니다.** 파일에 적힌 것은 사라지지 않고, AI가 매번 읽습니다.
이 절에서 만드는 규칙표가 **[[03-컨텍스트하네스/_스테이지|Stage 3]]에서 만든 지침 파일 안으로 들어갑니다.**
그러면 이후 AI가 만드는 모든 화면이 같은 값을 씁니다. **여기가 이 커리큘럼의 연결 지점입니다.**

## 핵심 — 색을 코드가 아니라 이름으로 저장한다

가장 흔한 실수는 이렇게 적는 것입니다.

```
버튼 색: #0057FF
```

이러면 파랑을 바꾸고 싶을 때 `#0057FF`가 박힌 곳을 전부 찾아 고쳐야 합니다.
그리고 AI에게 "파랑 말고 다른 색으로"라고 하면 **어디까지가 그 파랑인지 AI가 모릅니다.**

이름으로 저장하면 달라집니다.

```
주색 = #0057FF
주색-누를때 = #0043CC
글자-기본 = #1C1B19
글자-흐림 = #6B675F
배경 = #FBFAF8
선 = #E3DFD7
```

그리고 화면에서는 `#0057FF`가 아니라 **`주색`**이라고 씁니다.
나중에 주색 한 줄만 바꾸면 **화면 전체가 같이 바뀝니다.**

이렇게 "값에 이름을 붙여 한곳에 모아 둔 것"을 실무에서는 **디자인 토큰**이라고 부릅니다.
이름은 몰라도 됩니다. **중요한 건 값이 한곳에만 있다는 것**입니다.

## 규칙표에 들어갈 세 종류

세 종류면 충분합니다. 더 넣으면 관리가 안 됩니다.

| 종류 | 몇 개 | 예 |
|---|---|---|
| **색** | 주색 1 · 강조 1 · 무채색 4~5 | `주색` `강조` `글자-기본` `글자-흐림` `배경` `선` |
| **간격** | 5개 | `간격-1`=4 · `간격-2`=8 · `간격-3`=16 · `간격-4`=24 · `간격-5`=32 |
| **글자** | 글꼴 1 · 크기 3~5단계 | `글꼴`=Pretendard · `큰제목` `중제목` `본문` `작은글` |

여기에 필요하면 **모서리 둥글기** 두 개(`둥글기-작게` `둥글기-크게`) 정도만 더 붙입니다.

## 어디에 두나 — 두 곳에 같은 값을 둔다

| 어디 | 무엇을 위해 |
|---|---|
| **피그마** | 사람이 눈으로 보고 고르기 위해. 변수로 등록해 두면 화면을 그릴 때 목록에서 고릅니다 |
| **지침 파일**(Stage 3에서 만든 것) | **AI가 읽기 위해.** 코드를 만들 때 AI가 매번 이 값을 씁니다 |

둘 중 하나만 고르라면 **지침 파일이 먼저**입니다.
피그마에만 있는 값은 AI가 못 읽습니다. **파일에 적힌 값만 실제로 지켜집니다.**

두 곳에 있으면 어긋날 수 있으니, **고칠 때는 지침 파일을 먼저 고치고 피그마를 따라 맞춥니다.**
값의 집은 한 곳입니다.

## 규칙표 본보기 — 이대로 채우면 됩니다

```markdown
## 디자인 규칙 (이 파일이 정본이다. 여기 없는 값은 쓰지 않는다)

### 색
| 이름 | 값 | 어디에 |
|---|---|---|
| 주색 | #0057FF | 가장 중요한 버튼, 링크 |
| 주색-누를때 | #0043CC | 위 버튼을 누르는 순간 |
| 강조 | #D9480F | 경고·주의. 화면당 한 번을 넘기지 않는다 |
| 글자-기본 | #1C1B19 | 본문 |
| 글자-흐림 | #6B675F | 설명, 날짜 |
| 배경 | #FBFAF8 | 화면 바탕 |
| 선 | #E3DFD7 | 테두리, 구분선 |

### 간격 (4의 배수만)
4 / 8 / 16 / 24 / 32 — 이 다섯 외의 값은 쓰지 않는다.
요소 안은 4, 요소 사이는 8부터.

### 글자
글꼴: Pretendard 하나만. 굵기는 보통과 굵게 둘.
크기 단계: 큰제목 / 중제목 / 본문 / 작은글 — 네 개까지.

### 지켜야 할 최소선
- 본문 글자 대비 4.5:1 이상, 큰 글자 3:1 이상
- 누를 수 있는 것은 24×24px 이상
- 화면 크기 구분점은 3개만 쓴다

### 하지 말 것
- 위 목록에 없는 색을 새로 만들지 않는다
- 그라디언트를 쓰지 않는다
- 글꼴을 추가하지 않는다
```

## 📘 말 풀이

**디자인 토큰(design token)**
색·간격·글자 크기 같은 값에 이름을 붙여 한곳에 모아 둔 목록. "값의 사전"입니다. 국제 표준으로도 정리가 진행 중입니다.

**변수(variable)**
피그마에서 값에 이름을 붙여 등록해 두는 기능. 등록해 두면 색을 고를 때 색상판이 아니라 이름 목록에서 고르게 됩니다.

## ⚠️ 자주 걸리는 함정

- **머릿속에만 두고 매번 말로 알려줍니다.** 새 대화를 열면 사라집니다. 파일에 없으면 없는 것입니다.
- **색을 열두 개 만듭니다.** 많을수록 안 지켜집니다. 일곱 개 안쪽으로 시작합니다. 모자라면 그때 늘립니다.
- **이름을 색깔로 짓습니다.** `파랑`이라고 지으면 나중에 초록으로 바꿀 때 `파랑 = 초록`이라는 이상한 줄이 남습니다. **역할로 짓습니다** — `주색` `강조` `글자-흐림`.
- **피그마에만 등록합니다.** AI는 못 읽습니다. 지침 파일이 먼저입니다.
- **"하지 말 것"을 안 적습니다.** AI는 금지 목록이 없으면 자기가 아는 흔한 것을 넣습니다(4절 참고).

## ⚡ 이렇게 하세요

1. 위 본보기를 그대로 복사해 **[[03-컨텍스트하네스/_스테이지|Stage 3]]에서 만든 지침 파일 맨 아래에 붙입니다.**
2. 색 값 일곱 개를 내 것으로 바꿉니다. 아직 브랜드 색이 없으면 **아무 파랑 하나**로 시작합니다. 나중에 한 줄만 고치면 됩니다.
3. 피그마를 열고 같은 값을 **변수로 등록**합니다. 이름은 지침 파일과 **똑같이** 씁니다.
4. AI에게 아래를 붙여넣어 규칙이 실제로 읽히는지 확인합니다.

```
지침 파일의 「디자인 규칙」 절만 읽고, 아래를 답해줘.
1. 내가 정한 주색과 강조색을 값으로 알려줘
2. 내가 쓸 수 있는 간격 값을 전부 나열해줘
3. 내가 금지한 것을 나열해줘
그다음, 이 규칙만 써서 버튼 하나와 카드 하나를 만들어줘.
규칙에 없는 값을 쓰게 되면 만들지 말고 "규칙에 없다"고 말해줘.
```

5. 마지막 줄이 중요합니다. **AI가 "규칙에 없다"고 말하면 규칙표가 실제로 작동하는 것입니다.**

### 이렇게 해 봤습니다 — 2026-09-09

피그마에 빈 파일을 하나 만들고 **규칙표를 변수 7개로** 넣어 봤습니다. 색 3개(주색·강조·글자)와 간격 4개(안 4 · 사이 8 · 구역 24 · 큰 32).
그 변수에 묶은 히어로 화면 하나를 만들고, **그것을 코드로 다시 받아** 봤습니다.

```
background: var(--색/주색, #1f7a5c)
gap:        var(--간격/구역, 24px)
```

**변수 이름이 한글 그대로 살아서 코드에 나왔습니다.** 값을 손으로 적지 않아도 이름이 따라옵니다.

그런데 하나가 걸렸습니다. **글자 색은 변수로 안 묶었더니 코드에 `white`로 박혀 나왔습니다.**
같은 화면 안에서도 **묶은 것만 변수로 나오고, 안 묶은 것은 그냥 값으로 나옵니다.**
그래서 규칙표는 만드는 것으로 끝이 아니라, **화면의 모든 색·간격을 거기에 묶어야** 값을 합니다.

## ✅ 됐는지 확인

- [ ] 색 · 간격 · 글꼴을 **파일에** 적었나 (머릿속 말고 파일)
- [ ] 색 이름이 **역할 이름인가** (`주색`이지 `파랑`이 아닌가)
- [ ] 그 파일이 **Stage 3의 지침 파일 안에** 있나
- [ ] 「하지 말 것」 줄이 **적어도 세 개** 있나
- [ ] AI에게 물었을 때 **내가 적은 값 그대로** 답이 돌아왔나

하나라도 «아니오»면 이 절을 다시 봅니다. 이 표가 없으면 뒤의 모든 절이 매번 흔들립니다.
