AI에게 화면을 만들어 달라고 하면 매번 색과 간격이 다릅니다 — AI는 내 브랜드 값을 모르고, 새 대화를 열면 어제 말한 것은 사라지기 때문입니다. 그래서 파일에 적고, 그 파일을 [[03-컨텍스트하네스/_스테이지|Stage 3]]의 지침 파일 안에 넣습니다 — 여기가 이 커리큘럼의 **연결 지점**입니다.

## ① 색을 이름으로 저장한다

가장 흔한 실수는 `버튼 색: #0057FF`처럼 값을 바로 적는 것입니다. 파랑을 바꾸고 싶을 때 `#0057FF`가 박힌 곳을 전부 찾아야 하고, AI에게 "파랑 말고"라고 해도 어디까지가 그 파랑인지 모릅니다.

이름을 붙이면 달라집니다.

```
주색 = #0057FF
주색-누를때 = #0043CC
글자-기본 = #1C1B19
글자-흐림 = #6B675F
배경 = #FBFAF8
선 = #E3DFD7
```

화면에서는 `#0057FF` 대신 `주색`이라고 쓰세요. 나중에 주색 한 줄만 바꾸면 화면 전체가 같이 바뀝니다. 실무에서는 이것을 디자인 토큰이라고 부르지만, 중요한 건 **값이 한곳에만 있다**는 것입니다.

## ② 세 종류만 정한다

세 종류면 충분하고, 더 넣으면 관리가 안 됩니다.

| 종류 | 몇 개 | 예 |
|---|---|---|
| 색 | 주색 1 · 강조 1 · 무채색 4~5 | `주색` `강조` `글자-기본` `글자-흐림` `배경` `선` |
| 간격 | 5개 | `간격-1`=4 · `간격-2`=8 · `간격-3`=16 · `간격-4`=24 · `간격-5`=32 |
| 글자 | 글꼴 1 · 크기 3~5단계 | `글꼴`=Pretendard · `큰제목` `중제목` `본문` `작은글` |

필요하면 **모서리 둥글기** 둘(`둥글기-작게` `둥글기-크게`)만 더 붙입니다.

## ③ 두 곳에 같은 값을 둔다

| 어디 | 무엇을 위해 |
|---|---|
| 피그마 | 사람이 눈으로 보고 고르기 위해. 변수로 등록하면 화면을 그릴 때 목록에서 고릅니다 |
| 지침 파일(Stage 3) | AI가 읽기 위해. 코드를 만들 때 AI가 매번 이 값을 씁니다 |

둘 중 하나만 고르라면 **지침 파일이 먼저**입니다. 피그마에만 있는 값은 AI가 못 읽습니다. 고칠 때는 지침 파일을 먼저 고치고 피그마를 따라 맞춥니다 — 값의 집은 한 곳입니다.

## ④ 본보기를 채운다

아래를 그대로 복사해 값만 내 것으로 바꾸면 됩니다.

```markdown
[디자인 규칙] 이 파일이 정본이다. 여기 없는 값은 쓰지 않는다.

[색]
| 이름 | 값 | 어디에 |
|---|---|---|
| 주색 | #0057FF | 가장 중요한 버튼, 링크 |
| 주색-누를때 | #0043CC | 위 버튼을 누르는 순간 |
| 강조 | #D9480F | 경고·주의. 화면당 한 번을 넘기지 않는다 |
| 글자-기본 | #1C1B19 | 본문 |
| 글자-흐림 | #6B675F | 설명, 날짜 |
| 배경 | #FBFAF8 | 화면 바탕 |
| 선 | #E3DFD7 | 테두리, 구분선 |

[간격] 4의 배수만
4 / 8 / 16 / 24 / 32 — 이 다섯 외의 값은 쓰지 않는다.
요소 안은 4, 요소 사이는 8부터.

[글자]
글꼴: Pretendard 하나만. 굵기는 보통과 굵게 둘.
크기 단계: 큰제목 / 중제목 / 본문 / 작은글 — 네 개까지.

[지켜야 할 최소선]
- 본문 글자 대비 4.5:1 이상, 큰 글자 3:1 이상
- 누를 수 있는 것은 24×24px 이상
- 화면 크기 구분점은 3개만 쓴다

[하지 말 것]
- 위 목록에 없는 색을 새로 만들지 않는다
- 그라디언트를 쓰지 않는다
- 글꼴을 추가하지 않는다
```

「하지 말 것」이 있어야 AI가 흔한 것을 멋대로 넣지 않습니다. 4절에서 다섯 줄이 더 붙습니다.

## ⚡ 따라 하기

1. 위 본보기를 복사해 **[[03-컨텍스트하네스/_스테이지|Stage 3]] 지침 파일 맨 아래**에 붙이세요. 파일에 있어야 AI가 매번 읽기 때문입니다. 지침 파일 끝에 「디자인 규칙」 덩어리가 보이면 됩니다.
2. 색 값 일곱 개를 내 것으로 바꾸세요. 아직 브랜드 색이 없으면 아무 파랑 하나로 시작해도 됩니다 — 나중에 한 줄만 고치면 되기 때문입니다.
3. 피그마를 열고 같은 값을 변수로 등록하세요. 이름은 지침 파일과 똑같이 씁니다 — 이름이 다르면 두 곳이 어긋납니다. 색을 고를 때 색상판 대신 이름 목록이 뜨면 됩니다.
4. AI에게 아래를 붙여넣어 규칙이 실제로 읽히는지 확인하세요. 답에 내가 적은 값이 그대로 나와야 합니다.

```
지침 파일의 「디자인 규칙」 절만 읽고, 아래를 답해줘.
1. 내가 정한 주색과 강조색을 값으로 알려줘
2. 내가 쓸 수 있는 간격 값을 전부 나열해줘
3. 내가 금지한 것을 나열해줘
그다음, 이 규칙만 써서 버튼 하나와 카드 하나를 만들어줘.
규칙에 없는 값을 쓰게 되면 만들지 말고 "규칙에 없다"고 말해줘.
```

5. 마지막 줄을 보세요. AI가 "규칙에 없다"고 말하면 규칙표가 실제로 작동하는 것입니다.

### 이렇게 해 봤습니다 — 2026-09-09

피그마에 빈 파일을 만들고 규칙표를 변수 7개로 넣어 봤습니다 — 색 3개(주색·강조·글자)와 간격 4개(안 4 · 사이 8 · 구역 24 · 큰 32). 그 변수에 묶은 히어로 화면 하나를 만들고 코드로 다시 받았더니, **변수 이름이 한글 그대로** 코드에 나왔습니다.

```
background: var(--색/주색, #1f7a5c)
gap:        var(--간격/구역, 24px)
```

하나가 걸렸습니다. 글자 색은 변수로 안 묶었더니 코드에 `white`로 박혀 나왔습니다. 묶은 것만 변수로 나오고 안 묶은 것은 그냥 값으로 나오니, 규칙표는 만드는 것으로 끝이 아니라 화면의 모든 색·간격을 거기에 묶어야 값을 합니다.

## ✅ 확인

- [ ] 색 · 간격 · 글꼴이 머릿속이 아니라 Stage 3의 지침 파일 안에 있나
- [ ] 색 이름이 역할 이름인가 (`주색`이지 `파랑`이 아닌가)
- [ ] 「하지 말 것」 줄이 적어도 세 개 있나
- [ ] AI에게 물었을 때 내가 적은 값 그대로 답이 돌아왔나

하나라도 «아니오»면 이 절을 다시 봅니다. 이 표가 없으면 뒤의 모든 절이 매번 흔들립니다.

## 📘 말 풀이

**디자인 토큰(design token)** — 색·간격·글자 크기 같은 값에 이름을 붙여 한곳에 모아 둔 목록. "값의 사전"입니다.

**변수(variable)** — 피그마에서 값에 이름을 붙여 등록해 두는 기능. 색을 고를 때 색상판이 아니라 이름 목록에서 고르게 됩니다.

## ⚠️ 함정

**머릿속에만 두고 매번 말로 알려줍니다.** 새 대화를 열면 사라집니다. 파일에 없으면 없는 것입니다.

**색을 열두 개 만듭니다.** 많을수록 안 지켜집니다. 일곱 개 안쪽으로 시작하고, 모자라면 그때 늘립니다.

**이름을 색깔로 짓습니다.** `파랑`이라고 지으면 나중에 초록으로 바꿀 때 `파랑 = 초록`이라는 이상한 줄이 남습니다. 역할로 짓습니다 — `주색` `강조` `글자-흐림`.

**피그마에만 등록합니다.** AI는 못 읽습니다. 지침 파일이 먼저입니다.
