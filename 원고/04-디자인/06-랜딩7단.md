## 왜 이걸 하나

서비스를 만들면 결국 **"이게 뭔지 설명하는 한 페이지"**가 필요합니다. 랜딩 페이지입니다.
처음 만드는 사람이 여기서 하는 실수는 늘 같습니다. **너무 많이 넣습니다.**

만든 사람은 다 말하고 싶습니다. 회사 이야기, 만든 계기, 기술 설명, 팀 소개.
읽는 사람은 **"이게 나한테 무슨 소용인가"** 하나만 알고 싶습니다.

이 절의 순서와 금지 목록은 그 간격을 좁히는 장치입니다.
여기서 정한 구조가 [[05-구현/_스테이지|Stage 5]]에서 실제 코드가 됩니다.

## 위에서부터 일곱 칸

읽는 사람이 스크롤을 내리는 순서가 곧 설득의 순서입니다. 순서를 바꾸지 않습니다.

| 순서 | 무엇 | 지킬 것 |
|---|---|---|
| **1** | **헤드라인** | 이 서비스가 **누구의 무엇을 해결하는지** 한 줄. 회사 이름이 아니라 **상대의 문제**를 씁니다 |
| **2** | **가치 제안** | **30단어 안쪽.** 헤드라인을 풀어 주는 두세 줄. 길어지면 아무도 안 읽습니다 |
| **3** | **버튼 하나** | **하나입니다.** 여기서 무엇을 하길 바라는가. 둘 이상이면 선택을 미룹니다 |
| **4** | **사회적 증거** | 쓰는 사람 수, 후기, 로고, 실제 화면. 없으면 **비워 두고 생기면 채웁니다.** 지어내지 않습니다 |
| **5** | **근거 3~5개** | 왜 되는지. 기능이 아니라 **결과**로 씁니다. 셋에서 다섯 사이 |
| **6** | **입력칸 3개 이하** | 가입·문의 폼. 이름·이메일 정도. 칸이 늘수록 사람은 나갑니다 |
| **7** | **자주 묻는 질문** | 사기 전에 걸리는 걱정 넷에서 여섯 개. **"환불되나요" 같은 불편한 것부터** |

버튼(3번)은 아래쪽에 **한 번 더** 놓아도 됩니다. 다만 **같은 문구, 같은 곳으로 가는 것**이어야 합니다.
문구가 다르면 다른 선택지로 읽힙니다.

## 빼야 할 여섯

이게 이 절의 진짜 내용입니다. **넣는 것보다 빼는 게 어렵습니다.**

| 빼는 것 | 왜 |
|---|---|
| **회사 연혁** | 처음 온 사람은 회사에 관심이 없습니다. 자기 문제에 관심이 있습니다 |
| **팀 소개** | 신뢰를 주려는 의도지만, 처음 온 사람에게는 모르는 사람 얼굴입니다. 별도 페이지로 |
| **로고 슬라이더** | 옆으로 흐르는 협력사 로고 띠. 눈을 끌어당기고 아무 정보도 주지 않습니다 |
| **버튼 여러 개** | "가입하기 / 더 알아보기 / 문의하기"가 나란히 있으면 사람은 **아무것도 안 누릅니다** |
| **자동으로 넘어가는 배너** | 읽는 중에 넘어갑니다. 읽는 사람이 속도를 못 정합니다 |
| **자동재생 영상** | 소리가 나면 사람은 창을 닫습니다. 데이터도 씁니다 |

뒤의 셋(로고 슬라이더·자동 배너·자동재생)은 **접근성에서도 문제**입니다.
스스로 움직이는 것은 멈출 수단이 있어야 합니다. 7절에서 다시 나옵니다.

## 헤드라인 쓰는 법 — 주어를 바꾼다

가장 잘 듣는 방법 하나만 말하면 이것입니다. **주어를 나에서 상대로 바꿉니다.**

| 이렇게 말고 | 이렇게 |
|---|---|
| "AI 기반 뉴스레터 자동화 솔루션" | "매주 뉴스레터 쓰는 데 세 시간 쓰고 있다면" |
| "저희는 10년 경력의…" | "발송 전에 오타를 잡아 드립니다" |
| "혁신적인 워크플로 플랫폼" | "같은 자료를 두 번 정리하지 않게" |

왼쪽은 **내가 무엇인지**를 말하고, 오른쪽은 **상대가 무엇을 겪는지**를 말합니다.
사람은 자기 이야기가 나오면 멈춥니다.

## 📘 말 풀이

**랜딩 페이지(landing page)**
광고나 링크를 타고 처음 도착하는 한 페이지. 여기서 설명이 끝나고 행동이 정해집니다.

**가치 제안(value proposition)**
"당신에게 이런 이득이 있다"를 짧게 말한 문장. 기능 설명이 아니라 상대가 얻는 결과를 씁니다.

**사회적 증거(social proof)**
"다른 사람도 쓰고 있다"를 보여 주는 것. 사용자 수, 후기, 쓰는 회사 로고, 실제 화면 등.

## ⚠️ 자주 걸리는 함정

- **버튼을 여러 개 놓습니다.** 선택지를 주면 친절해 보이지만 실제로는 아무것도 안 누릅니다. **하나만.**
- **입력칸을 늘립니다.** "이왕 받는 김에 회사명도, 직급도"라고 생각하는 순간 사람이 나갑니다. **셋 이하.**
- **사회적 증거를 지어냅니다.** 없는 후기를 만들거나 안 쓰는 회사 로고를 넣지 않습니다. **비워 두는 편이 낫습니다.**
- **자주 묻는 질문에 편한 질문만 씁니다.** 진짜 걱정(가격·환불·해지·내 자료가 어디로 가나)을 안 다루면 아무 소용이 없습니다.
- **전환율 숫자를 근거로 씁니다.** 마케팅 글에 도는 "○○% 상승" 수치는 대부분 원본이 확인되지 않은 재인용입니다. 쓸 거면 **"업계에서 흔히 말하는"**이라고 붙이고, 판단은 내 화면에서 직접 확인한 것으로 합니다.

## ⚡ 이렇게 하세요

1. 종이에 **일곱 칸을 세로로** 그리고 각 칸에 들어갈 문장을 손으로 씁니다. 아직 화면을 만들지 않습니다.
2. 2번 칸(가치 제안)의 **단어를 세어 봅니다.** 30단어를 넘으면 자릅니다.
3. 「빼야 할 여섯」을 소리 내어 읽고, **이미 넣을 생각을 했던 것**에 표시합니다.
4. AI에게 아래를 붙여넣습니다.

```
아래 정보로 랜딩 페이지 한 장을 만들어줘. 지침 파일의 「디자인 규칙」을 그대로 지켜줘.

- 무엇: (서비스 한 줄)
- 누구를 위해: (Stage 1에서 정한 고객)
- 그 사람이 지금 겪는 문제: (한 줄)
- 여기서 하길 바라는 행동 하나: (예 — 이메일 남기기)

구조는 위에서부터 이 순서를 지켜줘.
헤드라인 → 30단어 이하 가치 제안 → 버튼 하나 → 사회적 증거 자리 → 근거 3~5개 → 입력칸 3개 이하 → 자주 묻는 질문

그리고 아래는 절대 넣지 마.
회사 연혁 / 팀 소개 / 로고 슬라이더 / 버튼 두 개 이상 / 자동으로 넘어가는 배너 / 자동재생 영상

헤드라인은 우리 회사가 무엇인지가 아니라 상대가 무엇을 겪는지로 시작해줘.
사회적 증거는 지어내지 말고 "여기에 후기가 들어갑니다"라고 자리만 비워둬.
```

5. 나온 결과에서 **버튼 개수와 입력칸 개수를 직접 세어 봅니다.** AI는 자주 늘립니다.
