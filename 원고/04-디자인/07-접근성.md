## 왜 이걸 하나

접근성은 "여유 있으면 나중에" 항목으로 밀리기 쉽습니다.
그런데 두 가지 이유로 **지금 해야 합니다.**

첫째, **나중에 하면 다시 만들어야 합니다.**
연한 회색 글자를 백 군데 깔아 놓고 나중에 고치는 것보다, 규칙표에 대비 값을 넣어 두는 게 훨씬 쌉니다.

둘째, **법의 자리가 있습니다.**
한국에서 **법인**이 운영하는 웹사이트는 원칙적으로 적용 대상입니다. 아래에서 정확히 짚습니다.

여기서 다루는 건 셋뿐입니다. 전문가 수준의 완전한 접근성이 아니라,
**혼자 만드는 사람이 지금 당장 지킬 수 있는 최소선**입니다.

## 하나 — 대비: 재야 하는 값이다

1절에서 나온 숫자를 다시 씁니다.

| 무엇 | 최소 |
|---|---|
| 본문 글자 | **4.5 : 1** |
| 큰 글자 | **3 : 1** |
| 버튼 테두리·아이콘 같은 부품 | **3 : 1** |

**눈짐작은 통하지 않습니다.** 만든 사람은 자기 화면 밝기와 자기 눈으로 봅니다.
햇빛 아래 휴대폰, 오래된 모니터, 나이 든 눈에서는 전혀 다르게 보입니다.

**재는 법** — 대비 계산기에 글자색과 배경색 값 두 개를 넣으면 숫자가 나옵니다.
브라우저의 개발자 도구에서도 색을 고르면 대비 값이 같이 표시됩니다.
AI에게 두 색 값을 주고 계산시켜도 됩니다. 어떤 방법이든 **숫자를 봐야 합니다.**

가장 자주 걸리는 자리 셋 — **회색 설명 글자 · 비활성 버튼 글자 · 이미지 위에 올린 흰 글자.**

## 둘 — 키보드만으로 조작되나

마우스를 못 쓰는 사람이 있습니다. 손이 불편한 경우도 있고, 화면을 못 보는 경우도 있습니다.
그 사람들은 **탭 키로 이동하고 엔터로 누릅니다.**

확인은 30초면 됩니다.

1. 마우스에서 손을 뗍니다
2. **탭 키를 계속 누릅니다**
3. 지금 어디에 있는지 **테두리로 보이나요?**
4. 순서가 **위에서 아래, 왼쪽에서 오른쪽**으로 자연스럽나요?
5. 모든 버튼과 링크에 **닿을 수 있나요?**
6. 창(팝업)이 열렸을 때 **탭이 그 안에 머무나요?** 그리고 **Esc로 닫히나요?**

가장 흔한 실패는 **테두리를 없앤 것**입니다.
"파란 테두리가 못생겨서" 지우는 경우가 많은데, 그러면 키보드 쓰는 사람은 **자기가 어디 있는지 못 봅니다.**
지우지 말고 **내 규칙표 색으로 바꿉니다.**

## 셋 — 이미지 대체 텍스트

화면을 못 보는 사람은 화면 읽어 주는 프로그램으로 웹을 씁니다.
그 프로그램은 이미지를 **대체 텍스트**로 읽습니다. 없으면 "이미지"라고만 말하고 지나갑니다.

쓰는 법은 세 줄입니다.

- **내용이 있는 이미지** — 무엇이 보이는지 짧게. "노트북 앞에서 메모하는 사람"
- **글자가 들어 있는 이미지** — **그 글자를 그대로** 적습니다. 카드뉴스가 여기 해당합니다
- **장식일 뿐인 이미지** — **비워 둡니다.** 의미 없는 것을 읽어 주면 방해가 됩니다

"이미지", "사진", "그림"이라고 적는 건 안 적은 것과 같습니다.

## ⚠️ 한국 법의 자리 — 법인이면 적용 대상입니다

여기는 정확하게 씁니다.

**장애인차별금지 및 권리구제 등에 관한 법률(장차법)** 시행령 별표3은
웹 접근성 의무를 적용받는 기관·사업자를 단계적으로 확대해 왔고,
마지막 단계에서 **"그 밖의 모든 법인"**이 포함되었습니다. 시행 시점은 **2013년 4월 11일**입니다.

즉 **법인 형태로 사업을 한다면, 규모가 작더라도 원칙적으로 적용 대상**입니다.

혼동하기 쉬운 것 하나를 짚습니다.
**웹 접근성 인증(마크)을 받는 심사는 임의입니다.** 안 받아도 됩니다.
그러나 **인증을 안 받는 것과 접근성 의무가 없는 것은 다른 이야기**입니다.
인증은 선택이고, 차별하지 않을 의무는 법에 있습니다.

> ***"1인 기업이라 안 해도 된다"는 말은 쓰지 않습니다.*** 근거가 없습니다.

**[확인 필요]**로 남기는 것 둘 — 실제 **집행·제재의 강도**가 소규모 법인에 어떻게 적용되는지,
그리고 **법인이 아닌 개인사업자가 단독으로 운영하는 사이트**의 적용 범위.
이 둘은 이 커리큘럼에서 1차 자료로 확인하지 못했습니다. 필요하면 변호사나 관련 기관에 확인합니다.

이 절에서 확실한 것은 하나입니다.
**대비 · 키보드 · 대체 텍스트 셋은 어느 경우에도 기본이고, 셋 다 오늘 안에 할 수 있습니다.**

## 📘 말 풀이

**대체 텍스트(alt text)**
이미지에 붙이는 글 설명. 화면을 못 보는 사람이 쓰는 읽어 주는 프로그램이 이 글을 대신 읽습니다.

**포커스 표시(focus indicator)**
키보드로 이동할 때 "지금 여기 있다"를 보여 주는 테두리. 없애면 키보드 사용자가 길을 잃습니다.

**웹 접근성 인증**
접근성 기준을 지켰는지 심사받고 표시를 받는 제도. **심사를 받는 것은 임의**이며, 안 받는다고 접근성 의무가 없어지는 것은 아닙니다.

## ⚠️ 자주 걸리는 함정

- **연한 회색이 세련돼 보여서 그대로 둡니다.** 가장 흔한 위반입니다. 재 보면 대부분 4.5:1에 못 미칩니다.
- **파란 테두리를 지웁니다.** 못생겼다고 지우면 키보드 사용자가 길을 잃습니다. **지우지 말고 색만 바꿉니다.**
- **대체 텍스트에 "이미지"라고 씁니다.** 없는 것과 같습니다.
- **카드뉴스에 글자를 그림으로 넣고 설명을 안 답니다.** 그 글자는 아무도 못 읽습니다. **글자를 그대로 옮겨 적습니다.**
- **자동으로 넘어가는 배너를 둡니다.** 스스로 움직이는 것은 멈출 수단이 있어야 합니다. 6절에서 뺀 이유가 여기에도 있습니다.
- **자동 검사 도구 결과만 믿습니다.** 도구는 대비나 대체 텍스트 유무는 잘 잡지만, **순서가 이상한 것·설명이 엉뚱한 것은 못 잡습니다.** 탭 키로 직접 눌러 봐야 합니다.

## ⚡ 이렇게 하세요

1. 규칙표(3절)에 **대비 최소값 줄**을 넣습니다. 이미 넣었으면 넘어갑니다.
2. 내 화면에서 **가장 연한 글자**를 하나 골라 색 값과 배경 값을 확인하고 **대비를 잽니다.** 숫자를 적어 둡니다.
3. **마우스에서 손을 떼고 탭 키로** 화면을 끝까지 지나가 봅니다. 걸리는 곳을 적습니다.
4. 이미지마다 대체 텍스트를 답니다. 장식은 비워 둡니다.
5. AI에게 아래를 붙여넣습니다.

```
이 화면을 접근성 세 항목으로 점검해줘. 항목마다 "통과 / 실패 + 위치 + 고칠 값"으로 표를 만들어줘.

1. 대비 — 글자색과 배경색 조합을 전부 찾아서 대비 값을 계산해줘.
   본문은 4.5:1, 큰 글자는 3:1이 최소야. 못 미치는 것만 표에 넣고, 규칙표 안의 색으로 대안을 제안해줘.
2. 키보드 — 탭으로 닿을 수 없는 요소, 포커스 표시가 없는 요소, 탭 순서가 화면 순서와 다른 곳을 찾아줘.
   포커스 표시를 없앤 코드가 있으면 지적해줘.
3. 대체 텍스트 — 대체 텍스트가 없는 이미지, "이미지"처럼 의미 없는 것,
   글자가 들어 있는데 그 글자를 안 옮긴 것을 찾아줘.

계산이 아니라 추측인 항목은 "추측"이라고 표시해줘.
```

6. AI가 못 잡는 것 하나가 있습니다 — **탭 순서가 자연스러운가.** 이건 직접 눌러 봐야 압니다.

## ✅ 됐는지 확인

- [ ] 본문 대비를 **재 봤나** (눈짐작 말고 숫자를 봤나)
- [ ] 가장 연한 글자의 대비 값이 **4.5 이상인가**
- [ ] **마우스 없이 탭 키만으로** 모든 버튼에 닿았나
- [ ] 탭으로 이동할 때 **지금 위치가 테두리로 보이나**
- [ ] 이미지마다 대체 텍스트가 있고, **장식 이미지는 비어 있나**
- [ ] 글자가 들어간 이미지의 **글자를 그대로 옮겨 적었나**

하나라도 «아니오»면 이 절을 다시 봅니다. 셋 다 오늘 안에 끝낼 수 있는 분량입니다.
