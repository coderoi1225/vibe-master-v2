앞의 여섯 절은 읽으면 다 맞는 말입니다.
그런데 읽는 것과 손에 붙는 것은 다릅니다. **이 절이 그 여섯을 실제 일정에 얹습니다.**

여기서 대부분이 마지막으로 망합니다. **기능을 다섯 개 만들려고 해서.**

기능 다섯 개를 어중간하게 만든 사람과, 기능 하나를 **계획부터 검증·커밋까지** 끝까지 밀어 본 사람 중
Stage 6으로 갈 수 있는 사람은 후자입니다.
왜냐하면 Stage 6에서 필요한 것은 기능의 개수가 아니라 **한 바퀴를 돌아 본 경험**이기 때문입니다.

그래서 이 절의 목표는 하나입니다. **가장 작은 기능 하나를, 끝까지.**

## ① 무엇을 만드나 — 가장 작은 것 하나

예시는 뉴스레터 서비스의 **구독 가입 화면**입니다.
방문자가 이메일을 넣고 버튼을 누르면 구독자로 저장되는 것. 그게 전부입니다.

> **내 사업이면 이렇게** — 손님이 나에게 처음 무언가를 남기는 화면 하나를 고르세요.
> 문의 남기기, 신청서 넣기, 예약 요청하기. **손님이 들어오는 첫 문 하나면 됩니다.**

## ② 7일 표

| 날 | 무엇을 하나 | 어느 절 | 그날 끝에 손에 남는 것 |
|---|---|---|---|
| **1일** | 앱에서 한 바퀴 — `@`로 파일 붙이기, `!`로 명령 결과 붙이기, `Esc`로 멈추기. 계획 모드로 내 프로젝트 둘러보기만. **아무것도 고치지 않는다** | 절 2 | 프로젝트 구조를 설명한 요약 |
| **2일** | 만들 기능 하나를 정하고 **계획을 세우게 한다.** 계획을 읽고 **최소 한 곳을 고친다.** 인터뷰 다섯 문항을 받아 답한다 | 절 1 | `docs/`에 저장된 계획 파일 |
| **3일** | **핵심 흐름 3개**를 고르고 **실패하는 테스트를 먼저** 만든다. 빨간불을 눈으로 확인한다 | 절 4 | 빨간불 3개 · 테스트 돌리는 명령 한 줄 |
| **4일** | **구현.** 계획대로만. 테스트를 하나씩 초록으로. **자동 수락은 내 컴퓨터 안 파일 고치기에만** 켠다 | 절 2·3 | 초록불 3개 |
| **5일** | ⭐ **일부러 막혀 본다.** 에러를 그대로 붙여 보고, 로그를 붙여 보고, 세 번 반복되면 새 대화로 옮겨 본다. 되돌리기 한 번 연습 | 절 5 | "막혔을 때 나만의 순서" 메모 한 장 |
| **6일** | **검증.** 2겹 확인 목록 5개를 만들어 직접 눈으로 통과시킨다. **새 대화에서 트집 리뷰.** 시크릿 점검. 저장소 안전장치 셋 켜기 | 절 6 | ○×로 채워진 확인 목록 · 안전장치 셋 |
| **7일** | **커밋과 다음 장 준비.** 문서 갱신 → 세 번 반복된 지시를 스킬로 → 커밋 → Stage 6에서 바꿀 자리를 표시해 둔다 | 절 3 | 커밋 하나 · Stage 6 준비 메모 |

**하루 1~2시간입니다.** 더 하려고 하지 마세요. 5일차가 가장 중요하니 그날은 남겨 두세요.

## ③ 5일차를 왜 일부러 넣었나

막히는 것은 사고가 아니라 **반드시 오는 일**입니다.
처음 막히는 날이 하필 손님이 보고 있는 날이면 최악입니다.

그래서 **안전한 날에 미리 막혀 봅니다.** 소방 훈련과 같습니다.
일부러 잘못된 지시를 시키고, 에러를 받고, 그대로 붙이고, 세 번 실패하면 대화를 바꿔 보고,
마지막으로 **되돌려서 멀쩡한 상태로 돌아옵니다.**

되돌리기를 한 번 성공해 보면 그 다음부터 **과감해집니다.** 그게 이 훈련의 진짜 목적입니다.

## ④ 7일차 — 커밋과 다음 장 준비

마지막 날은 새로 만들지 않습니다. **닫는 날**입니다.

1. **문서 갱신** — 이번에 정한 것, 겪은 것을 지침 파일과 문서에 반영합니다
2. **패턴 추출** — 이번 주에 **세 번 이상** 반복한 지시가 있으면 그것만 스킬로 만듭니다
3. **커밋** — 코드·테스트·문서를 함께. 커밋 메시지는 한국어로, 무엇을 왜 바꿨는지
4. ⭐ **Stage 6에서 바꿀 자리 표시** — 지금 구독자는 어디에 저장되고 있나요? 아마 파일이나 임시 저장소일 겁니다. **그 줄에 표시를 남깁니다.**

## 📘 말 풀이

- **한 바퀴** — 계획 → 테스트 → 구현 → 막힘 → 검증 → 커밋까지 한 번 돌아 보는 것. Stage 5의 목표는 기능의 개수가 아니라 **한 바퀴**입니다.
- **커밋** — 지금 상태를 저장소에 저장 지점으로 찍어 두는 것. 되돌아갈 수 있는 자리를 만드는 일입니다 (Stage 4.5).

## ⚠️ 함정

- **기능을 여러 개 만들려고 한다** — 하나입니다. 하나를 끝까지 미는 게 다섯 개를 절반씩 하는 것보다 훨씬 큽니다.
- **1일차에 벌써 만들기 시작한다** — 1일차는 **아무것도 고치지 않는 날**입니다. 손이 근질거려도 참으세요.
- **3일차를 건너뛰고 4일차로 간다** — 가장 흔한 이탈 지점입니다. 테스트 없이 구현하면 5·6일차에 할 게 없어집니다.
- **5일차를 건너뛴다** — "잘 되고 있는데 굳이 왜"라고 생각합니다. 그러면 진짜로 막히는 날 순서를 모릅니다.
- **마지막 날에 커밋을 미룬다** — 커밋 안 하면 이번 주는 없었던 일이 됩니다. Stage 6에서 이어받을 것도 없습니다.
- **하루를 세 시간씩 몰아 한다** — 이틀 하고 그만둡니다. 하루 1~2시간, 이레.

## ⚡ 따라 하기

**① 1일차 — 오늘은 아무것도 고치지 않습니다**

```
계획 모드로 시작해 줘. 오늘은 아무것도 고치지 마.

1. 이 프로젝트가 무엇을 하는지 한 줄
2. 폴더별로 무슨 일을 하는지 한 줄씩
3. 지금 이미 돌아가는 것과, 아직 안 되는 것
4. 내가 가장 작게 만들 수 있는 기능 후보 3개 — 각각 왜 작은지 한 줄씩

나는 코드를 못 읽어. 전부 한국어 짧은 문장으로.
```

**② 2일차 — 기능 하나를 정하고 계획을 받습니다**

```
후보 중에 (고른 것)을 만들 거야.

바로 만들지 말고 계획만 글로 써 줘.
1. 다 되면 사용자가 화면에서 무엇을 할 수 있나 (한 줄)
2. 새로 만들 파일 / 고칠 파일 목록
3. 네가 혼자 정한 것 전부
4. 되돌리기 어려운 일이 있나
5. 내가 눈으로 확인할 방법

고칠 파일이 3개를 넘으면 더 작게 쪼개서 다시 제안해 줘.
계획이 정해지면 docs/ 아래 파일로 저장해 줘.
```

**③ 5일차 — 일부러 막혀 보기 (안전하게)**

```
오늘은 막히는 연습을 할 거야. 진짜로 망가뜨려도 돼 — 되돌릴 거니까.

1. 먼저 지금 상태를 커밋해 줘. 되돌아올 지점이 필요해.
2. 그 다음, 이 기능에서 흔히 나는 에러 하나를 일부러 만들어 줘.
   무엇을 망가뜨렸는지는 나에게 말하지 마.
3. 나는 에러를 보고 원인을 찾아 볼게. 내가 물어보기 전엔 답을 알려 주지 마.
4. 다 끝나면 아까 커밋한 지점으로 되돌리는 방법을 알려 줘.
```

**④ 7일차 — 닫고, 다음 장을 준비합니다**

```
이번 주 작업을 마무리하고 다음 단계를 준비할게.

1. 이번 주에 정한 것 중 문서나 지침 파일에 반영할 것을 찾아 고쳐 줘
2. 이번 주에 내가 세 번 이상 반복한 지시가 있나? 있으면 그것만 스킬로 만들자고 제안해 줘
3. 커밋 메시지를 한국어 한 줄로 써 줘 — 무엇을 왜 바꿨는지
4. 지금 데이터(예: 구독자 목록)가 어디에 어떻게 저장되고 있는지 알려 주고,
   나중에 진짜 데이터베이스로 바꿀 때 고쳐야 할 자리를 목록으로 정리해 줘.
   그 목록을 docs/다음단계.md 로 저장해 줘.
```
