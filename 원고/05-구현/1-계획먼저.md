여기서 처음으로 **돌아가는 것**이 나옵니다.
그리고 대부분의 사람이 바로 여기서 처음 크게 망칩니다. 이유는 하나입니다 —
**"만들어 줘"라고 바로 시켜서.**

## 왜 이걸 하나

AI에게 "만들어 줘"라고 하면 진짜로 만듭니다. 5분 만에 파일 열두 개가 바뀌어 있습니다.
문제는 그 열두 개 중에 **내가 시키지 않은 것이 섞여 있다는 것**입니다.

AI는 모르는 것이 있어도 손을 들지 않습니다. **그냥 정합니다.**
"구독자 목록은 어디에 저장하지?" → 혼자 정합니다.
"메일은 몇 시에 보내지?" → 혼자 정합니다.
"이미 있는 파일을 지워도 되나?" → 혼자 정합니다.

이 절을 건너뛰면 그 '혼자 정한 것'을 **코드가 다 만들어진 뒤에** 알게 됩니다.
그때는 되돌리는 것 말고 방법이 없습니다.

계획을 먼저 읽게 하는 이 한 단계가 **결과를 가장 크게 바꿉니다.**
이 절 하나만 지켜도 Stage 5의 절반은 성공입니다.

## 네 걸음 — 살펴보기 → 계획 → 만들기 → 확인

부엌을 고친다고 생각해 보세요.
좋은 목수는 오자마자 벽을 뜯지 않습니다. **먼저 둘러보고, 그림을 그려 보여주고, 내가 좋다고 하면 그때 뜯습니다.**

| 걸음 | 무엇을 시키나 | AI가 하는 일 | 내가 하는 일 |
|---|---|---|---|
| ① **살펴보기** | "고치지 말고, 지금 어떻게 되어 있는지만 알려 줘" | 폴더와 파일을 읽고 요약 | 읽는다 |
| ② **계획** | "무엇을 만들고 무엇을 고칠지 계획만 써 줘" | 계획을 **글로** 내놓음 | ⭐ **읽고 고친다** |
| ③ **만들기** | "이 계획대로 해 줘" | 계획대로만 코드 작성 | 지켜본다 |
| ④ **확인** | "됐는지 내가 눈으로 볼 방법을 알려 줘" | 확인 방법 안내 | ⭐ **직접 눈으로 본다** |

**②와 ④가 사람의 자리입니다.** ①③은 AI가 훨씬 잘합니다.
1인 사업에서 사람의 병목은 만드는 쪽이 아니라 **보는 쪽**입니다.

## 계획을 읽는 게 왜 그렇게 큰가

우리는 코드를 못 읽습니다. 그건 사실입니다.
**그런데 계획은 읽을 수 있습니다.** 한국어로 쓰인 글이니까요.

계획 문서는 AI가 **혼자 정한 것이 글로 드러나는 유일한 자리**입니다.
코드가 되고 나면 안 보입니다. 계획일 때는 보입니다.
그래서 계획 단계가 비개발자에게는 **유일하게 남은 운전대**입니다.

## 계획을 읽을 때 볼 곳 넷

코드를 몰라도 이 넷은 볼 수 있습니다.

**① 손대는 파일이 몇 개인가**
셋을 넘으면 일단 멈춥니다. "더 작게 쪼개 줘"라고 말합니다.
파일 열 개짜리 계획은 성공해도 검증을 못 합니다.

**② 내가 말한 적 없는 것을 혼자 정하지 않았나**
계획 안에 처음 보는 이름·규칙·화면이 있으면 그건 AI가 지어낸 것입니다.
"이건 제가 말한 적 없는데요, 왜 이렇게 정했나요?"라고 물으면 됩니다.

**③ 되돌릴 수 있나**
데이터를 지우거나, 메일을 실제로 보내거나, 밖으로 나가는 일이 계획에 있으면
그 부분만 **따로 떼어서 나중에** 합니다.

**④ 다 됐다는 걸 무엇으로 확인하나**
계획에 "확인하는 법"이 없으면 그 계획은 미완성입니다. 확인 방법을 계획에 넣어 달라고 하세요.

## 계획 모드는 언제 켜나

| 상황 | 계획 먼저? |
|---|---|
| 처음 만드는 기능 | ⭕ 반드시 |
| 파일 세 개 이상이 바뀔 것 같을 때 | ⭕ 반드시 |
| 남이 만든 코드를 건드릴 때 | ⭕ 반드시 |
| 돈·개인정보가 걸린 곳 | ⭕ 반드시 |
| 글자 하나 고치기, 색 바꾸기 | ❌ 그냥 시켜도 됨 |
| 무엇이 어디 있는지 물어보기만 | ❌ 계획 모드로 물어보면 편함 |

**계획 모드에서는 AI가 파일을 못 고칩니다.** 읽기만 합니다.
그래서 겁 없이 이것저것 물어봐도 됩니다. 망칠 수가 없으니까요.
처음 며칠은 계획 모드로만 놀아 보는 것을 권합니다.

## 계획이 부실하면 — 인터뷰를 시킨다

계획이 두루뭉술하게 나왔다면 AI가 정보가 부족한 것입니다.
이럴 때 만병통치약에 가까운 한 줄이 있습니다.

> **"계획 세우기 전에, 나한테 질문 다섯 개 먼저 해 줘."**

이 한 줄이 빠뜨리는 것의 대부분을 막습니다. 큰 작업일수록 효과가 큽니다.

## 📘 말 풀이

- **계획 모드** — AI가 **읽기만 하고 고치지는 못하는** 상태. 둘러보기와 계획 세우기 전용입니다. 망칠 수 없으니 마음 편히 씁니다.
- **세션** — AI와의 대화 한 판. 한 세션에 여러 작업을 섞으면 AI가 전부 어중간해집니다. **한 작업 = 한 세션.**
- **컨텍스트** — AI가 지금 머리에 담고 있는 내용. 작업대 위 그릇이라고 생각하세요. 그릇이 차면 새 재료를 못 올려서 답이 갑자기 멍청해집니다. 그때는 대화를 정리하거나 새로 엽니다.

## ⚠️ 자주 걸리는 함정

- **"계획 세워 줘" 하고 안 읽는다** — 가장 흔합니다. 계획을 안 읽으면 계획을 안 세운 것과 같습니다. 스크롤만 내리지 말고 위 네 곳을 보세요.
- **한 세션에 여러 일을 던진다** — "기획서도 봐 주고, 발송 기능도 만들고, 디자인도 손봐 줘." 그릇이 넘쳐서 전부 어중간해집니다.
- **계획이 마음에 안 드는데 그냥 진행시킨다** — 계획 단계에서 고치는 값은 1, 코드가 된 뒤에 고치는 값은 10입니다.
- **AI가 "완료했습니다"라고 하면 믿는다** — 그건 증거가 아니라 **주장**입니다. 확인은 절 4·6에서 다룹니다.
- **엉뚱한 폴더에서 시작한다** — 프로젝트 폴더가 아닌 곳에서 시키면 AI가 남의 파일을 고칩니다. **한 작업 = 한 폴더 = 한 세션.**

## ⚡ 이렇게 하세요

**① 살펴보기 — 아직 아무것도 고치지 않게**

```
계획 모드로 시작해 줘. 아무것도 고치지 마.

이 프로젝트를 처음 보는 사람이라고 생각하고 다음을 알려 줘.
1. 이 프로젝트가 무엇을 하는 것인지 한 줄로
2. 폴더가 어떻게 나뉘어 있는지, 각 폴더가 무슨 일을 하는지
3. 내가 만들려는 기능과 관련 있어 보이는 파일 목록
4. 지금 상태에서 이미 돌아가는 것과, 아직 안 되는 것

나는 코드를 못 읽으니 전부 한국어로, 짧은 문장으로.
```

**② 계획 — 코드는 아직 쓰지 않게**

```
만들 기능: (여기에 한 줄로 씁니다. 예 — 방문자가 이메일을 넣으면 구독자로 저장되는 가입 화면)

바로 만들지 말고, 계획만 글로 써 줘. 형식은 이렇게.

1. 이 기능이 다 되면 사용자가 화면에서 무엇을 할 수 있나 (한 줄)
2. 새로 만들 파일 목록
3. 고칠 파일 목록 — 각각 무엇을 왜 고치는지 한 줄씩
4. 내가 알려주지 않아서 네가 혼자 정한 것 — 전부 솔직하게 나열
5. 되돌리기 어려운 일이 들어 있나 (데이터 삭제, 실제 메일 발송, 외부로 나가는 것)
6. 다 됐는지 내가 눈으로 확인할 방법

조건:
- 고치는 파일이 3개를 넘으면, 3개 이하가 되도록 더 작게 쪼개서 다시 제안해 줘.
- 코드는 한 줄도 쓰지 마. 계획만.
```

**③ 계획이 부실할 때 — 인터뷰 시키기**

```
계획을 세우기 전에, 나한테 질문 5개를 먼저 해 줘.
네가 지금 몰라서 혼자 정하게 될 것들만 물어봐.
내가 답하면 그 답을 반영해서 계획을 다시 써 줘.
```

**④ 계획을 고쳐서 실행시키기**

```
계획 중에서 이 부분을 고쳐 줘.
- (고칠 것 1)
- (고칠 것 2)

고친 계획을 다시 보여 주고, 내가 "진행"이라고 하면 그때부터 만들어 줘.
계획에 없는 파일은 절대 건드리지 마. 계획에 없는 걸 하고 싶으면 먼저 물어봐.
```

## ✅ 됐는지 확인

- [ ] **계획을 먼저 읽고** 나서 실행시켰나 (바로 "만들어 줘"라고 하지 않았나)
- [ ] 계획에 **새로 만들 파일**과 **고칠 파일** 목록이 눈에 보이나
- [ ] 계획에 **"AI가 혼자 정한 것"** 항목이 있고, 내가 그걸 읽었나
- [ ] 고칠 파일이 **셋 이하**인가 (넘었다면 쪼개 달라고 했나)
- [ ] 계획 중 **최소 한 곳**을 내가 고쳐서 다시 받았나
- [ ] 계획에 **"내가 눈으로 확인하는 방법"**이 적혀 있나
