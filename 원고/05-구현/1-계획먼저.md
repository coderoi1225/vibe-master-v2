여기서 처음으로 돌아가는 것이 나옵니다. 그리고 대부분이 여기서 처음 크게 망합니다 — **"만들어 줘"라고 바로 시켜서.**

## ① 네 걸음을 표로 본다

AI에게 "만들어 줘"라고 하면 5분 만에 파일 열두 개가 바뀝니다. 그중에 내가 시키지 않은 것이 섞여 있습니다 — AI는 모르는 것이 있어도 묻지 않고 혼자 정하기 때문입니다.

| 걸음 | 무엇을 시키나 | 내가 하는 일 |
|---|---|---|
| 살펴보기 | "고치지 말고, 지금 어떻게 되어 있는지만 알려 줘" | 읽는다 |
| 계획 | "무엇을 만들고 고칠지 계획만 써 줘" | ⭐ 읽고 고친다 |
| 만들기 | "이 계획대로 해 줘" | 지켜본다 |
| 확인 | "됐는지 내가 눈으로 볼 방법을 알려 줘" | ⭐ 직접 눈으로 본다 |

**계획과 확인이 사람의 자리입니다.** 코드는 못 읽어도 한국어로 쓰인 계획은 읽을 수 있고, AI가 혼자 정한 것이 글로 드러나는 자리는 계획뿐입니다.

## ② 계획에서 볼 곳 넷을 익힌다

계획을 받으면 스크롤만 내리지 말고 이 넷을 찾으세요. 코드를 몰라도 전부 볼 수 있습니다.

1. **손대는 파일 수** — 셋을 넘으면 "더 작게 쪼개 줘"라고 말합니다. 파일 열 개짜리 계획은 성공해도 검증을 못 합니다.
2. 내가 말한 적 없는 것 — 처음 보는 이름·규칙·화면은 AI가 지어낸 것입니다. "왜 이렇게 정했나요?"라고 묻습니다.
3. 되돌릴 수 있나 — 데이터 삭제, 실제 메일 발송, 밖으로 나가는 일은 따로 떼어 나중에 합니다.
4. 무엇으로 확인하나 — 확인 방법이 없는 계획은 미완성입니다. 넣어 달라고 하세요.

## ③ 계획 모드를 켤 때를 가린다

계획 모드에서는 AI가 파일을 읽기만 하고 고치지 못합니다. 그래서 겁 없이 물어봐도 망칠 수가 없습니다.

| 상황 | 계획 먼저? |
|---|---|
| 처음 만드는 기능 · 파일 셋 이상이 바뀔 때 | ⭕ 반드시 |
| 남이 만든 코드 · 돈·개인정보가 걸린 곳 | ⭕ 반드시 |
| 글자 하나 고치기, 색 바꾸기 | ❌ 그냥 시켜도 됨 |

처음 며칠은 **계획 모드로만** 놀아 보세요.

## ④ 부실한 계획엔 인터뷰를 시킨다

계획이 두루뭉술하면 AI에게 정보가 부족한 것입니다. 계획을 다시 시키지 말고 **질문을 먼저 받으세요.**

> "계획 세우기 전에, 나한테 질문 다섯 개 먼저 해 줘."

이 한 줄이 빠뜨리는 것의 대부분을 막습니다.

## ⚡ 따라 하기

1. 프로젝트 폴더에서 AI를 열고 계획 모드로 시작하세요 — 첫 대화에서는 아무것도 고치지 않기 위해서입니다. 폴더 구조와 관련 파일 목록이 한국어로 돌아와야 합니다.

```
계획 모드로 시작해 줘. 아무것도 고치지 마.

이 프로젝트를 처음 보는 사람이라고 생각하고 알려 줘.
1. 이 프로젝트가 무엇을 하는 것인지 한 줄로
2. 폴더가 어떻게 나뉘어 있고, 각 폴더가 무슨 일을 하는지
3. 내가 만들려는 기능과 관련 있어 보이는 파일 목록
4. 이미 돌아가는 것과, 아직 안 되는 것

나는 코드를 못 읽으니 전부 한국어로, 짧은 문장으로.
```

2. 만들 기능을 한 줄로 정해서 계획만 받으세요 — 혼자 정한 것을 코드가 되기 전에 보기 위해서입니다. 답에 「혼자 정한 것」 항목과 파일 목록이 보여야 합니다.

```
만들 기능: (한 줄로. 예 — 방문자가 이메일을 넣으면 구독자로 저장되는 가입 화면)

바로 만들지 말고, 계획만 글로 써 줘.
1. 다 되면 사용자가 화면에서 무엇을 할 수 있나 (한 줄)
2. 새로 만들 파일 목록
3. 고칠 파일 목록 — 각각 무엇을 왜 고치는지 한 줄씩
4. 내가 알려주지 않아서 네가 혼자 정한 것 — 전부 솔직하게
5. 되돌리기 어려운 일이 있나 (데이터 삭제, 실제 발송, 외부로 나가는 것)
6. 다 됐는지 내가 눈으로 확인할 방법

고치는 파일이 3개를 넘으면 더 작게 쪼개서 다시 제안해 줘.
코드는 한 줄도 쓰지 마.
```

3. 계획이 두루뭉술하면 인터뷰를 시키세요 — 부족한 정보를 채워야 계획이 구체해집니다. 질문 다섯 개가 오면 답하고, 답을 반영한 계획이 다시 옵니다.

```
계획을 세우기 전에, 나한테 질문 5개를 먼저 해 줘.
네가 지금 몰라서 혼자 정하게 될 것들만 물어봐.
내가 답하면 그 답을 반영해서 계획을 다시 써 줘.
```

4. ②의 네 곳을 보고 최소 한 곳을 고쳐서 돌려보내세요 — 계획에서 고치는 값은 1, 코드가 된 뒤는 10입니다. 고친 계획이 다시 오고, 내가 "진행"이라고 말한 뒤에야 파일이 바뀝니다.

```
계획 중에서 이 부분을 고쳐 줘.
- (고칠 것 1)
- (고칠 것 2)

고친 계획을 다시 보여 주고, 내가 "진행"이라고 하면 그때부터 만들어 줘.
계획에 없는 파일은 건드리지 마. 계획에 없는 걸 하고 싶으면 먼저 물어봐.
```

## ✅ 확인

- [ ] 계획에 「새로 만들 파일」「고칠 파일」「혼자 정한 것」 항목이 보이나
- [ ] 고칠 파일이 셋 이하인가
- [ ] 계획 중 한 곳 이상을 내가 고쳐서 다시 받았나
- [ ] 계획에 「내가 눈으로 확인하는 방법」이 적혀 있나

## 📘 말 풀이

**계획 모드(plan mode)** — AI가 읽기만 하고 고치지 못하는 상태. 둘러보기와 계획 세우기 전용이라 망칠 수 없습니다.

**세션(session)** — AI와의 대화 한 판. 한 세션에 여러 작업을 섞으면 전부 어중간해집니다. 한 작업 = 한 세션.

**컨텍스트(context)** — AI가 지금 머리에 담고 있는 내용. 작업대 위 그릇이라 차면 답이 갑자기 멍청해지고, 그때는 대화를 새로 엽니다.

## ⚠️ 함정

**"계획 세워 줘" 하고 읽지 않습니다.** 가장 흔합니다. 계획을 안 읽으면 계획을 안 세운 것과 같습니다.

**한 세션에 여러 일을 던집니다.** 그릇이 넘쳐서 전부 어중간해집니다. 한 작업 = 한 폴더 = 한 세션.

**AI가 "완료했습니다"라고 하면 믿습니다.** 그건 증거가 아니라 주장입니다. 확인은 [[05-구현/4-테스트|4절]]과 [[05-구현/6-검증|6절]]에서 다룹니다.
