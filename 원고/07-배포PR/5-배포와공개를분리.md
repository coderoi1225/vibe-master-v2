배포가 무서운 이유는 하나입니다. **올리는 순간 사용자가 본다**고 믿기 때문입니다.

그래서 이런 일이 벌어집니다.
만들다 만 기능이 완성될 때까지 가지에 몇 주씩 쌓입니다.
그 사이 본줄기는 계속 바뀝니다. 나중에 합치려니 충돌이 백 군데입니다.
결국 통째로 버리거나, 겁먹은 채로 한 번에 밀어 넣습니다.

**둘을 떼어 놓으면 이게 통째로 사라집니다.**
코드는 매일 올리되, 사용자에게 보이는 시점은 내가 따로 정합니다.

이건 새 발상이 아닙니다. **2009년에 한 사진 서비스가 찾은 답**이고, 지금도 유효합니다.
그때 나온 말이 이겁니다 — *"미완성 기능을 켜지 않은 채로 매일 올린다."*

## ① 발상 하나 — 스위치

코드에 **전등 스위치**를 하나 답니다.

```
if (새기능이_켜져있나) {
    새 화면을 보여 준다
} else {
    원래 화면을 보여 준다
}
```

그리고 그 스위치의 **켜짐/꺼짐은 코드 밖에** 둡니다(1절의 그 서랍입니다).

이렇게 되면 무엇이 달라지나요.

| | 스위치가 없을 때 | 스위치가 있을 때 |
|---|---|---|
| 만들다 만 기능 | 가지에 쌓아 둔다 | **꺼 둔 채로 올린다** |
| 합칠 때 | 몇 주치가 한꺼번에 | 매일 조금씩 |
| 사고가 나면 | 코드를 되돌리고 다시 굽는다 | **스위치를 끈다 — 몇 초** |
| 나만 먼저 보기 | 불가능 | 내 계정에만 켜 둔다 |

마지막 두 줄이 핵심입니다.
**되돌리는 데 몇 초**고, **나에게만 보이게** 할 수 있습니다.

## ② 이걸로 할 수 있게 되는 것 넷

**① 만들다 만 기능을 올려 둡니다.**
반쯤 만든 채로 본줄기에 합쳐도 됩니다. 꺼져 있으니 아무도 못 봅니다.
그러면 PR이 작아지고, PR이 작아지면 리뷰가 되고, 되돌리기도 쉬워집니다.

**② 실서비스에서 나만 먼저 봅니다.**
미리보기 주소는 연습 데이터로 돕니다. 실서비스는 진짜 데이터로 돕니다.
진짜 데이터에서만 나는 문제가 있습니다. 스위치를 **내 계정에만** 켜 두면 그걸 잡습니다.

**③ 조금씩 엽니다.**
전체 사용자에게 한 번에 열지 않고, 먼저 10명에게 열고 봅니다.
문제가 있으면 10명만 겪습니다.

**④ 사고가 나면 코드를 안 건드리고 끕니다.**
새벽 3시에 결제가 이상하다는 연락이 옵니다. 다시 굽고 배포하려면 몇 분이 걸립니다.
스위치는 **몇 초**입니다.

> 이게 7절의 **되돌리기**와 짝입니다.
> 되돌리기가 "밖에 나간 것을 물린다"면, 스위치는 **"애초에 안 보이게 해 둔다"**입니다.

## ③ 얼마나 복잡한가 — 설정 한 줄이면 됩니다

전용 서비스를 사야 하는 게 아닙니다.
**환경변수 한 줄이면 이 발상 전체를 가집니다.**

```
NEXT_PUBLIC_FEATURE_새기능=off
```

배포 서비스 설정 화면에서 이 값을 `off`에서 `on`으로 바꾸고 저장하면 켜집니다.
그게 전부입니다. 나중에 사용자별로 켜고 끄고 싶어지면 그때 전용 도구를 봐도 늦지 않습니다.

## 📘 말 풀이

**기능 스위치(feature flag / feature toggle)**
코드 안의 기능 하나를 **밖에서 켜고 끌 수 있게 만든 장치.**
코드를 다시 굽지 않고도 보였다 안 보였다 하게 만듭니다. 전등 스위치와 같습니다.

**점진 공개(gradual rollout)**
새 기능을 **전체가 아니라 일부에게 먼저** 여는 것.
문제가 있으면 전부가 아니라 일부만 겪습니다.

**죽은 스위치(stale flag)**
다 열어 놓고 **치우는 걸 잊은 스위치.** 코드에 갈림길만 남아서, 시간이 지나면
아무도 어느 쪽이 진짜인지 모르게 됩니다. 스위치를 만들 때 **없앨 날짜를 같이 적어 둡니다.**

## ⚠️ 함정

- **스위치를 만들고 안 치운다** — 가장 흔합니다. 반년 뒤 스위치가 열두 개면 코드가 갈림길 미로가 됩니다. **다 열었으면 스위치와 옛 코드를 지우는 PR을 하나 더 냅니다.**
- **꺼진 기능이 사실은 돌고 있다** — 화면만 감추고 뒤의 처리는 그대로 도는 경우입니다. 진짜 데이터가 바뀌거나 진짜 결제가 갑니다. **화면이 아니라 동작을 감쌉니다.**
- **스위치가 꺼진 쪽을 시험 안 한다** — 켠 쪽만 보고 병합했다가, 끄는 순간 화면이 깨집니다. **끄고도 한 번 열어 봅니다.**
- **`NEXT_PUBLIC_` 을 아무 값에나 붙인다** — 이 접두사가 붙은 값은 **브라우저까지 전달됩니다.** 즉 사용자가 볼 수 있습니다. 스위치는 괜찮지만, **열쇠에는 절대 붙이면 안 됩니다.**
- **스위치를 코드에 박아 둔다** — `const 새기능 = true` 라고 적으면 끌 때 다시 구워야 합니다. 스위치의 의미가 없습니다.
- **스위치가 열 개인 채로 배포한다** — 조합이 폭발합니다. **동시에 켜 두는 미완성 스위치는 두세 개까지.**

## ⚡ 따라 하기

**1) 스위치를 읽는 자리를 한 곳으로 모읍니다.** 여기저기 흩어지면 못 치웁니다.

```ts
// lib/스위치.ts — 스위치는 전부 여기 한 파일에서만 읽는다
export const 스위치 = {
  // 이름: [켜짐 여부, 없앨 날짜]  ← 날짜를 적어야 죽은 스위치가 안 남는다
  새기능:  process.env.NEXT_PUBLIC_FEATURE_새기능 === 'on',   // 없앨 날: 2026-10-31
} as const
```

**2) 화면이 아니라 동작을 감쌉니다.**

```tsx
import { 스위치 } from '@/lib/스위치'

export default function 결제화면() {
  if (!스위치.새기능) {
    return <기존결제 />        // 꺼져 있으면 새 코드는 아예 실행되지 않는다
  }
  return <새결제 />
}
```

**3) 방마다 다르게 켭니다.** 1절에서 나눈 세 방을 여기서 씁니다.

| 방 | 값 |
|---|---|
| 내 컴퓨터(`.env`) | `on` — 만드는 중이니 켜 둔다 |
| 미리보기 | `on` — PR에서 눈으로 확인 |
| 실서비스 | `off` — **완성될 때까지 꺼 둔다** |

**4) 나에게만 먼저 열어 봅니다.** 실서비스에서 진짜 데이터로 확인하는 방법입니다.

```ts
// 내 계정만 켜기 — 사용자 식별자는 코드에 적지 않고 환경변수로 둔다
export function 나만보기(사용자id?: string) {
  if (스위치.새기능) return true                       // 전체 공개 상태
  const 미리보는사람 = (process.env.PREVIEW_USER_IDS ?? '').split(',')
  return !!사용자id && 미리보는사람.includes(사용자id)
}
```

**5) 끄는 연습을 한 번 합니다.** 이게 확인의 전부입니다.

```
배포 서비스 → Settings → Environment Variables
  NEXT_PUBLIC_FEATURE_새기능 을 on → off 로 바꾸고 저장
  → 재배포(Redeploy) 를 누른다
  → 실서비스 주소를 열어 기능이 사라졌는지 본다
  → 시계를 본다. 몇 초 걸렸나
```

**6) 다 열었으면 치우는 PR을 냅니다.** 없앨 날짜가 오면.

```bash
git switch -c 스위치치우기-새기능
# 스위치 갈림길과 옛 코드를 지운다. 환경변수도 지운다.
git commit -am "새기능 스위치 제거 — 전체 공개 완료"
```

- [ ] 그 상태에서 실서비스 주소를 열었을 때 **아무것도 안 보이나**
- [ ] 스위치를 켰을 때 **다시 보이나**
- [ ] 끄는 데 **몇 초**밖에 안 걸렸나 (다시 굽지 않고)
- [ ] 꺼진 쪽으로도 화면이 **안 깨지고** 열리나
- [ ] 스위치마다 **없앨 날짜**가 적혀 있나
