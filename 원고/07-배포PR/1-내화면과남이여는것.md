Stage 6에서 주소 하나가 생겼고 남이 엽니다. 이제 고치기 시작하면 «내 화면에서는 되는데 올리면 깨진다»가 생기는데, 이 절은 그걸 막는 **자리 배치**입니다.

## ① 굽기와 올리기를 가른다

AI가 쓴 코드는 사람이 읽기 좋게 생겼습니다. 줄바꿈이 있고 설명이 붙어 있고 여러 파일로 나뉘어 있어서, 브라우저는 그걸 그대로는 빠르게 못 읽습니다. 그래서 남에게 보내기 전에 번역하고 합치고 압축하는 과정을 한 번 거치는데, 이게 **빌드**입니다.

```
① 굽는다(빌드)  →  ② 남의 컴퓨터에 올린다(배포)
```

반죽을 그대로 주지 않고 굽는 것과 같습니다. 굽는 과정은 내 화면보다 까다로워서, 내 화면에서 대충 넘어가던 것을 빌드는 안 넘어가 줍니다. 빌드가 잡아 준 오류는 사용자가 안 겪는 오류이니 나면 다행인 겁니다.

## ② 방을 셋으로 나눈다

배포를 시작하면 «지금 보고 있는 화면이 어느 것인가»가 헷갈립니다. 처음부터 방을 셋으로 나눠 두세요.

| 방 | 누가 보나 | 무엇에 쓰나 | 데이터 |
|---|---|---|---|
| 내 컴퓨터 | 나만 | 만드는 중. 마음껏 부순다 | 가짜·연습용 |
| 미리보기 | 나와 링크를 준 사람 | 합치기 전에 눈으로 확인 | 연습용(실제와 분리) |
| 실서비스 | 모두 | 돈이 오가는 진짜 | 진짜 |

미리보기는 특별한 장치가 아닙니다. 가지(브랜치)를 하나 만들어 올리면 배포 서비스가 그 가지만의 임시 주소를 하나 더 만들어 주고, 거기서 아무리 깨져도 사용자는 모릅니다.

방을 안 나누면 연습으로 만든 가짜 주문이 진짜 매출에 잡히고, 결제를 시험하다 진짜 카드가 긁힙니다. 방을 나누는 건 조심성이 아니라 **되돌릴 수 있게 만드는 일**입니다.

## ③ 열쇠를 코드 밖에 둔다

여기가 가장 자주, 가장 크게 사고가 나는 자리입니다. 데이터베이스 열쇠·결제 열쇠·AI 열쇠를 코드 파일 안에 적으면 코드와 함께 GitHub에 올라갑니다. 저장소를 비공개로 두더라도 **한 번 올라간 열쇠는 기록에 영원히 남습니다** — 파일에서 지워도 이전 기록에 그대로 있습니다.

그래서 열쇠는 코드 밖의 서랍에 넣습니다.

| 어디 | 어떻게 |
|---|---|
| 내 컴퓨터 | `.env` 파일. `.gitignore`에 적어서 절대 안 올라가게 |
| 미리보기·실서비스 | 배포 서비스의 설정 화면에 손으로 붙여넣기 |

그리고 방마다 열쇠가 달라야 합니다. 연습용 열쇠와 진짜 열쇠가 같으면 방을 나눈 의미가 사라집니다.

## ④ 미리보기 주소를 만들어 본다

가지를 하나 올려서 실서비스와 **다른 주소**가 생기는지 눈으로 봐야 이 절이 끝납니다. 여기서 생긴 미리보기 주소는 다음 절의 PR 화면 안에 «이 변경을 미리 보려면 여기» 링크로 자동으로 붙습니다.

## ⚡ 따라 하기

1. 올리기 전에 내 컴퓨터에서 먼저 구우세요 — 여기서 걸리면 배포에서도 걸립니다. 오류 없이 끝까지 돌면 다음으로 갑니다.

```bash
npm run build
```

2. 커밋하기 전에 열쇠 검색 명령 둘을 돌리세요 — 올라가기 전에 잡아야 되돌릴 일이 없습니다. 아무것도 안 나오면 통과이고, 뭔가 나오면 커밋하지 말고 먼저 뺍니다.

```bash
# 올라갈 파일 목록에 위험한 이름이 있는지 본다
git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"

# 코드 안에 열쇠처럼 생긴 문자열이 있는지 본다
grep -rniE "(api[_-]?key|secret|password)\s*[:=]\s*['\"][^'\"]{12,}" --exclude-dir=node_modules --exclude-dir=.git .
```

3. `.gitignore`를 열어 이 세 줄이 있는지 확인하세요 — `.env`가 올라가는 사고를 파일 한 장으로 막습니다. 마지막 줄은 값이 비어 있는 견본만 올리겠다는 뜻이라, 나중에 «무슨 값을 넣어야 하지?»를 안 겪습니다.

```gitignore
.env
.env.*
!.env.example
```

```bash
# .env.example — 값은 비워 두고 이름만 적는다
DATABASE_URL=
PAYMENT_SECRET_KEY=
```

4. 배포 서비스 설정 화면에서 값 하나를 넣을 때마다 **어느 방에 적용할지 고르는 칸**을 찾으세요 — 연습용 열쇠는 미리보기에만, 진짜 열쇠는 실서비스에만 체크합니다. 저장하면 방마다 다른 값이 들어간 목록이 보입니다.

5. 가지를 하나 만들어 올리세요 — 미리보기 주소가 생기는지 보기 위해서입니다. 몇 분 뒤 배포 서비스 화면에 실서비스와 다른 주소가 하나 더 떠 있으면 성공입니다.

```bash
git switch -c 미리보기-시험
echo "<!-- 시험 -->" >> README.md
git add README.md && git commit -m "미리보기 주소가 생기는지 시험"
git push -u origin 미리보기-시험
```

## ✅ 확인

- [ ] `npm run build`가 끝까지 성공하나
- [ ] `.gitignore`에 `.env`가 있고, 검색 명령을 돌렸을 때 아무것도 안 나오나
- [ ] 실서비스 주소 말고 미리보기 주소가 따로 하나 더 생겼나
- [ ] 열쇠를 코드에서 다 뺐는데도 사이트가 여전히 돌아가나

넷째가 «아니오»면 배포 서비스 설정 화면에 값을 안 넣은 것입니다.

## 📘 말 풀이

**빌드(build)** — 사람이 쓴 코드를 브라우저가 빠르게 읽을 수 있는 형태로 번역·압축해서 굽는 일. 여기서 나는 오류는 사용자가 안 겪습니다.

**배포(deploy)** — 구운 결과물을 꺼지지 않는 남의 컴퓨터에 올려서 주소를 붙이는 일. 빌드는 굽기, 배포는 내놓기입니다.

**환경변수(environment variable)** — 코드 밖에 따로 적어 두는 값. 열쇠·주소·설정 같은 것이고, 같은 코드가 방에 따라 다르게 동작하게 만드는 스위치이기도 합니다.

## ⚠️ 함정

**«내 컴퓨터에서는 되는데요».** 배포본만 죽는 원인은 거의 셋입니다 — 배포 쪽에 열쇠를 안 넣었다(가장 흔함), 파일 이름의 대소문자가 다르다, 프로그램 판이 다르다. 둘째는 맥에서 특히 안 걸립니다. 맥은 `Header.tsx`와 `header.tsx`를 같은 것으로 보는데 서버는 다르게 봅니다.

**열쇠를 코드에 잠깐만 적어 둡니다.** «나중에 빼야지»가 그대로 올라갑니다. 잠깐이 없습니다.

**연습용과 진짜의 데이터베이스가 같습니다.** 방은 나눴는데 뒤가 하나로 이어져 있으면 안 나눈 것입니다.

**미리보기 주소를 남에게 그냥 줍니다.** 미리보기도 인터넷 주소라 아는 사람은 다 봅니다. 보여 주기 싫으면 배포 서비스의 보호 설정을 켭니다.

**AI 도구가 `.env`를 읽게 둡니다.** 저장소에 있는 `.env` 하나가 도구의 보호 설정을 무력화한 실사례가 있습니다. 도구 설정에서 읽지 못하게 막아 둡니다.
