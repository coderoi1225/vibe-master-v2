이 문서가 없으면 끝이 안 납니다. 만들다 보면 «이것도 있으면 좋겠다»가 계속 떠오르고, 하나씩 붙일 때마다 완성은 하루씩 밀립니다.

## ① 기획서와 무엇이 다른지 본다

기획서는 사람이 읽고 사람이 해석합니다. 애매해도 회의로 메꿉니다. 요구사항 문서는 **AI가 읽고 그대로 코드가 되므로**, 애매하면 AI가 알아서 정합니다.

| | 이렇게 쓰면 안 되고 | 이렇게 씁니다 |
|---|---|---|
| 목표 | "사용자가 편하게 뉴스를 본다" | "매일 아침 7시에 고른 분야 기사 5개를 이메일로 받는다" |
| 기능 | "결제 기능" | "매달 자동으로 결제되고, 마이페이지에서 한 번 눌러 해지할 수 있다" |
| 성공 | "많이 쓴다" | "가입한 사람 중 다음 달에도 남아 있는 사람이 절반을 넘는다" |

기준은 하나입니다. 읽고 나서 «그래서 화면에 뭐가 보이는데?»라는 질문이 남으면 아직 덜 쓴 것입니다.

## ② 네 칸을 익힌다

거창한 양식이 필요 없습니다. 네 칸만 채우면 요구사항 문서입니다.

| 칸 | 무엇을 적나 | 분량 |
|---|---|---|
| 무엇을 | 이 서비스가 하는 일 한 문단 | 3~5줄 |
| 누구를 위해 | Stage 1에서 만든 고객 둘을 그대로 옮긴다 | 각 3줄 |
| 성공 기준 | 눈으로 셀 수 있는 숫자 하나 + 보조 둘 | 3줄 |
| 안 만들 것 | 이번엔 안 할 것 다섯 개 이상, 각각 한 줄 이유 | 5~7줄 |

앞의 세 칸은 새로 쓰지 않습니다. **Stage 1의 사업 한 장이 그대로 재료**라서, 문제와 해법은 「무엇을」로, 고객은 「누구를 위해」로, 지표는 「성공 기준」으로 옮깁니다. 여기까지는 AI가 대신 옮겨 줍니다.

## ③ 안 만들 것 다섯을 고른다

만들 것을 적는 건 쉽고 다들 씁니다. 안 만들 것을 적는 사람이 드뭅니다. 「하루 5분 뉴스 요약을 이메일로 보내는 구독 서비스」로 예를 들면 이렇습니다.

만들 것 — 셋만

1. 이메일로 가입하고 관심 분야를 하나 고른다
2. 매일 아침 정해진 시간에 기사 다섯 개를 요약해 이메일로 보낸다
3. 매달 자동 결제되고, 마이페이지에서 해지할 수 있다

안 만들 것 — 다섯 이상

| 안 만드는 것 | 왜 |
|---|---|
| 휴대폰 앱 | 웹으로 먼저 확인한다. 앱은 만드는 일이 통째로 하나 더 늘어난다 |
| 메신저로 보내기 | 이메일 하나가 되는지부터 본다 |
| 댓글·게시판 | 사람이 늘기 전에는 빈 화면만 늘어난다 |
| 어두운 화면 모드 | 화면 손볼 곳이 두 배가 된다 |
| 취향 추천 | 쌓인 기록이 없으면 추천할 것도 없다 |
| 다른 나라 말 | 한국어로 팔릴지부터 본다 |

«영원히 안 만든다»가 아니라 «이번에는 안 만든다»입니다. 나중에 만들 것은 지우지 말고 이 칸에 남겨 두면 그 목록이 다음에 할 일의 후보가 됩니다. 만들 것을 다섯, 여섯으로 늘리면 각각이 반쯤 된 채로 멈추는데, **반쯤 된 기능 여섯 개는 팔 수 없습니다.**

## ④ 고칠 때의 규칙을 정한다

끝나는 문서가 아닙니다. 만들면서 계속 고칩니다.

- 새 기능을 넣고 싶어질 때 → 먼저 「안 만들 것」을 봅니다. 거기 적혀 있으면 이번엔 안 합니다.
- 정말 넣어야겠다면 → 「안 만들 것」에서 지우고 「무엇을」로 옮깁니다. **그리고 대신 뺄 것을 하나 고릅니다.**
- 안 만들기로 새로 정한 게 생기면 → 그 자리에서 「안 만들 것」에 한 줄 추가합니다.

## ⚡ 따라 하기

1. `docs/PRD.md` 파일을 만드세요. 빈 파일이어도 됩니다 — AI가 채울 자리를 먼저 잡는 것입니다. `docs` 폴더 안에 파일 이름이 보이면 됩니다.
2. Stage 1의 사업 한 장을 첨부하고 아래를 붙여넣으세요. 앞의 세 칸을 AI가 옮겨 쓰게 하는 것입니다. 네 칸 제목이 있고 「안 만들 것」만 비어 있는 문서가 돌아와야 합니다.

```
첨부한 사업 한 장과 고객 정리를 읽고 PRD.md 초안을 써라.
코드는 짜지 마라. 마크다운으로 파일 하나만 만들어라.

구조는 네 칸으로 고정한다.
1. 무엇을 — 이 서비스가 하는 일 한 문단
2. 누구를 위해 — 고객 둘, 각각 하루 일과와 지금 겪는 불편 3줄
3. 성공 기준 — 셀 수 있는 숫자 하나 + 보조 지표 둘
4. 안 만들 것 — 비워 둬라. 이건 내가 직접 채운다.

3의 숫자는 "화면이나 표에서 실제로 셀 수 있는 것"만 써라.
셀 수 없는 말(만족도, 편리함)은 쓰지 마라.
```

3. 「안 만들 것」은 **손으로 채우세요.** 다섯 개가 안 떠오르면 아래를 붙여넣어 후보를 받으세요. 기능 15개에 예/아니오가 붙은 목록이 돌아옵니다.

```
첨부한 PRD.md를 읽어라.

이 서비스를 만들 때 "있으면 좋겠다"고 사람들이 흔히 붙이는 기능을 15개 나열해라.
각각 옆에 "이번에 안 만들면 서비스가 성립하지 않는가"를 예/아니오로 표시해라.

칭찬하거나 권하지 마라. 목록만 내라.
```

4. 「아니오」인 것 중 다섯 개 이상을 골라 이유를 한 줄씩 붙이세요. 이유가 없으면 다음 주에 내가 다시 흔들립니다. 「안 만들 것」 칸이 이유 붙은 다섯 줄 이상이면 됩니다.
5. 문서 맨 위에 아래 한 줄을 적으세요. 만들 것이 늘어나는 것을 막는 잠금장치입니다.

```
규칙: 만들 것에 하나를 더하려면, 반드시 하나를 뺀다.
```

## 📘 말 풀이

**PRD(Product Requirements Document, 제품 요구사항 문서)** — «무엇을, 누구를 위해, 왜 만드는가»를 적어 둔 문서. 이름이 어려울 뿐 내용은 위의 네 칸이 전부입니다.

**MVP(Minimum Viable Product, 최소로 팔 수 있는 것)** — 이것저것 다 붙인 완성품이 아니라 돈을 받을 수 있는 최소한. 위의 「만들 것 셋」이 곧 이것입니다.

## ⚠️ 함정

**「안 만들 것」을 비워 둡니다.** 가장 흔합니다. 이 칸이 비어 있으면 이 문서는 아무 일도 하지 않고, 다섯 줄이 안 나오면 아직 안 정해진 것입니다.

**「안 만들 것」까지 AI에게 맡깁니다.** AI는 앞의 세 칸은 잘 쓰지만 이 칸은 눈치를 봐서 «필요하면 넣으세요» 식으로 씁니다. 이 칸은 사람이 정합니다.

**성공 기준에 셀 수 없는 말을 씁니다.** «만족도가 높다»는 셀 수 없습니다. «다음 달에도 남아 있는 사람 수»는 셀 수 있습니다.

**만들 것을 계속 늘립니다.** 하나 넣으면 하나 뺍니다. 이 규칙을 문서 맨 위에 적어 둡니다.
