문서 셋을 다 썼습니다. 그런데 여기서 대부분 실패합니다 — 폴더에 있는 것과 AI가 읽는 것은 다르기 때문입니다.

## ① 문서가 죽는 두 방식을 본다

문서를 아무리 잘 써 두어도 AI는 그 폴더에 무슨 파일이 있는지 스스로 뒤지지 않습니다. 그래서 새 대화를 열면 지난주에 정한 것을 또 뒤집습니다. 그리고 안 고친 문서는 틀린 문서가 되는데, 틀린 지도를 확신을 갖고 따라가니 **아무것도 안 읽히는 것보다 나쁩니다.**

| 어떻게 죽나 | 증상 |
|---|---|
| 안 읽힌다 | 새 대화마다 같은 설명을 처음부터 다시 한다 |
| 안 고친다 | 문서에는 이메일만 보낸다고 적혀 있는데 실제로는 메신저도 붙어 있다 |

둘 다 고칠 수 있습니다. 하나는 자리의 문제고, 하나는 습관의 문제입니다.

## ② 입구 하나에서 가리킨다

문서를 여기저기 흩어 두지 않고 입구를 하나 만들어 거기서 가리킵니다. 프로젝트 폴더 맨 위에 AI가 자동으로 읽는 파일 하나를 두고, 그 안에서 다른 문서들의 경로를 적습니다.

```
내프로젝트/
  (AI가 자동으로 읽는 지침 파일)   ← 입구. 여기서 아래를 가리킨다
  docs/
    PRD.md              ← 무엇을 만드나
    ARCHITECTURE.md     ← 무엇이 어디에 있나
    adr/                ← 왜 그렇게 정했나
```

입구 파일에는 이런 식으로 적습니다.

```
이 프로젝트에서 일하기 전에 반드시 읽는다.
- docs/PRD.md — 무엇을 만들고 무엇을 안 만드는가
- docs/ARCHITECTURE.md — 화면·저장소·빌려 쓰는 것의 구조
- docs/adr/ — 이미 내린 결정. 여기 있는 것을 뒤집지 않는다.
  뒤집어야 한다면 먼저 나에게 묻는다.
```

**마지막 두 줄이 중요합니다.** «읽어라»만 적으면 읽고 나서 뒤집습니다. «뒤집지 마라, 뒤집으려면 먼저 물어라»까지 적어야 합니다.

입구 파일을 제대로 만드는 일은 [[03-컨텍스트하네스/_스테이지|Stage 3]]의 내용입니다. 지금은 가리키는 줄만 적어 둬도 절반은 됩니다.

## ③ 바뀌는 그 자리에서 고친다

답은 하나입니다. **결정이 바뀌는 그 자리에서.** 나중에 몰아서 고치겠다고 미루면 일주일 뒤에는 무엇이 바뀌었는지 기억이 안 나서 못 고칩니다.

| 이런 일이 생기면 | 그 자리에서 |
|---|---|
| 안 만들기로 한 걸 만들기로 했다 | 요구사항 문서의 「안 만들 것」에서 지우고 「무엇을」로 옮긴다. 대신 뺄 것을 하나 고른다 |
| 빌려 쓰는 서비스를 바꿨다 | 구조 문서의 표를 고치고, 결정 기록을 하나 남긴다 |
| 화면이 하나 늘었다 | 구조 문서의 화면 표에 한 줄 추가한다 |
| 예전 결정을 뒤집었다 | 옛 결정 기록에 「대체됨」 한 줄, 새 결정 기록 하나 |

고치는 일도 AI에게 시킵니다. 손으로 안 고쳐도 되고, 시키는 데 30초입니다.

## ④ 새 대화 시험으로 잰다

문서가 살아 있는지 재는 방법은 딱 하나입니다. **새 대화를 열고, 문서만 주고, «무엇을 만드는 거야?»라고 묻습니다.**

| 이렇게 답하면 | 뜻 |
|---|---|
| 무엇을 · 누구를 위해 · 무엇을 안 만드는지까지 말한다 | 통과 |
| 무엇을 만드는지는 아는데 안 만들 것은 모른다 | 요구사항 문서의 「안 만들 것」이 부실하다 |
| 화면 이름이나 저장할 정보를 못 댄다 | 구조 문서가 부실하다 |
| 이미 정한 걸 "이렇게 하면 어떨까요"로 다시 제안한다 | 결정 기록이 안 읽히고 있다 |

이 시험을 만드는 내내 반복합니다. 한 달 뒤에 답이 흐려졌다면 문서가 실제를 못 따라간 것이고, 그때가 고칠 때입니다.

## ⑤ 다음 장의 1층을 본다

「하네스」는 AI에게 무엇을 읽히고 무엇을 못 하게 할지를 짜 놓은 판이고, 층이 넷입니다.

| 층 | 무엇 | 어디서 만드나 |
|---|---|---|
| 1층 | 문서 — 요구사항 · 구조 · 결정 기록 | 이 장 |
| 2층 | 입구 지침 파일 — 절대 어기면 안 되는 것 | Stage 3 |
| 3층 | 일을 시키고 받는 순서 | Stage 3 |
| 4층 | 규칙을 강제하는 장치 | Stage 3 |

**1층이 부실하면 위의 셋을 아무리 잘 쌓아도 무너집니다.** 지침 파일에 «PRD를 읽어라»라고 적어 뒀는데 PRD가 비어 있으면 읽을 게 없습니다.

## ⚡ 따라 하기

1. 문서 셋이 `docs` 폴더 안에 있는지 확인하세요. 흩어져 있으면 모으세요. `PRD.md`·`ARCHITECTURE.md`·`adr/`이 한 폴더에 나란히 보이면 됩니다.
2. 아래를 붙여넣어 입구 파일에 가리키는 줄을 적게 하세요. AI가 새 대화마다 자동으로 문서 셋을 찾아가게 하는 것입니다. 지침 파일 맨 앞에 「먼저 읽을 것」 목록과 «뒤집지 않는다» 두 줄이 생겨야 합니다.

```
이 프로젝트 폴더 맨 위에 있는 지침 파일을 열어라. 없으면 새로 만들어라.
코드는 건드리지 마라.

파일 맨 앞에 "먼저 읽을 것" 항목을 추가해라. 내용은 이렇게.
- docs/PRD.md — 무엇을 만들고 무엇을 안 만드는가
- docs/ARCHITECTURE.md — 화면·저장소·빌려 쓰는 것의 구조
- docs/adr/ — 이미 내린 결정

그 아래에 이 두 줄을 반드시 넣어라.
"docs/adr/ 에 있는 결정을 뒤집지 않는다."
"뒤집어야 한다고 판단되면 코드를 고치기 전에 먼저 나에게 묻는다."

이 파일에 다른 내용을 추가하지 마라. 지금은 이것만.
```

3. **새 대화를 열고** 문서 셋만 첨부한 뒤 아래를 물으세요. 문서만으로 AI가 답할 수 있는지 재는 시험입니다. 답 다섯 개가 번호대로 돌아옵니다.

```
첨부한 문서들만 읽고 답해라. 추측하거나 지어내지 마라.

1. 나는 무엇을 만들고 있는가 — 세 줄로
2. 누구를 위해 만드는가 — 두 줄로
3. 이번에 안 만들기로 한 것은 무엇인가 — 목록으로
4. 이미 정해져서 네가 바꾸면 안 되는 것은 무엇인가 — 목록으로
5. 문서만으로는 알 수 없어서 내가 채워야 하는 것 — 목록으로

문서에 없는 것은 "문서에 없음"이라고 써라.
```

4. 3번과 4번 답을 보세요. 비어 있으면 다음 장으로 넘어가지 않습니다 — 3번이 비면 [[02-명세/2-요구사항|2절]]로, 4번이 비면 [[02-명세/4-결정6줄|4절]]로 돌아갑니다.
5. 앞으로 결정이 바뀔 때마다 그 자리에서 아래를 시키세요. 바뀐 부분만 고쳐지고 `docs/adr`에 파일이 하나 늘어야 합니다.

```
방금 정한 것이 기존 문서와 어긋난다. 어긋난 곳을 찾아서 고쳐라.
docs/PRD.md · docs/ARCHITECTURE.md 를 확인하고,
바뀐 부분만 고쳐라. 안 바뀐 부분은 손대지 마라.
그리고 이 변경을 docs/adr/ 에 여섯 줄 형식으로 남겨라.
```

## ✅ 확인

- [ ] 문서 셋이 `docs` 폴더 한 곳에 모여 있나
- [ ] 입구 지침 파일에 「먼저 읽을 것」 목록과 «결정을 뒤집지 않는다» 줄이 있나
- [ ] 새 대화에 문서만 주고 물었을 때 답에 「안 만들 것」이 들어 있나
- [ ] 그 답에 「바꾸면 안 되는 결정」이 들어 있나

하나라도 «아니오»면 해당 절로 돌아갑니다. 여기가 다음 장의 1층이라 무너진 채로 올리지 않습니다.

## 📘 말 풀이

**하네스(harness, 작업 판)** — AI가 일할 때 무엇을 읽고 무엇을 못 하게 할지를 미리 짜 놓은 틀. 말에게 씌우는 마구에서 온 말로, 힘을 못 쓰게 묶는 게 아니라 원하는 방향으로 끌게 하는 장치입니다.

**컨텍스트(context, 지금 읽고 있는 것)** — AI가 이번 대화에서 실제로 보고 있는 글 전부. 여기 안 들어간 것은 AI에게 존재하지 않는 것입니다.

## ⚠️ 함정

**"문서 다 썼으니 끝."** 쓴 것과 읽히는 것은 다릅니다. 새 대화 시험을 한 번은 해 봐야 압니다.

**매번 손으로 문서를 붙여넣습니다.** 처음 며칠은 하지만 곧 안 합니다. 그래서 자리를 정해 자동으로 읽히게 만드는 것입니다.

**문서를 늘립니다.** 문서가 열 개가 되면 AI가 다 못 읽고 흘립니다. 셋을 유지하고, 늘려야 한다면 결정 기록 폴더 안에서 늘립니다.

**문서와 실제가 다른 채로 둡니다.** 없는 것보다 나쁩니다. 어긋난 걸 발견하면 만들던 걸 멈추고 먼저 고칩니다.
