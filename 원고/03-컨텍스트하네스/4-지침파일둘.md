도구는 둘을 씁니다 — 메인 하나, 백업 하나([[00-환경/1-도구지도|Stage 0]]). 그런데 둘은 **서로의 지침 파일을 읽지 않아서**, 메인에만 규칙을 적어 두고 백업을 부르면 그 도구는 아무것도 모르는 채로 내 프로젝트를 만집니다.

## ① 서로 안 읽는 것을 표로 본다

| | Claude Code | 코덱스 |
|---|---|---|
| 읽는 지침 파일 | `CLAUDE.md` 만 | `AGENTS.md` 만 |
| 상대 것을 읽나 | 안 읽습니다 (공식 문서에 명시) | 안 읽습니다 |
| 스킬을 두는 폴더 | `.claude/skills/` | `.agents/skills/` |
| 스킬 파일 형식 | `SKILL.md` | `SKILL.md` — 형식은 같고 폴더만 다릅니다 |
| 상대 설정 흡수 | 상대 것을 가져오는 명령이 있습니다 | 반대 방향은 없습니다 |
| 승인 방식 | 어디까지 알아서 하게 둘지를 한 축으로 | 「어디까지 만지나」와 「무엇을 물어보나」를 따로 |

충돌이 나는 게 아니라 그냥 서로 못 봅니다. 결과는 하나 — **두 번 쓰게 됩니다.**

## ② `@` 한 줄로 잇는다

내용은 `AGENTS.md`에 한 벌만 두고, `CLAUDE.md`에서 그것을 가리킵니다.

```markdown
# 이 프로젝트의 지침

@AGENTS.md
```

`@`로 시작하는 줄은 그 파일을 여기 끼워 넣으라는 뜻입니다. `AGENTS.md` 한 벌을 고치면 양쪽이 같이 바뀝니다 — **한 정보의 집은 하나**입니다.

파일 두 개가 싫으면 심볼릭 링크로 `CLAUDE.md`를 `AGENTS.md`의 바로가기로 만들 수도 있습니다. 다만 바로가기는 눈에 잘 안 보여서 나중에 헷갈리므로, 처음에는 `@` 한 줄을 권합니다.

## ③ 「리뷰는 다른 도구로」를 정직하게 본다

*"Claude로 짜고 코덱스로 리뷰한다"*는 많이 하는 방식이지만, 효과가 측정된 적은 없습니다.

| | |
|---|---|
| 흔한가 | 흔합니다. `AGENTS.md`에 Claude를 함께 적어 둔 저장소가 GitHub에 수십만 건 있습니다 (2026-09 조사) |
| 효과가 실측됐나 | 없습니다. 이 방식을 다룬 글은 전부 논증이지 측정이 아닙니다 |
| 찬성 | *"계획을 다른 도구에 리뷰시키면 항상 뭔가 찾아낸다"* |
| 반대 | *"큰 문제를 잡는 걸 본 적 없다. 어차피 만들다 보면 해결될 것만 지적한다"* |
| 오히려 반대 방향 근거 | AI가 유능해질수록 서로 비슷한 실수를 한다는 연구가 있습니다 *(현행 적용 여부 [확인 필요])* |

그래서 이렇게 말합니다 — «많은 개발자가 이렇게 한다. 다만 얼마나 이득인지 측정된 적은 없다». 지금은 **도구 하나를 제대로 익히는 게 먼저**이고, 두 번째 도구는 남의 돈·남의 개인정보가 걸린 결과물을 내보내기 직전에 한 번만 부릅니다.

## ④ 한 벌로 합치고 새 대화로 시험한다

합치는 것은 아래 ⚡에서 합니다. 시험은 1절과 같이 **새 대화에서 설명 없이** 묻는 것입니다.

## ⚡ 따라 하기

1. 프로젝트 폴더에서 지금 상태를 확인합니다. 두 파일이 이미 따로 있으면 어느 쪽이 맞는지부터 알아야 하기 때문입니다. 있는지 여부와 차이 표가 보여야 합니다.

```
이 폴더에 CLAUDE.md와 AGENTS.md가 각각 있는지 확인해줘.
있으면 두 파일의 내용이 어디가 다른지 표로 비교해줘.
```

2. 한 벌로 합칩니다. 두 곳에 두면 한 달 뒤 내용이 서로 달라지기 때문입니다. 끝나면 `AGENTS.md` 전체와 두 줄만 남은 `CLAUDE.md`가 보여야 합니다.

```
지침 내용을 AGENTS.md 한 파일로 합쳐줘.
그리고 CLAUDE.md는 아래 두 줄만 남겨줘.

# 이 프로젝트의 지침
@AGENTS.md

합친 뒤 AGENTS.md 전체를 보여줘. 100줄을 넘으면 넘긴 부분은 docs/ 로 빼고 경로로 가리켜줘.
```

3. 새 대화를 열고 설명 없이 묻습니다. `@` 줄이 정말 읽히는지는 이렇게만 알 수 있습니다. `AGENTS.md`에 적힌 NEVER 항목이 답으로 나와야 합니다.

```
이 프로젝트에서 절대 하면 안 되는 게 뭐야?
```

4. 백업 도구를 쓸 계획이면 스킬 폴더도 이어 둡니다. 형식은 같고 폴더만 다르기 때문입니다. 복사와 바로가기의 차이 설명이 먼저 나오고, 그다음 실행 결과가 보여야 합니다.

```
.claude/skills/ 에 있는 스킬들이 .agents/skills/ 에서도 보이게 해줘.
복사하는 방법과 바로가기를 거는 방법의 차이를 먼저 한 줄씩 설명하고,
어느 쪽을 권하는지 이유와 함께 말해줘. 그다음에 실행해줘.
```

### 이렇게 해 봤습니다 — 2026-09-10 · 정말 안 읽습니다

한쪽 도구를 몇 달 쓴 컴퓨터에 다른 도구를 새로 깔고, 각자의 설정 폴더를 열어 봤습니다. 이미 쓰던 도구는 지침 파일이 여러 층으로 채워져 있고 스킬 폴더에 9개가 있었는데, 새로 깐 도구는 **지침 0줄(빈 파일) · 스킬 0개**였습니다.

같은 컴퓨터, 같은 사람, 같은 프로젝트인데 새 도구는 아무것도 모르는 상태로 시작했습니다. 그래서 도구를 둘 쓰기로 했다면 두 번 쓸 각오를 하거나, 위의 우회(`@` 한 줄)를 걸어 두어야 합니다. 저는 이래서 「메인 하나 + 백업 하나」를 권합니다.

새로 깐 도구의 기본 권한도 확인했습니다 — 작업 폴더 안에서는 읽고 고치고 실행하지만, 폴더 밖으로 나가거나 인터넷에 닿으려면 물어보고, 인터넷은 기본으로 꺼져 있습니다. 설정을 안 건드려도 이 정도는 막혀 있다는 뜻입니다. 그래도 다 풀어 주는 설정은 쓰지 마세요.

## ✅ 확인

- [ ] 지침 내용이 한 벌만 있나 — 같은 내용이 두 파일에 복사돼 있지 않나
- [ ] `CLAUDE.md`를 열었을 때 `@AGENTS.md` 한 줄이 보이나
- [ ] 새 대화에서 설명 없이 3번 질문에 NEVER 항목이 답으로 왔나

## 📘 말 풀이

**심볼릭 링크(symbolic link)** — 파일의 바로가기. 실물은 한 곳에 있고, 다른 이름으로도 열리게 만드는 표지판입니다.

**샌드박스(sandbox)** — 도구가 놀 수 있는 모래밭의 울타리. 이 폴더 밖은 못 만진다, 인터넷은 못 쓴다 같은 경계를 물어보기 전에 미리 그어 두는 층입니다.

## ⚠️ 함정

**양쪽에 복사해 둡니다.** 처음엔 편한데, 한 달 뒤 두 파일의 내용이 서로 달라집니다. 어느 쪽이 맞는지 아무도 모릅니다.

**스킬을 만들고 다른 도구에서 안 보인다고 당황합니다.** 형식은 같고 폴더만 다릅니다. 복사하거나 바로가기를 걸면 됩니다.

**둘을 같은 폴더에서 동시에 켭니다.** 서로가 고친 것을 덮어씁니다.

**효과를 과장해서 스스로를 속입니다.** 두 번째 도구를 켠 날 결과가 좋았다면, 도구 때문인지 그날 내가 잘 시킨 건지 구분할 방법이 없습니다.
