## 왜 이걸 하나

도구는 **둘**을 씁니다 — 메인 하나, 백업 하나([[00-환경/1-도구지도|Stage 0]]).
그런데 **둘은 서로의 지침 파일을 읽지 않습니다.**

메인 도구에만 규칙을 적어 두고 백업 도구를 부르면, 그 도구는 **아무것도 모르는 채로** 내 프로젝트를 만집니다.
지금 5분이면 막을 수 있는 일입니다.

## 서로 다른 이름, 서로 안 읽음

| | Claude Code | 코덱스 |
|---|---|---|
| **읽는 지침 파일** | `CLAUDE.md` **만** | `AGENTS.md` **만** |
| **상대 것을 읽나** | ❌ **안 읽습니다** (공식 문서에 명시) | ❌ **안 읽습니다** |
| **스킬을 두는 폴더** | `.claude/skills/` | `.agents/skills/` |
| **스킬 파일 형식** | `SKILL.md` | `SKILL.md` — **형식은 같은데 폴더만 다릅니다** |
| **상대 설정 흡수** | 상대 것을 가져오는 명령이 **있습니다** | 반대 방향은 **없습니다** |
| **승인 방식** | 어디까지 알아서 하게 둘지를 한 축으로 정합니다 | **「어디까지 만질 수 있나」와 「무엇을 물어보나」를 따로** 정합니다 |

**충돌이 나는 게 아닙니다.** 그냥 **서로 못 봅니다.** 결과는 하나 — **두 번 쓰게 됩니다.**

## 우회 — 한 줄이면 됩니다

내용은 `AGENTS.md`에 **한 벌만** 두고, `CLAUDE.md`에서 그것을 가리킵니다.

```markdown
# 이 프로젝트의 지침

@AGENTS.md
```

`@`로 시작하는 줄은 **그 파일을 여기 끼워 넣으라**는 뜻입니다.
이러면 `AGENTS.md` 한 벌을 고치면 양쪽이 같이 바뀝니다. **한 정보의 집은 하나입니다.**

파일을 두 개로 두기도 싫으면 **심볼릭 링크**를 씁니다 — `CLAUDE.md`를 `AGENTS.md`의 **바로가기**로 만드는 것입니다. 다만 바로가기는 눈에 잘 안 보여서, 나중에 *"왜 두 파일이 똑같지"* 하고 헷갈립니다. **처음에는 `@` 한 줄을 권합니다.**

## ⚠️ 정직하게 — 「짜기는 하나로, 리뷰는 다른 하나로」

*"Claude로 짜고 코덱스로 리뷰한다"* — 많이 하는 방식입니다. 근데 **효과가 측정된 적은 없습니다.**

| | |
|---|---|
| **흔한가** | ✅ 흔합니다. `AGENTS.md`에 Claude를 함께 적어 둔 저장소가 GitHub에 **수십만 건** 있습니다 (2026-09 조사) |
| **효과가 실측됐나** | ❌ **없습니다.** 이 방식을 다룬 글은 전부 논증이지 측정이 아닙니다 |
| **찬성** | *"계획을 다른 도구에 리뷰시키면 항상 뭔가 찾아낸다"* |
| **반대** | *"큰 문제를 잡는 걸 본 적 없다. 어차피 만들다 보면 해결될 것만 지적한다"* |
| **오히려 반대 방향 근거** | AI가 유능해질수록 **서로 비슷한 실수를 한다**는 연구가 있습니다. "다른 AI를 하나 더 = 안전망 두 겹"이라는 가정이 약해집니다 *(현행 적용 여부 [확인 필요])* |

> 그래서 이렇게 씁니다 — ***"이렇게 하면 좋아진다"*가 아니라 «많은 개발자가 이렇게 한다. 다만 얼마나 이득인지 측정된 적은 없다».**

**지금 당장의 선택** — 도구 하나를 제대로 익히는 게 먼저입니다.
두 번째 도구는 **남의 돈이나 남의 개인정보가 걸린 결과물**을 내보내기 직전, 한 번만 부릅니다.
그리고 **둘을 동시에 켜 두고 같은 폴더를 돌리지 않습니다** — 얻는 것보다 부담이 큽니다.

## 📘 말 풀이

**심볼릭 링크(symbolic link)**
파일의 **바로가기.** 실물은 한 곳에 있고, 다른 이름으로도 열리게 만드는 표지판입니다. 실물을 고치면 바로가기로 열어도 고쳐진 내용이 보입니다.

**샌드박스(sandbox)**
도구가 **놀 수 있는 모래밭의 울타리.** 이 폴더 밖은 못 만진다, 인터넷은 못 쓴다 같은 경계를 미리 그어 두는 것입니다. 「무엇을 해도 되나」를 **물어보기 전에** 정해 두는 층입니다.

## ⚠️ 자주 걸리는 함정

- **한쪽에만 적어 둡니다.** 그리고 다른 도구를 부른 날 사고가 납니다.
- **양쪽에 복사해 둡니다.** 처음엔 편한데, 한 달 뒤 두 파일의 내용이 **서로 달라집니다.** 어느 쪽이 맞는지 아무도 모릅니다.
- **스킬을 만들고 다른 도구에서 안 보인다고 당황합니다.** 형식은 같고 **폴더만 다릅니다.** 복사하거나 바로가기를 걸면 됩니다.
- **둘을 같은 폴더에서 동시에 켭니다.** 서로가 고친 것을 덮어씁니다.
- **효과를 과장해서 스스로를 속입니다.** 두 번째 도구를 켠 날 결과가 좋았다면, 도구 때문인지 그날 내가 잘 시킨 건지 **구분할 방법이 없습니다.**

## ⚡ 이렇게 하세요

1. 지금 상태를 확인합니다.

```
이 폴더에 CLAUDE.md와 AGENTS.md가 각각 있는지 확인해줘.
있으면 두 파일의 내용이 어디가 다른지 표로 비교해줘.
```

2. **한 벌로 합칩니다.**

```
지침 내용을 AGENTS.md 한 파일로 합쳐줘.
그리고 CLAUDE.md는 아래 두 줄만 남겨줘.

# 이 프로젝트의 지침
@AGENTS.md

합친 뒤 AGENTS.md 전체를 보여줘. 100줄을 넘으면 넘긴 부분은 docs/ 로 빼고 경로로 가리켜줘.
```

3. **정말 이어졌는지 시험합니다.** 새 대화를 열고 설명 없이 묻습니다.

```
이 프로젝트에서 절대 하면 안 되는 게 뭐야?
```

4. 백업 도구를 쓸 계획이면, 스킬 폴더도 이어 둡니다.

```
.claude/skills/ 에 있는 스킬들이 .agents/skills/ 에서도 보이게 해줘.
복사하는 방법과 바로가기를 거는 방법의 차이를 먼저 한 줄씩 설명하고,
어느 쪽을 권하는지 이유와 함께 말해줘. 그다음에 실행해줘.
```

## ✅ 됐는지 확인

- [ ] 지침 내용이 **한 벌**만 있나 (같은 내용이 두 파일에 복사돼 있지 않나)
- [ ] `CLAUDE.md`를 열었을 때 **`@AGENTS.md` 한 줄**이 보이나
- [ ] 새 대화에서 **설명 없이** 3번 질문에 제대로 답이 왔나
- [ ] *"두 도구는 서로의 지침을 안 읽는다"*를 **한 문장으로 말할 수 있나**
- [ ] 「짜기는 하나, 리뷰는 다른 하나」의 효과가 **측정된 적 없다는 것**을 아나
