## 왜 이걸 하나

*"아까는 잘하더니 왜 갑자기 이상해지지?"*

능력이 떨어진 게 아닙니다. **책상이 꽉 찬 것**입니다.
대화가 길어지면 AI는 이미 정한 것과 어긋나는 답을 내고, 아까 고친 문제를 다시 만들고, 말투가 흐트러집니다.

이건 **예방할 수 있는 일**이고, 방법은 간단합니다. 몰라서 당하는 것뿐입니다.

## 컨텍스트는 책상이다

AI가 한 번에 들고 있을 수 있는 기억에는 **정해진 크기**가 있습니다. 책상 넓이와 같습니다.

- 지침 파일이 자리를 차지합니다 (그래서 짧아야 합니다)
- 읽은 파일이 자리를 차지합니다
- 주고받은 대화가 **계속 쌓입니다**

책상이 차면 새 서류를 놓을 자리가 없어서, **밑에 깔린 것을 못 보게 됩니다.**
사람처럼 "중요한 걸 기억하고 나머지를 잊는" 게 아니라 **다 흐려집니다.**

## 70% — 정리할 때의 신호

화면에 남은 자리가 표시됩니다. 이 숫자만 보면 됩니다.

| 얼마나 찼나 | 무엇을 하나 |
|---|---|
| **0~50%** | 그냥 합니다. 가장 정확한 구간입니다 |
| **50~70%** | 새 작업으로 넘어갈 참이면 **정리를 생각합니다** |
| **70% 넘음** | **지금 정리합니다.** 여기서부터는 결과가 눈에 띄게 나빠집니다 |

## 접기와 비우기 — 둘은 다릅니다

| | 접기 `/compact` | 비우기 `/clear` |
|---|---|---|
| **무엇을 하나** | 지금까지를 **요약해서** 유지 | **통째로 지우고** 처음부터 |
| **언제** | **같은 일**을 계속할 때 | **다른 일**로 넘어갈 때 |
| **남는 것** | 요약 + 지침 파일 | 지침 파일 |

**헷갈리면 비우기가 안전합니다.** 잃을 게 없으면 비우는 쪽이 맞습니다.
3절에서 본 대로, **접히기 직전 원본이 자동 백업되는 훅**이 있으면 접는 것도 무섭지 않습니다.

## 진짜 답 — 남길 것은 대화가 아니라 문서다

접기와 비우기는 응급처치입니다. 근본 방법은 이것입니다.

1. **큰 일은 대화가 아니라 문서에 적는다** — 지금 뭘 하는 중이고, 어디까지 했고, 다음이 뭔지
2. **자리가 줄면 그 문서를 갱신한다** — 대화에 있는 것을 문서로 옮긴다
3. **비우고, 다음 세션에서 이렇게 말한다**

```
진행 중인 것 이어서 해줘.
```

문서에 상태가 적혀 있으면 이 한 줄로 이어집니다.
**대화를 아끼려 하지 말고, 대화를 버려도 되게 만듭니다.**

## 큰 읽기는 딴 데 맡긴다

자료 스무 개를 읽어야 할 때, 메인 대화에서 읽으면 **책상이 그 자료로 덮입니다.**
읽은 내용은 대부분 쓸모없고 **결론만** 필요한데도요.

이럴 때 **서브에이전트**에게 맡깁니다. 그쪽이 딴 방에서 다 읽고 **결론만 가져옵니다.**
메인 대화에는 결론 몇 줄만 남습니다. 책상이 깨끗하게 유지됩니다.

```
자료 폴더 전체를 읽어야 하는데, 서브에이전트에게 맡겨서 결론만 가져와줘.
원문은 여기 붙이지 말고, 요약 10줄과 출처 목록만 보여줘.
```

**한 작업 = 한 대화**를 지키면 이 문제 대부분이 애초에 안 생깁니다.
*"문서도 봐주고, 코드도 짜고, 디자인도 보고, 결제도 붙여줘"*를 한 대화에 넣으면 전부 어중간하게 끝납니다.

## 📘 말 풀이

**컨텍스트(context)**
AI가 **한 번에 들고 있을 수 있는 기억의 크기.** 책상 넓이입니다. 지침·읽은 파일·주고받은 대화가 전부 여기 올라갑니다. 대화가 끝나면 **비워집니다.**

**토큰(token)**
그 기억을 **세는 단위.** 글자보다 조금 큰 덩어리라고 보면 됩니다. 한국어는 대략 한두 글자가 한 덩어리입니다. *"토큰을 아낀다"*는 말은 **책상 자리를 아낀다**는 뜻입니다.

**서브에이전트(subagent)**
**따로 떨어져 나가 일하는 분신.** 큰 조사를 대신 하고 **결론만** 가져옵니다. 읽은 원문은 그쪽 방에 두고 오기 때문에 메인 대화가 깨끗하게 유지됩니다.

## ⚠️ 자주 걸리는 함정

- **끝까지 버팁니다.** 90%에서 나온 결과를 믿고 코드를 짜면, 나중에 그 부분부터 무너집니다. 70%에서 정리합니다.
- **대화 자체를 기록으로 여깁니다.** 대화는 사라집니다. **문서에 옮긴 것만 남습니다.**
- **접기와 비우기를 반대로 씁니다.** 같은 일을 계속하는데 비우면 문맥을 다시 설명하고, 다른 일로 넘어가는데 접으면 앞의 일이 계속 끼어듭니다.
- **한 대화에 여러 일을 다 넣습니다.** 가장 흔하고 가장 비쌉니다.
- **큰 자료를 메인 대화에 통째로 붙입니다.** 붙이는 순간 자리의 절반이 날아갑니다.
- **비우기 전에 저장을 안 합니다.** 비우기 전에 **결과물을 먼저 저장**합니다.

## ⚡ 이렇게 하세요

1. **지금 얼마나 찼는지** 화면에서 확인하는 자리를 찾아 둡니다. 남은 자리 표시가 어디 뜨는지 눈에 익힙니다.

2. **끝내는 의식**을 정합니다. 한 작업이 끝날 때마다 매번 같은 순서로.

```
① 결과물 저장하기
② 배운 게 있으면 지침 파일 「실제로 망가진 것」에 한 줄 추가
③ 진행 상태를 문서에 적기
④ /clear
```

3. 상태 문서를 만듭니다.

```
docs/진행중.md 를 만들어줘. 아래 세 칸만.
- 지금 하는 일 (한 줄)
- 어디까지 했나 (목록)
- 다음에 할 것 (목록)
지금 이 대화에서 한 것을 기준으로 채워줘.
```

4. **비우고 이어 봅니다.** `/clear` 후 새 대화에서:

```
docs/진행중.md 읽고 진행 중인 것 이어서 해줘.
```

## ✅ 됐는지 확인

- [ ] 남은 자리(%)가 **화면 어디에 뜨는지** 아나
- [ ] **70%**라는 숫자를 말할 수 있나
- [ ] 접기와 비우기를 **언제 각각 쓰는지** 한 줄로 말할 수 있나
- [ ] `docs/진행중.md`가 **실제로 생겼나**
- [ ] 비운 뒤 **"이어서 해줘" 한 줄로 이어졌나**
- [ ] 큰 읽기를 **서브에이전트에게 맡겨** 봤나

다섯 번째가 «아니오»면 상태 문서가 부실한 것입니다. 대화가 아니라 **문서**를 고칩니다.
