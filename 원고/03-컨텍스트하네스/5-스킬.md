## 왜 이걸 하나

지침 파일은 **항상** 읽힙니다. 그래서 짧아야 합니다(1절).
그런데 *"보도자료는 이 순서로 정리해"*처럼 **가끔만 필요한 긴 절차**는 어디에 둘까요.

지침에 넣으면 매번 자리를 차지하고, 안 넣으면 매번 다시 설명합니다.
**그 사이를 메우는 것이 스킬입니다.**

이 절을 건너뛰면 [[05-구현/_스테이지|Stage 5]] 이후로 같은 절차를 매번 말로 풀게 됩니다.

## 스킬은 레시피북이다

요리책을 통째로 외우고 다니는 사람은 없습니다.
**목차만 알고 있다가, 필요한 요리가 정해지면 그 쪽을 폅니다.**

스킬이 정확히 그렇습니다.

| | 평소 | 맞는 상황이 오면 |
|---|---|---|
| **AI가 읽는 것** | 스킬의 **설명문 한 줄만** | **본문 전체**를 펼쳐서 읽음 |
| **차지하는 자리** | 거의 없음 | 그때만 |

그래서 스킬은 **아무리 많아도 부담이 되지 않습니다.** 안 쓰는 것은 잠들어 있습니다.

## ⭐ 그래서 설명문이 전부입니다

AI가 평소 보는 것은 **설명문 한 줄**뿐입니다.
그 한 줄에 **«언제 이걸 쓰는가»**가 없으면, 스킬은 만들어 놓고 **영영 안 펴집니다.**

| ❌ 안 펴지는 설명문 | ⭕ 펴지는 설명문 |
|---|---|
| `문서를 정리한다` | `회의록·메모·자료 뭉치를 하나의 문서로 정리할 때 쓴다. "정리해줘", "회의록 만들어줘", "이거 요약해서 문서로" 같은 말이 나오면 사용.` |
| `조사 도우미` | `어떤 주제를 조사해서 한 장으로 요약할 때 쓴다. "알아봐줘", "조사해줘", "시장 어때" 같은 말이 나오면 사용. 출처와 날짜를 반드시 붙인다.` |

**규칙 하나** — 설명문에는 «무엇을 하나»가 아니라 **«어떤 말이 나오면 쓰나»**를 적습니다.
내가 실제로 쓰는 말투 그대로 넣으면 됩니다.

## 스킬 하나의 생김새

폴더 하나 + 파일 하나입니다.

```
프로젝트폴더/
└── .claude/
    └── skills/
        └── 문서정리/
            └── SKILL.md
```

`SKILL.md` 안은 이렇게 생겼습니다.

```markdown
---
name: 문서정리
description: 회의록·메모·자료 뭉치를 하나의 읽을 수 있는 문서로 정리할 때 쓴다. "정리해줘", "회의록 만들어줘", "이거 문서로" 같은 말이 나오면 사용.
---

# 문서 정리

## 순서
1. 재료를 전부 읽고 중복을 표시한다
2. 결론 · 결정된 것 · 남은 질문 셋으로 나눈다
3. 결론을 맨 위에 놓는다
4. 날짜와 출처를 각 줄에 붙인다
5. 확인 못 한 것은 [확인 필요]로 남긴다

## 내지 않을 것
- 추측을 사실처럼 쓰지 않는다
- 원문을 그대로 붙이지 않는다. 다시 쓴다
```

맨 위 세 줄(`---` 사이)이 **설명문 자리**이고, 그 아래가 **본문**입니다.
본문이 길어지면 딴 파일로 쪼개고 여기서는 **경로로 가리킵니다** — 지침 파일과 같은 원리입니다.

## 📘 말 풀이

**스킬(Skill)**
**레시피북 한 권.** 자주 하는 일의 순서를 적어 둔 파일입니다. AI가 평소에는 목차만 보고 있다가, 맞는 상황이 오면 펼쳐 읽습니다.

**설명문(description)**
스킬 맨 위에 적는 **«언제 이걸 쓰는가» 한 줄.** AI가 평소에 유일하게 읽는 부분이라, 여기가 부실하면 스킬이 있어도 안 불려 나옵니다.

**맨 위 칸(frontmatter)**
파일 맨 위에 `---` 두 줄 사이에 적는 **이름표 구역.** 이름과 설명문이 여기 들어갑니다. 본문이 아니라 **꼬리표**라고 보면 됩니다.

## ⚠️ 자주 걸리는 함정

- **⚠️ 비밀값을 넣습니다.** 스킬 파일에 키·비밀번호·계정 정보를 **절대** 넣지 않습니다. 스킬은 남에게 그대로 건네줄 수 있는 것만 담습니다. 필요하면 *"키는 `.env`에서 읽는다"*라고 **적기만** 합니다.
- **설명문에 「무엇을 하나」만 적습니다.** 그러면 안 펴집니다. **어떤 말이 나오면 쓰는지**를 적습니다.
- **한 스킬에 다섯 가지 일을 넣습니다.** 언제 써야 할지 AI도 나도 모릅니다. **하나에 하나**입니다.
- **본문이 수백 줄이 됩니다.** 펼쳐지는 순간 자리를 다 잡아먹습니다. 길면 쪼개고 경로로 가리킵니다.
- **만들어 놓고 안 씁니다.** 스킬은 **내가 이미 세 번 이상 시킨 일**만 만듭니다. 안 해 본 일을 미리 스킬로 만들면 틀린 순서가 굳습니다.
- **폴더를 헷갈립니다.** 백업 도구는 스킬 폴더 이름이 다릅니다(4절).

## ⚡ 이렇게 하세요

비개발자가 **바로 값을 보는 스킬 셋**을 만듭니다.

```
내 프로젝트에 쓸 스킬 3개를 만들어줘. 각각 .claude/skills/<이름>/SKILL.md 파일 하나로.

1) 문서정리 — 회의록·메모·자료 뭉치를 하나의 읽을 수 있는 문서로 정리
2) 조사요약 — 주제 하나를 조사해서 한 장으로 요약. 출처와 날짜를 반드시 붙이고, 확인 못 한 건 [확인 필요]로
3) 발행전점검 — 밖으로 내보내기 직전 점검. 비밀값이 섞였는지 · 깨진 링크 · 오타 · 날짜가 옛날 것인지

각 파일의 규칙:
- 맨 위 --- 사이에 name과 description
- description에는 "어떤 말이 나오면 쓰는가"를 내 말투로 넣을 것 (예: "정리해줘", "조사해줘", "올려도 돼?")
- 본문은 순서 6단계 이내 + "하지 않을 것" 목록
- 키·비밀번호는 절대 넣지 말고, 필요하면 .env에서 읽는다고 적기만 할 것
- 각 파일 40줄 이내

만든 뒤 세 파일의 description만 모아서 보여줘.
```

그다음 **정말 불려 나오는지** 시험합니다. 스킬 이름을 대지 **않고** 평소 말투로 시킵니다.

```
어제 회의 메모 세 개 있는데, 이거 하나로 정리해줘.
```

→ 답이 시작될 때 **어떤 스킬을 쓰는지 표시**되면 성공입니다.
안 불려 나오면 **설명문에 내가 방금 쓴 말을 추가**하고 다시 시험합니다.

## ✅ 됐는지 확인

- [ ] `.claude/skills/` 안에 **폴더 세 개**가 생겼나
- [ ] 각 `SKILL.md` 맨 위에 **`name`과 `description`**이 있나
- [ ] **스킬 이름을 대지 않고** 평소 말투로 시켰을 때 스킬이 **불려 나왔나**
- [ ] 세 파일 어디에도 **비밀값이 없나**
- [ ] 안 불려 나온 스킬의 **설명문을 고쳐서 다시 시험**해 봤나

세 번째가 «아니오»면 설명문 문제입니다. 본문이 아니라 **설명문**을 고칩니다.

## 🔎 더 깊이

- 스킬을 **여러 개 조합해 한 줄로 실행**하는 것이 슬래시 명령입니다. 이미 깔린 것들의 목록은 [[부록/_스테이지|부록]]에.
- 검색해 볼 말 — `SKILL.md`, `agent skills`, `skill description trigger`
