## 왜 이걸 하나

새 대화를 열 때마다 같은 말을 반복하고 있다면 — *"한국어로 답해줘", "이 프로젝트는 이런 거고", "이 폴더는 건드리지 마"* — 도구가 나쁜 게 아니라 **어디에도 적어 두지 않은 것**입니다.
AI는 대화가 끝나면 **기억이 남지 않습니다.** 매번 처음 만나는 신입입니다.

이 절을 건너뛰면 뒤의 모든 장에서 **"설명 30분 + 일 10분"**이 반복됩니다.
비개발자에게 이 장의 가장 큰 이득이 여기 있습니다 — **새 대화를 열어도 설명이 필요 없어집니다.**

## 원리 한 문장

> **글로벌 설정 = 코드를 어떻게 작성할 것인가 / 프로젝트 지침 = 이 프로젝트가 어떻게 동작하는가.
> 둘은 자동으로 합쳐집니다.**

「어떻게 일하나」와 「여기가 어떤 곳인가」는 다른 층입니다.
섞어 놓으면 프로젝트를 옮길 때마다 다시 씁니다. 나눠 두면 **한 번만 씁니다.**

## 무엇을 어느 층에 적나

| | 글로벌 (위층) | 프로젝트 (아래층) |
|---|---|---|
| **어디에** | 내 컴퓨터 홈 폴더 안 설정 폴더 — `~/.claude/CLAUDE.md` | 그 프로젝트 폴더 맨 위 — `CLAUDE.md` |
| **언제 읽히나** | **모든** 프로젝트에서 항상 | **그 폴더**에서 일할 때만 |
| **무엇을 적나** | 나와 일하는 **방식** | 이 프로젝트의 **사실** |
| **예** | 한국어로 답한다 · 결론을 먼저 말한다 · 비밀값을 코드에 넣지 않는다 · 지우기 전에 물어본다 · 작업 단위마다 저장한다 | 무엇을 만드는 서비스인가 · 어떤 도구를 쓰나 · 건드리면 안 되는 폴더 · 자주 쓰는 명령 · **문서가 어디 있나** |
| **길이** | 짧게 | 짧게 |

**판단은 한 줄이면 됩니다** — 다른 프로젝트에서도 참이면 **위층**, 여기서만 참이면 **아래층**.

## 짧을수록 강하다

지침 파일은 **대화를 열 때마다 통째로 읽힙니다.** 길면 정작 오늘 할 일을 밀어냅니다.
**100줄 안**을 목표로 하고, 길어지는 것은 문서로 빼고 **한 줄로 가리킵니다.**

```
## 문서 참조
- 요구사항: docs/요구사항.md
- 구조: docs/구조.md
- 결정 기록: docs/결정기록.md
```

이 세 줄이 [[02-명세/_스테이지|Stage 2]]에서 만든 문서를 **하네스의 1층**으로 끌어올리는 자리입니다.
AI는 필요할 때 그 파일을 열어 읽습니다. 지침에 내용을 통째로 복사하지 않습니다.

## 일반론 대신 「실제로 망가진 것」

지침을 처음 쓰는 사람이 가장 많이 하는 실수는 **모범 답안을 적는 것**입니다.

| ❌ 의미 없음 | ⭕ 값이 있음 |
|---|---|
| 코드는 깨끗하게 짜자 | 지난주에 발송 함수를 잘못 짜서 메일이 두 번 갔다 → **보내기 전에 항상 구독 상태를 확인한다** |
| 보안에 신경 쓰자 | **비밀값은 `.env`에만 둔다. 저장 전에 섞였는지 확인한다** |

지침의 「실제로 망가진 것」 칸은 **사고가 날 때마다 한 줄씩** 늘어납니다.
반 년이 지나면 그 칸이 가장 비싼 자산이 됩니다 — 같은 실수를 두 번 하지 않게 만드는 면역입니다.

## 📘 말 풀이

**지침 파일**
AI가 일을 시작할 때 **자동으로 먼저 읽는 메모장.** 파일 이름이 정해져 있어서(`CLAUDE.md`) 그 이름으로 두면 알아서 읽습니다. 대화창에 매번 붙여넣을 말을 파일에 옮겨 놓은 것이라고 생각하면 됩니다.

**홈 폴더 (`~`)**
내 컴퓨터에서 **나만의 짐이 놓이는 자리.** 글에서 `~/`로 시작하는 경로는 전부 이 폴더 안입니다. 앞에 점이 붙은 폴더(`.claude`)는 평소에 숨겨져 있습니다 — 설정이 놓이는 자리라 그렇습니다.

## ⚠️ 자주 걸리는 함정

- **어디에도 안 적고 대화창에만 씁니다.** 그 대화가 끝나면 사라집니다. 파일에 적어야 남습니다.
- **두 층을 섞습니다.** 프로젝트 지침에 "한국어로 답해줘"를 적으면, 프로젝트를 하나 더 만들 때 또 적게 됩니다.
- **지침에 비밀값을 적습니다.** 키·비밀번호는 **절대** 지침 파일에 넣지 않습니다. 지침은 남에게 보여 줄 수 있는 것만 담습니다.
- **한 번 쓰고 다시 안 봅니다.** 지침은 살아 있는 문서입니다. 고치지 않으면 반년 뒤엔 틀린 말이 됩니다.
- **너무 깁니다.** 500줄짜리 지침은 안 읽히는 게 아니라, **다른 걸 밀어내면서** 읽힙니다.

## ⚡ 이렇게 하세요

1. 도구를 열고 아래를 붙여넣어 **글로벌 층**을 만듭니다.

```
내 홈 폴더의 ~/.claude/CLAUDE.md 를 열어서(없으면 새로 만들어서) 아래 규칙을 정리해 넣어줘.
- 항상 한국어로 답한다
- 결론을 먼저 말하고, 근거는 그다음에
- 비밀값(키·비밀번호)은 코드나 대화에 절대 넣지 않는다
- 파일을 지우거나 되돌리기 전에 반드시 나에게 먼저 물어본다
- 확인하지 못한 것은 "추측"이라고 표시한다
50줄을 넘기지 말고, 다 쓴 다음 전체 내용을 보여줘.
```

2. 이어서 **프로젝트 층**을 만듭니다. Stage 2에서 만든 문서가 있는 폴더에서 실행합니다.

```
이 폴더에 맞는 CLAUDE.md를 100줄 이내로 만들어줘. 아래 순서로.
1) 이 프로젝트가 뭔지 3줄
2) 쓰는 도구 목록
3) 반드시 지킬 것 — NEVER / ALWAYS 5개 이내 (진짜 어기면 안 되는 것만)
4) 자주 쓰는 명령
5) 문서 참조 — docs/ 안의 파일들을 경로로 가리키기만 할 것 (내용 복사 금지)
6) 실제로 망가진 것 — 지금은 빈 칸으로 두고 제목만
일반론은 넣지 말고, 이 폴더를 실제로 살펴본 사실만 적어줘.
```

3. **가장 중요한 시험** — 대화를 완전히 새로 열고(`/clear`), 아무 설명 없이 이렇게만 묻습니다.

```
지금 이 프로젝트에서 내가 절대 하면 안 되는 게 뭐야? 그리고 요구사항 문서는 어디 있어?
```

## ✅ 됐는지 확인

- [ ] 파일이 **두 개** 생겼나 — 홈 폴더 안 하나, 프로젝트 폴더 안 하나
- [ ] **새 대화에서 설명 없이** 3번 질문에 제대로 답이 돌아왔나
- [ ] 프로젝트 지침 안에 **Stage 2 문서 경로**가 적혀 있나
- [ ] 두 파일 모두 **100줄 아래**인가
- [ ] 지침 안에 **비밀값이 한 글자도 없나**

하나라도 «아니오»면 이 절을 다시 봅니다. 여기가 이 장 전체의 바닥입니다.
