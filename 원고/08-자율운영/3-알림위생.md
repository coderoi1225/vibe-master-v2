## 왜 이걸 하나

점검이 무언가를 발견해도 **내가 못 보면 없는 것과 같습니다.**
반대로, 내가 다 보게 만들면 일주일 만에 하나도 안 보게 됩니다.

그래서 이 절은 "어디로 받나"(경로)와 **"무엇을 받지 않나"**(위생) 둘입니다.
둘 중 어려운 쪽은 두 번째입니다. 알림을 만드는 건 5분이고, **알림을 지우는 건 결심**입니다.

## 어디로 받나 — 셋 중 하나

| 경로 | 언제 좋은가 | 한계 |
|---|---|---|
| **텔레그램 봇** | **휴대폰에 즉시. 무료.** 잠금화면에 뜬다 | 설정에 5분쯤 걸린다 |
| **디스코드 웹훅** | 이미 디스코드를 쓰고 있다면 가장 빠름. 기록이 채널에 쌓인다 | 알림을 켜 두지 않으면 못 본다 |
| 이메일 | 아무 설정 없이 된다 | **늦다.** 다른 메일에 묻힌다 |

**혼자라면 텔레그램입니다.** 이유는 하나 — 새벽 3시에 잠금화면에 뜨는 것은 이것뿐입니다.

### 다만 0순위는 따로 있습니다 — 아무것도 안 깔고 시작하기

위 셋 중 무엇을 고르든 **오늘 당장 켤 수 있는 것이 하나 더 있습니다. 깃허브가 이미 보내 줍니다.**

검사가 실패하면 깃허브가 알려 줍니다. 봇도, 열쇠도, 새 계정도 필요 없습니다.
**설정에서 스위치 하나만 켜면 됩니다.**

```
깃허브 오른쪽 위 내 사진 → Settings → Notifications → Actions
→ 받는 곳으로 «Email»을 고르고
→ ⭐ «Only notify for failed workflows» 를 켠다 → Save
```

마지막 줄이 핵심입니다. **이걸 안 켜면 성공한 것까지 전부 옵니다.** 하루에 열 통씩 오면
일주일 만에 안 보게 되고, 그때부터는 알림이 있으나 마나입니다.
**「깨울 것만 울린다」는 원칙이 여기서 시작됩니다.**

| | 깃허브 기본 알림 | 텔레그램 봇 |
|---|---|---|
| 설치·설정 | **스위치 하나** | 봇 만들기 · 열쇠 보관 · 연결 확인 (20~40분) |
| 언제 오나 | 메일함에 (몇 분 안에) | **잠금화면에 즉시** |
| 무엇을 알려 주나 | **검사·빌드 실패만** | 내가 정한 것 아무거나 (사이트가 죽었나 등) |
| 새벽에 나를 깨우나 | ❌ | ✅ |

> **먼저 스위치를 켜고 일주일 살아 보세요.** 그동안 알림이 몇 번 왔는지, 그중 몇 번이
> 정말 급했는지 세어 봅니다. **급한 게 한 번도 없었다면 텔레그램은 아직 필요 없습니다.**
> 「사이트가 죽었는데 아침까지 몰랐다」가 실제로 한 번 생기면 그때 붙입니다.
>
> **텔레그램을 안 쓰는 사람도 많습니다.** 그때는 깃허브 기본 알림 + 「매일 아침 요약」(다음 절)으로
> 충분합니다. **알림 수단이 없다고 자율 운영을 못 하는 게 아닙니다.**
슬랙은 좋은 도구지만 **혼자면 과합니다.** 팀에게 알리기 위한 장치를 나 혼자 쓰면, 나에게 말을 거는 나만 남습니다.

**받는 곳은 두 개까지입니다.** 급한 것은 텔레그램, 기록으로 남길 것은 디스코드. 셋이 되는 순간 어디를 봐야 할지 몰라집니다.

## 알림 위생 3원칙

### ① 깨울 것만 울린다

**지금 당장 내가 일어나서 뭔가 해야 하는 것**만 소리를 냅니다.
"내일 봐도 되는 것"은 알림이 아니라 **아침 요약 한 통**에 들어갑니다.

| 지금 울린다 | 아침에 묶어서 |
|---|---|
| 사이트가 죽었다 | 링크 하나가 깨졌다 |
| 결제가 연달아 실패한다 | 인증서가 20일 뒤 만료된다 |
| 데이터가 안 들어온다 | 페이지가 조금 느려졌다 |

### ② 연쇄 장애는 한 건으로 묶는다

데이터베이스가 죽으면 그 뒤에 붙은 것이 **전부 같이 죽습니다.**
그러면 알림이 한 개가 아니라 **서른 개** 옵니다. 서른 개를 보고 알 수 있는 건 하나도 없습니다.

두 가지로 막습니다.
- **같은 문제는 한 번만** — 계속 죽어 있으면 5분마다 다시 알리지 않고, 처음 한 번과 **되살아났을 때** 한 번만.
- **뿌리만 알린다** — 데이터베이스가 죽었으면 "데이터베이스가 죽었다" 하나만. 거기 붙은 다섯 개의 비명은 함께 접습니다.

### ③ 한 달 무시한 알림은 지운다

가장 중요하고, 가장 안 지켜집니다.

**한 달 동안 울렸는데 내가 아무 조치도 안 한 알림은 알림이 아닙니다.** 소음입니다.
"언젠가 필요할지도 모르니까"는 그 알림을 남길 이유가 되지 않습니다. 오히려 **다른 알림을 못 보게 만드는 이유**가 됩니다.

앞 절의 `점검표.md`에 「지난달 울린 횟수」 칸을 만든 게 이걸 판정하기 위해서입니다.
매월 1일에 그 표를 열고, **울렸는데 아무것도 안 한 줄을 지웁니다.**

## 알림 기준은 딱 하나

큰 회사의 운영 원칙에서 1인이 그대로 가져올 수 있는 문장이 하나 있습니다.

> **"지금 사용자에게 보이는 문제인가."**

이게 전부입니다. 예면 울리고, 아니면 안 울립니다.
서버 사용량이 70%가 됐다 — 사용자에게 안 보입니다. 안 울립니다.
로그에 경고가 하나 늘었다 — 안 보입니다. 안 울립니다.
결제 버튼을 눌렀는데 아무 일도 안 일어난다 — **보입니다. 울립니다.**

그리고 이 원칙에는 뒷면이 있습니다.

> **과잉 모니터링이 과소보다 나쁩니다.**

점검이 없으면 **모르는 상태**지만, 점검이 너무 많으면 **알 수 있는데도 못 보는 상태**가 됩니다.
후자가 더 나쁜 이유는, 본인은 잘 감시하고 있다고 믿기 때문입니다.

## 📘 말 풀이

**봇(bot)**
사람 대신 메시지를 보내는 계정. 텔레그램에서는 봇을 하나 만들면 **비밀 열쇠(토큰)** 를 주는데, 그 열쇠로 내 폰에 메시지를 보낼 수 있습니다.

**웹훅 주소(webhook URL)**
"여기로 메시지를 던지면 내 채널에 뜬다"는 전용 주소. **이 주소를 아는 사람은 누구나 내 채널에 글을 쓸 수 있으므로 비밀번호처럼 다룹니다.**

## ⚠️ 자주 걸리는 함정

- **봇 토큰이나 웹훅 주소를 코드에 그대로 적기.** 저장소에 올라가는 순간 남이 내 채널에 광고를 뿌립니다. 반드시 저장소의 **비밀값 보관함(Secrets)** 에 넣고 이름으로만 부릅니다.
- **봇에게 먼저 말을 걸지 않기.** 텔레그램 봇은 **내가 먼저 대화를 시작해야** 나에게 메시지를 보낼 수 있습니다. 만들자마자 안 오는 이유의 대부분이 이것입니다.
- **알림에 개인정보 담기.** 사용자 이메일·전화번호를 알림 본문에 넣지 않습니다. "결제 실패 3건"까지만 쓰고, 누구인지는 로그인해서 봅니다.
- **복구 알림을 안 만들기.** 죽었다는 소식만 오고 살아났다는 소식이 안 오면, 하루 종일 불안합니다. **되살아났을 때도 한 통** 보냅니다.
- **알림을 무음으로 돌려 두기.** 그 순간 이 장 전체가 무효가 됩니다. 무음으로 돌리고 싶어졌다면 그건 **알림을 지우라는 신호**입니다.

## ⚡ 이렇게 하세요

**1) 텔레그램 봇을 만듭니다.** 5분입니다.

```
① 텔레그램에서 @BotFather 를 검색해 대화 시작
② /newbot 입력 → 이름과 아이디를 정하면 긴 글자 줄(토큰)을 준다
③ 방금 만든 내 봇을 검색해서 들어가 /start 를 눌러 대화를 먼저 연다  ← 이 단계를 빠뜨리면 안 온다
④ 브라우저에서 아래 주소를 열어 내 방 번호(chat id)를 확인한다
   https://api.telegram.org/bot<토큰>/getUpdates
```

**2) 토큰과 방 번호를 저장소의 비밀값에 넣습니다.**

```
깃허브 저장소 → Settings → Secrets and variables → Actions → New repository secret
  TELEGRAM_TOKEN   = 받은 토큰
  TELEGRAM_CHAT_ID = 확인한 방 번호
```

**3) 앞 절의 감시에 알림을 붙입니다.** 실패했을 때만 울리게.

```yaml
# .github/workflows/살아있나.yml 에 이어 붙입니다
      - name: 죽었으면 텔레그램으로
        if: failure()
        run: |
          curl -s -X POST \
            "https://api.telegram.org/bot${{ secrets.TELEGRAM_TOKEN }}/sendMessage" \
            -d chat_id="${{ secrets.TELEGRAM_CHAT_ID }}" \
            -d text="🔴 사이트가 응답하지 않습니다. $(date '+%m/%d %H:%M')"
```

**4) 일부러 한 번 깨뜨려서 폰으로 확인합니다.** 이게 이 절의 진짜 과제입니다.

```
감시 주소를 잠깐 존재하지 않는 주소로 바꾼다
→ Actions 탭에서 Run workflow 를 눌러 지금 돌린다
→ 휴대폰 잠금화면에 빨간 메시지가 뜨는 것을 눈으로 본다
→ 주소를 되돌린다
```

**5) 매월 1일에 할 일을 달력에 넣습니다.**

```
매월 1일 — 점검표.md 를 열고, 지난달 울렸는데 내가 아무것도 안 한 줄을 지운다
```

## ✅ 됐는지 확인

- [ ] **알림이 실제로 휴대폰에 왔나** — 코드를 짠 게 아니라, 잠금화면에서 **눈으로 봤나**
- [ ] 사이트를 되살렸을 때 **복구 알림도 왔나**
- [ ] 토큰과 방 번호가 코드가 아니라 **비밀값 보관함에** 들어 있나 (`git grep` 으로 토큰이 안 나오는 것을 확인했나)
- [ ] 알림을 받는 곳이 **두 개 이하인가**
- [ ] 매월 1일 「알림 청소」가 **달력에 들어가 있나**
- [ ] 한 달 뒤에 무시한 알림이 있으면 **지울 생각이 있나**
