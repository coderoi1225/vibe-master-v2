## 왜 이걸 하나

이 장에서 만든 것들이 늘어나면 어느 순간 이런 질문이 옵니다.

**"밤에 도는 이 일이, 도중에 두 갈래로 갈라져야 하면 어떻게 하지?"**

예를 들어 야간 점검이 이렇게 되어야 한다면요.

- 실패가 **빌드 문제면** → 수정안을 만들어 PR
- 실패가 **외부 서비스 문제면** → 고칠 게 없으니 기록만 남기고 끝
- 실패가 **결제 문제면** → 아무것도 하지 말고 **나를 깨운다**

프롬프트 한 장으로 "알아서 판단해서 셋 중 하나를 해"라고 시킬 수는 있습니다.
**그런데 밤마다 다르게 행동합니다.** 어제는 기록만 남기고 오늘은 PR을 열고, 왜 그랬는지 알 수 없습니다.

여기서 필요해지는 것이 **그래프**입니다.

## 용어 체인 — 다섯 단계

지금까지 배운 말들이 사실 한 줄로 이어집니다. **뒤로 갈수록 더 넓은 것을 정합니다.**

| 단계 | 무엇을 정하나 | 한 줄 |
|---|---|---|
| **프롬프트** | 뭐라고 말할까 | 이번 한 번 무엇을 시킬까 |
| **컨텍스트** | 무엇을 알려 줄까 | 이 일에 필요한 재료를 붙여 준다 |
| **하네스** | **무엇을 읽히나** | 매번 자동으로 읽히는 것을 자리에 놓아 둔다 |
| **루프** | 몇 번 돌까 | 시켰다 → 해 봤다 → 확인했다 → 다시 → 될 때까지 |
| **그래프** | **어떤 순서로 도나** | 갈림길과 순서를 미리 그려 둔다 |

**하네스와 그래프는 층이 다릅니다.** 이걸 섞으면 둘 다 망가집니다.

- **하네스**는 **무엇을 읽히나** — 지침 파일, 프로젝트 문서, 규칙. **재료** 쪽입니다.
- **그래프**는 **어떤 순서로 도나** — 이거 다음에 저거, 여기서 갈라짐. **동선** 쪽입니다.

같은 하네스를 두고 그래프만 바꿀 수 있고, 같은 그래프에 하네스만 바꿔 낄 수도 있습니다.
그래서 한 장에 묶어서 설명하면 틀립니다.

## ⚠️ 그래프 엔지니어링은 지식 그래프가 아닙니다

**가장 많이 생기는 오해라서 따로 씁니다.**

| | 무엇 | 여기서 말하는 것 |
|---|---|---|
| **지식 그래프** | 정보들의 **관계**를 그물처럼 이어 둔 것. "A는 B의 자회사" | ❌ 아니다 |
| **제어 그래프** | 일이 **어떤 순서로 도는지**를 그려 둔 것. "① 다음 ②, 실패면 ③" | ✅ **이것** |

**"그래프 엔지니어링"은 제어 그래프 쪽입니다.**
검색하면 지식 그래프 이야기가 훨씬 많이 나오므로, 검색할 때는 `control flow`나 `orchestration`을 함께 넣습니다.

말을 바꿔서 기억해도 됩니다 — **순서도**입니다. 학교에서 그리던 그 마름모와 화살표.
새로운 개념이 아니라, **AI에게 시키는 일에도 순서도를 그려 두게 됐다**는 이야기입니다.

## 1인에게 언제 필요한가

**대부분의 경우 필요 없습니다.** 이 절에서 가장 중요한 문장입니다.

| 상태 | 무엇으로 |
|---|---|
| 단계가 **1~4개**, 갈림길 없음 | **프롬프트 한 장.** 그래프는 과하다 |
| 단계가 **다섯을 넘고, 중간에 갈림길이 생김** | **그래프를 그린다** |
| 같은 일을 **매일 똑같이 반복**해야 함 | 그래프를 그린다 |
| 틀렸을 때 **어디서 틀렸는지 찾아야** 함 | 그래프를 그린다 |

**단계 다섯 · 갈림길 하나 — 이 선을 넘기 전에는 그리지 않습니다.**
그 전에 그리면, 프롬프트 세 줄이면 될 일에 도구 하나를 배우고 파일 다섯 개를 만들게 됩니다.

그리고 그래프는 **종이에 먼저 그립니다.** 도구는 나중입니다. 종이에 못 그리는 흐름은 도구로도 못 만듭니다.

## 루프 안에서 루프 위로

이 장 전체가 사실 이 변화에 관한 것이었습니다.

| | **루프 안에**(in the loop) | **루프 위에**(on the loop) |
|---|---|---|
| 내 자리 | 매 단계마다 내가 «예»를 누른다 | 돌게 두고, **정해 둔 지점에서만** 본다 |
| 내가 보는 것 | 모든 것 | **막힌 것과 승인할 것** |
| 몇 개를 볼 수 있나 | 하나 | 여러 개 |
| 위험 | 내가 병목이 된다 | **울타리가 없으면 사고가 난다** |

**위로 올라가는 값이 울타리입니다.**
5절에서 권한을 잠근 이유가 여기 있습니다. 매 단계를 안 보게 되는 대신, **못 하는 일을 미리 정해 둡니다.**

그러니 순서를 거꾸로 하면 안 됩니다. **울타리를 세운 다음에 루프 위로 올라갑니다.**

## 📘 말 풀이

**루프(loop)**
AI가 혼자 도는 반복. 시켰다 → 해 봤다 → 결과를 확인했다 → 안 됐으면 다시. 사람이 매번 안 눌러도 될 때까지 돕니다.

**제어 그래프(control graph)**
일의 순서와 갈림길을 미리 정해 둔 그림. 마름모와 화살표로 그리는 **순서도**와 같은 것입니다.

**루프 위에(human on the loop)**
매 단계 승인하는 대신, **정해 둔 몇 개 지점에서만** 사람이 들어가는 방식. 그 지점을 정하는 것이 사람의 일입니다.

## ⚠️ 자주 걸리는 함정

- **지식 그래프와 섞어 이해하기.** 이 절의 그래프는 **정보의 관계**가 아니라 **일의 순서**입니다.
- **하네스에 순서를 적기.** 지침 파일에 "①번 다음 ②번"을 길게 적어도 AI는 자주 건너뜁니다. **글로 적은 순서는 지켜지지 않습니다.** 순서를 강제하려면 도구가 그 순서로만 돌게 만들어야 합니다.
- **필요하기 전에 도구부터 배우기.** 단계 셋짜리 일에 그래프 도구를 붙이면 **일보다 도구가 커집니다.**
- **울타리 없이 루프 위로 올라가기.** 매 단계를 안 보기로 했으면 **못 하는 일을 미리 잠가야** 합니다. 순서가 반대면 5절의 사고가 그대로 재현됩니다.
- **갈림길을 AI 판단에 맡겨 두고 "왜 그랬는지" 묻기.** 갈림길이 그림에 없으면 매번 답이 다릅니다. 답이 같아야 하는 갈림길은 **그림에 그립니다.**

## ⚡ 이렇게 하세요

**1) 지금 도는 밤 작업의 단계를 세어 봅니다.**

```
① 실패한 기록을 찾는다
② 로그를 읽는다
③ 원인을 정리한다
④ 수정안을 만든다
⑤ PR을 연다
→ 다섯 단계. 갈림길은 아직 없음 → 프롬프트 한 장으로 충분하다
```

**2) 갈림길이 생기면 그때 종이에 그립니다.** 도구를 열기 전에.

```
        실패 발견
            │
      어떤 종류인가?
     ┌──────┼──────┐
   빌드    외부서비스   결제
     │       │        │
 수정안 PR  기록만   나를 깨운다
     │       │        │
     └──── 장애기록.md 에 3줄 ────┘
```

**3) 그림을 그대로 프롬프트에 넣습니다.** 도구 없이 그래프를 흉내 내는 가장 싼 방법입니다.

```
아래 순서를 그대로 따른다. 순서를 바꾸거나 건너뛰지 않는다.

1. 최근 24시간의 실패를 찾는다. 없으면 여기서 끝낸다.
2. 실패의 종류를 아래 셋 중 하나로 분류한다. 셋에 없으면 "기타"로 두고 3-C 로 간다.
   A) 빌드·테스트 문제   B) 외부 서비스 문제   C) 결제 관련
3. 분류에 따라 하나만 실행한다.
   3-A: 수정안을 만들어 PR 을 연다. 병합하지 않는다.
   3-B: 아무것도 고치지 않는다. 기록만 남긴다.
   3-C: 아무것도 하지 않는다. 텔레그램으로 나를 부르고 끝낸다.
4. 어느 경우든 마지막에 장애기록.md 에 3줄을 덧붙인다.
5. 실행한 단계 번호를 결과 맨 위에 그대로 적는다. (예: 1 → 2 → 3-B → 4)
```

**5번이 핵심입니다.** 어느 길로 갔는지 적게 하면, 틀렸을 때 **어디서 갈라졌는지** 바로 보입니다.

**4) 이 프롬프트로도 매번 답이 흔들리면** 그때 그래프 도구를 봅니다. 그전에는 보지 않습니다.
