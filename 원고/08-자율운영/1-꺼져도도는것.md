## 왜 이걸 하나

"내가 컴퓨터에 없어도 자동으로 점검되면 좋겠다."

이 장 전체가 그 한 문장에서 나왔습니다. 그런데 **여기서 갈립니다.**
자동으로 돌게 만들었다고 생각했는데 **내 컴퓨터가 꺼지는 순간 같이 멈추는 것**이 있고, 정말로 남의 컴퓨터에서 도는 것이 있습니다.

이걸 먼저 구분하지 않으면 뒤의 모든 절이 헛수고가 됩니다.
새벽 3시에 사이트가 죽었는데 점검도 같이 자고 있으면, 점검을 만든 의미가 없습니다.

## 세 층 — 모니터 · 컴퓨터 · 재생 중인 영상

가장 많이 헷갈리는 자리입니다. **터미널 창을 닫는 것과 컴퓨터를 끄는 것은 다릅니다.**

| 무엇 | 비유 | 닫으면 |
|---|---|---|
| **터미널 앱** | 모니터 | 눈앞에서 사라질 뿐 |
| **멀티플렉서 서버** | 컴퓨터 본체 | 뒤에서 계속 돈다 |
| **프로세스(내가 시킨 일)** | 재생 중인 영상 | 모니터를 꺼도 재생은 계속된다 |

모니터를 껐다고 영상이 멈추지 않습니다. 하지만 **본체 전원을 뽑으면** 멈춥니다.
그래서 질문은 "창을 닫아도 되나"가 아니라 **"이 일은 누구의 본체에서 도는가"**입니다.

### 왜 지금 이게 다시 문제가 됐나

예전에는 개발자 한 사람이 굴리는 프로그램이 **내가 타이핑하는 동안만** 돌았습니다.
지금은 지시 한 번에 AI가 10분에서 30분씩 혼자 돕니다. 그 사이에 나는 자거나 출근합니다.
그래서 셋이 필요해졌습니다 — **지속성**(내가 없어도 계속) · **병렬 시야**(여러 개를 한눈에) · **원격**(밖에서도 확인).

## 꺼져도 도나 — 다섯 가지 방식

| 방식 | 꺼져도 도나 | 최소 주기 | 한계 |
|---|---|---|---|
| **깃허브 예약 실행**(GitHub Actions) | ✅ | 5분 | 부하가 몰리면 밀린다. 저장소가 60일 조용하면 자동 중지 |
| **배포 서비스 예약**(무료 범위) | ✅ | **하루 1회** | 실시간 감시 불가. 하루치 정산·리포트용 |
| **Claude 예약 실행** | ✅ (클라우드) | 1시간 | **매번 기억이 없다.** 맥락을 프롬프트에 다 넣어야 한다 |
| **맥미니 + 터미널 멀티플렉서** | **터미널을 닫아도 ✅** | 자유 | **컴퓨터는 켜져 있어야 한다.** 덮었을 때는 절전 설정에 달림 `[확인 필요]` |
| 맥미니 · 그냥 터미널 | ❌ | 자유 | 창을 닫는 순간 프로세스가 죽는다 |

**결론 한 줄**

> **감시(5분)는 깃허브 예약, 판단·수정(1시간~1일)은 Claude 예약, 긴 작업은 멀티플렉서로 돌려놓고 잔다.**

셋을 다 쓰는 게 아니라 **일의 성격에 따라 자리를 나누는 것**입니다.
5분마다 "살아 있나"만 묻는 일에 AI를 부르면 낭비고, "왜 죽었나"를 판단하는 일을 5분마다 시키면 시끄럽습니다.

## 📘 말 풀이

**예약 실행(scheduled run / cron)**
"몇 분마다" 또는 "매일 몇 시에" 알아서 실행되게 걸어 두는 것. 내가 버튼을 누르지 않아도 시간이 되면 혼자 돕니다.

**터미널 멀티플렉서(terminal multiplexer)**
터미널 창 뒤에 **따로 세워 두는 작은 서버**. 창을 닫아도 그 안의 일은 계속 돌고, 나중에 다시 붙어서(attach) 들여다볼 수 있습니다. `tmux`가 대표적입니다.

**헬스체크(health check)**
"살아 있나"를 묻는 가장 단순한 점검. 내 사이트 주소를 열어 보고 정상 응답이 오는지만 봅니다.

## ⚠️ 자주 걸리는 함정

- **"내 맥미니는 항상 켜 두니까 괜찮다"** — 업데이트 재부팅·정전·절전이 있습니다. 감시하는 쪽이 감시당하는 쪽보다 잘 죽으면 안 됩니다.
- **노트북 뚜껑을 덮으면** 절전 설정에 따라 멈출 수 있습니다. 덮고도 도는지는 **직접 확인해야** 합니다 `[확인 필요]`.
- **저장소가 조용하면 예약이 꺼집니다.** 깃허브 예약은 저장소에 아무 변화가 없이 60일이 지나면 자동으로 멈춥니다. 다 만들어 두고 두 달 뒤에 "왜 안 오지" 하는 자리가 여기입니다.
- **5분이 5분이 아닙니다.** 무료 예약은 부하가 몰리면 밀립니다. "정확히 5분마다"에 기대는 설계는 하지 않습니다.
- **Claude 예약 실행은 어제 일을 기억하지 못합니다.** 사람에게 말하듯 "어제 그거"라고 쓰면 못 알아듣습니다.

## ⚡ 이렇게 하세요

**1) 5분마다 도는 감시를 깃허브에 올립니다.** 저장소에 아래 파일을 만듭니다.

```yaml
# .github/workflows/살아있나.yml
name: 살아있나
on:
  schedule:
    - cron: '*/5 * * * *'   # 5분마다
  workflow_dispatch:         # 버튼으로 지금 당장 돌려보기
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - name: 사이트 열어보기
        run: curl -sSf --max-time 10 https://내주소.example.com > /dev/null
```

**2) 내 컴퓨터를 완전히 끄고 확인합니다.** 이게 이 절의 핵심입니다.

```
깃허브 저장소 → Actions 탭 → 살아있나 → Run workflow 로 한 번 돌려 초록불 확인
→ 맥을 완전히 종료 → 20분 뒤 휴대폰으로 Actions 탭을 열어 새 실행 기록이 쌓였는지 본다
```

**3) 긴 작업은 멀티플렉서 안에서 시작합니다.** 창을 닫아도 살아 있게.

```bash
# 이름을 붙여 방 하나를 만든다
tmux new -s 밤작업

# 그 안에서 오래 걸리는 일을 시작한 뒤,
# Ctrl+b 를 누르고 손을 뗀 다음 d 를 누른다 (창에서 빠져나오기)

# 나중에 다시 들여다보기
tmux ls          # 살아 있는 방 목록
tmux attach -t 밤작업
```

**4) 터미널 앱을 완전히 종료했다가 다시 열고** `tmux ls`를 칩니다. 방이 그대로 있으면 성공입니다.

### 이렇게 해 봤습니다 — 2026-09-09

표의 마지막 두 줄(**멀티플렉서** vs **그냥 터미널**)을 실제로 재 봤습니다.

멀티플렉서 세션에 긴 작업을 걸고 **터미널을 완전히 끝낸 뒤** 새 터미널에서 다시 붙으니,
기록이 **3줄에서 11줄로 늘어 있었습니다.** 보는 사람이 없는 동안에도 돌고 있었습니다.

**표에서 «터미널을 닫아도 ✅»는 실제로 그렇습니다.** 다만 **컴퓨터가 켜져 있어야 한다**는 조건은 그대로입니다.
덮었을 때는 절전 설정에 달려 있어 `[확인 필요]`로 남깁니다 — 이건 각자 자기 기기에서 재 봐야 합니다.

## ✅ 됐는지 확인

- [ ] **터미널을 닫고도 살아 있는 것을 확인했나** — 문서를 읽은 게 아니라, 앱을 종료했다가 다시 열어 `tmux ls`에 방이 **보이는 것**을 눈으로 봤나
- [ ] **맥을 완전히 끈 상태에서** 깃허브 예약 실행이 새 기록을 남기는 것을 봤나
- [ ] 내 점검 다섯 개가 각각 **누구의 컴퓨터에서 도는지** 한 줄로 말할 수 있나
- [ ] 노트북을 덮었을 때 도는지 **직접 시험해 봤나** (도는지 안 도는지 둘 중 하나로 답할 수 있나)

하나라도 «아니오»면 다음 절로 넘어가지 않습니다. 여기가 갈림길입니다.
