되돌리기는 되돌아갈 지점이 있을 때만 됩니다. 그 지점을 만드는 게 커밋이고, 문제는 어떻게 나누느냐입니다.

## ① 나누는 기준을 잡는다

오늘 로그인 화면을 고치고, 색을 바꾸고, 오타를 잡은 뒤 한 번에 저장했다고 해 봅시다. 다음 날 색만 되돌리고 싶어도 방법이 없습니다. 로그인 수정과 오타 수정까지 같이 날아갑니다.

규칙은 한 줄 — **하나의 커밋은 하나의 이유로 묶입니다.**

| 나쁜 예 | 좋은 예 |
|---|---|
| 「오늘 작업」 (다섯 가지가 섞임) | 「로그인 화면 여백 정리」 |
| 「수정」 | 「가입 이메일 중복 검사 추가」 |
| 「이것저것」 | 「README 오타 수정」 |

나누는 질문은 하나 — *"이걸 나중에 통째로 무를 일이 생길까?"* 답이 갈리는 지점이 커밋의 경계입니다. 얼마나 자주 하느냐는 시간이 아니라 일의 단위이고, 특히 AI에게 크게 시키기 전에 커밋을 하나 찍어 두면 결과가 마음에 안 들 때 그 지점으로 통째로 되감으면 됩니다.

## ② 네 걸음으로 저장한다

Git의 저장은 두 단계입니다. 번거롭게 느껴지지만 이 구조 덕분에 「바꾼 것 중 일부만 저장」이 됩니다.

```bash
git status
```
> 지금 무엇이 바뀌었는지 보여 줍니다. 항상 여기서 시작합니다.

```bash
git add 파일이름
```
> 그 파일을 「이번에 저장할 목록」에 올립니다. 전부 올리려면 `git add .` 을 씁니다.

```bash
git commit -m "가입 이메일 중복 검사 추가"
```
> 목록에 올린 것을 이름 붙여 저장합니다. `-m` 뒤의 따옴표 안이 메시지입니다.

```bash
git push
```
> 저장한 것을 GitHub으로 올립니다.

**`commit`과 `push`는 다른 일입니다.** 커밋은 내 컴퓨터 안의 일이고 푸시를 해야 인터넷 창고로 갑니다. 이 차이가 5절 되돌리기에서 단계를 가르는 기준이 됩니다.

## ③ 메시지에 이유를 적는다

메시지를 나중의 나와 AI가 읽습니다. 그래서 한 일의 목록이 아니라 **이유**를 적습니다.

| ❌ 무엇을 했는지 나열 | ✅ 무엇을 왜 바꿨는지 |
|---|---|
| 「login.js, auth.js, db.js 수정」 | 「같은 이메일로 두 번 가입되던 문제 막음」 |
| 「함수 3개 추가」 | 「결제 실패했을 때 사용자에게 이유를 보여 주도록」 |
| 「스타일 변경」 | 「휴대폰에서 버튼이 잘려 크기를 키움」 |

왼쪽은 파일을 열어 보면 어차피 아는 것이고, 오른쪽은 파일을 열어도 알 수 없는 것입니다. 기록해야 할 건 후자입니다.

## ④ 메시지를 AI에게 맡긴다

메시지 쓰기가 귀찮아서 「수정」만 반복하게 됩니다. AI에게 맡기되, 요령은 하나 — **바뀐 것을 실제로 보여 주고 요약시킵니다.** 안 보여 주면 지어냅니다.

```bash
git diff --cached
```
> 지금 저장하려는 것이 정확히 무엇이 바뀌었는지 줄 단위로 보여 줍니다.

```
지금 저장할 변경사항을 `git diff --cached` 로 직접 읽어보고,
커밋 메시지를 한 줄로 지어줘. 조건 셋:

1. 파일 이름이나 함수 이름을 나열하지 말고, 「무엇을 왜 바꿨는지」를 써줘
2. 한글로, 50자 안쪽으로
3. 이 변경이 사실은 두 가지 이상 섞여 있으면,
   메시지를 짓지 말고 「커밋을 몇 개로 나눠야 하는지」를 먼저 알려줘

메시지만 보여주고, 커밋은 내가 확인한 다음에 해.
```

조건 3이 진짜입니다. 사람은 자기가 섞은 걸 못 알아보고, AI는 알아봅니다.

## ⚡ 따라 하기

파일 하나를 아무렇게나 고친 뒤 아래를 순서대로 치세요. 각 줄의 결과를 보고 다음으로 갑니다.

```bash
git status
```
> 무엇이 바뀌었는지 봅니다. 고친 파일 이름이 빨간 글씨로 보여야 합니다.

```bash
git add 파일이름
```
> 저장할 것을 장바구니에 담습니다. 한 가지씩만 담습니다.

```bash
git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"
```
> 3절의 확인. 아무것도 안 나와야 다음으로 갑니다.

```bash
git diff --cached
```
> 무엇이 바뀌는지 눈으로 봅니다. `+`와 `-`가 붙은 줄이 보입니다.

```bash
git commit -m "무엇을 왜 바꿨는지 한 줄"
```
> 이름 붙여 저장합니다. 파일 수와 바뀐 줄 수가 한 줄로 나옵니다.

```bash
git push
```
> GitHub으로 올립니다. GitHub 저장소 페이지를 새로고침하면 방금 메시지가 보여야 합니다.

그다음 커밋 규칙을 프로젝트에 박아 두세요. 이후로는 AI에게 「커밋해줘」라고만 해도 이 셋을 지킵니다.

```
이 프로젝트의 CLAUDE.md 에 커밋 규칙을 적어줘. 내용은 이 셋:

1. 한 커밋 = 한 가지. 성격이 다른 변경은 절대 한 커밋에 섞지 않는다
2. 커밋 메시지는 한글로, 「무엇을 왜 바꿨는지」를 쓴다. 파일·함수 나열 금지
3. 커밋 전에 반드시 아래를 실행하고, 한 줄이라도 나오면 멈추고 물어본다
   git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"
```

## ✅ 확인

- [ ] 커밋 뒤 `git log --oneline`을 쳤을 때 내가 쓴 메시지가 보이나
- [ ] 그 메시지가 「수정」이 아니라 「무엇을 왜」로 읽히나
- [ ] GitHub 저장소 웹페이지를 새로고침했을 때 방금 올린 것이 보이나
- [ ] AI에게 `git diff --cached`를 읽히고 메시지를 받아 본 적이 있나

## 📘 말 풀이

**커밋(commit)** — 지금 상태를 이름 붙여 저장하는 것. 커밋마다 긴 글자·숫자 줄(예: `a3f9c21…`)이 붙는데, 이게 그 지점의 주소입니다. 5절에서 이 주소를 씁니다.

**스테이지(staging area)** — `git add`가 담는 「이번에 저장할 것」 장바구니. 바꾼 파일 다섯 개 중 셋만 담아 저장할 수 있어서 「한 커밋 = 한 가지」가 가능합니다.

**diff** — 두 시점 사이에 정확히 어느 줄이 바뀌었는지 보여 주는 것. 더해진 줄 앞에 `+`, 지워진 줄 앞에 `-`가 붙습니다.

## ⚠️ 함정

**`git add .` 을 습관적으로 씁니다.** 폴더 안의 모든 걸 담아서 `.env`가 딸려 들어가는 사고가 여기서 납니다. 담은 뒤 3절의 확인 명령을 반드시 칩니다.

**커밋만 하고 푸시를 안 합니다.** 내 컴퓨터에만 있어서 컴퓨터가 고장 나면 그대로 사라집니다.

**하루 끝에 몰아서 한 번 커밋합니다.** 되돌릴 수 있는 단위가 「하루 통째로」가 됩니다.

**AI에게 diff를 안 보여 주고 메시지를 시킵니다.** 그럴듯한데 사실이 아닌 메시지가 나옵니다.

**커밋을 「완성했을 때만」 하는 것으로 오해합니다.** 커밋은 발표가 아니라 되돌아올 지점 만들기입니다. 어중간해도 돌아가면 찍어 둡니다.
