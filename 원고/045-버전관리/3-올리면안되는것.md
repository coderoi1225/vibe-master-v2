## 왜 이걸 하나

**이 장에서 가장 위험한 자리입니다.**

앞 절들에서 잘못하면 **안 됩니다**. 여기서 잘못하면 **일이 벌어집니다.**
남의 카드로 결제가 되거나, 남이 내 데이터베이스를 지우거나, 내 계정으로 돈이 나갑니다.

버전 관리의 성질 때문입니다. 저장소는 **지나온 모든 순간**을 보관합니다.
그러니까 **한 번 올린 것은 나중에 지워도 기록에는 남습니다.**

이 절을 건너뛰면 [[06-서버결제/_스테이지|Stage 6]]에서 결제 열쇠를 다루는 순간 사고가 납니다.

## 지워도 남는다 — 이게 핵심입니다

보통의 파일은 이렇게 생각합니다.

> 올렸다가 잘못됐네 → 지운다 → 없어진다

**저장소에서는 안 그렇습니다.**

> 올렸다 → 지운다 → **지웠다는 사실이 새로 기록될 뿐** → 올렸던 순간은 그대로 남아 있음

되감기 되는 영상이라 그렇습니다. 영상 중간의 한 장면을 도려내도, 그 앞뒤 영상은 그 장면을 지나왔습니다.
누구든 그 지점으로 되감으면 **비밀값이 그대로 보입니다.**

그래서 답이 정해져 있습니다.

> ## 실수로 올렸으면 **지우는 게 아니라 새로 발급받습니다.**

발급처(예: 결제 서비스, AI 서비스, 데이터베이스)에 들어가서 **그 열쇠를 폐기하고 새 열쇠를 만듭니다.**
새 열쇠를 만드는 순간 올라간 옛 열쇠는 **쓸모없는 글자 줄**이 됩니다. 그제야 안전해집니다.

**저장소를 비공개로 해 뒀어도 마찬가지입니다.** 협업자, 나중에 공개로 바꿀 가능성, 내 계정이 뚫릴 가능성이 전부 남아 있습니다. 공개 저장소는 더 급합니다 — 인터넷을 훑으며 새어 나온 열쇠를 자동으로 주워 가는 프로그램이 **실제로 돌아다닙니다.** 몇 분 단위입니다.

## 무엇이 비밀값인가

이름이 달라도 **성질이 같으면 전부 비밀값**입니다.

| 부르는 이름 | 무엇 |
|---|---|
| **API 키(API key)** | 바깥 서비스를 쓸 때 "나 맞습니다"를 증명하는 긴 글자 줄 |
| **토큰(token)** | 같은 역할. 기한이 있는 경우가 많습니다 |
| **비밀번호(password)** | 데이터베이스·서버 접속용 |
| **접속 문자열(connection string)** | 주소와 비밀번호가 한 줄에 붙어 있는 것 |
| **인증서 파일**(`.pem`, `.key`) | 서버 접속용 열쇠 파일 |
| **서비스 계정 파일**(`.json`) | 구글 등에서 내려받는 자격증명 파일 |

판단 기준 한 줄 — **"이걸 남이 보면 내 이름으로 뭔가 할 수 있나?"** 그렇다면 비밀값입니다.

## `.gitignore` — 애초에 안 올라가게 막는 문지기

`.gitignore`는 저장소 맨 위에 두는 **평범한 텍스트 파일**입니다.
여기 적힌 이름의 파일은 Git이 아예 못 본 척합니다. 실수할 기회 자체가 사라집니다.

저장소 맨 위 폴더에 `.gitignore` 파일을 만들고 아래를 넣습니다.

```
# 비밀값 — 절대 올리지 않는다
.env
.env.*
*.key
*.pem
secrets.json
credentials.json

# 프로그램이 자동으로 만드는 것 — 올릴 이유가 없다
node_modules/
.next/
dist/
build/
__pycache__/
*.log

# 맥이 몰래 만드는 것
.DS_Store
```

**줄마다 무슨 뜻인지**

| 적는 법 | 뜻 |
|---|---|
| `.env` | 정확히 이 이름의 파일 |
| `.env.*` | `.env.`로 시작하는 모든 파일 (`.env.local` 등) |
| `*.key` | 확장자가 `.key`인 모든 파일 |
| `node_modules/` | 이 이름의 폴더 통째로 |
| `# 로 시작하는 줄` | 사람이 읽는 메모. Git은 무시합니다 |

**`.env` 파일이란** — 비밀값을 코드 밖으로 빼서 따로 모아 두는 파일입니다. 코드에는 "이 이름의 값을 가져다 써"라고만 적고, 실제 값은 `.env`에 둡니다. **코드는 올리고 `.env`는 안 올리는** 구조가 여기서 나옵니다.

## ⚠️ 자주 걸리는 함정

- **`.gitignore`에 적었는데도 계속 올라갑니다.** `.gitignore`는 **아직 한 번도 저장한 적 없는 파일**에만 듣습니다. 이미 한 번 커밋된 파일은 계속 따라갑니다. `git rm --cached .env`로 추적을 끊어 줘야 합니다(아래 ⚡에 있습니다).
- **`.env.example`까지 막아 버립니다.** `.env.example`은 **값이 비어 있는 견본**이라 올려야 합니다. 나중에 다른 컴퓨터에서 무엇을 채워야 하는지 알려 주는 지도입니다. `.env.*`가 이것까지 막으니 `!.env.example` 한 줄을 더해 예외로 둡니다.
- **AI 대화창에 열쇠를 그대로 붙여넣습니다.** 파일에 안 올려도 **대화 기록에 남습니다.** AI에게는 "`.env`의 `STRIPE_KEY` 값을 읽어서 써"라고 시킵니다. 값 자체를 채팅에 쓰지 않습니다.
- **스크린샷에 열쇠가 찍힙니다.** 터미널 화면이나 설정 화면을 캡처해 올릴 때 자주 샙니다.
- **"비공개니까 괜찮다"고 생각합니다.** 비공개는 유예이지 안전이 아닙니다. 규칙은 공개·비공개 상관없이 같습니다.
- **AI가 알아서 걸러 줄 거라 믿습니다.** AI는 시키면 커밋합니다. **`.env`를 커밋 목록에 넣어도 대개 그냥 넣습니다.** 확인은 사람 몫입니다.

## ⚡ 이렇게 하세요

### 1. `.gitignore`부터 만듭니다 — 첫 커밋보다 먼저

```bash
cd ~/projects/내폴더이름
```
> 작업 폴더로 이동합니다.

AI 도구 대화창에 붙여넣습니다.

```
이 폴더 맨 위에 .gitignore 파일을 만들어줘.
.env, .env.*, *.key, *.pem, secrets.json, credentials.json,
node_modules/, dist/, build/, __pycache__/, *.log, .DS_Store 를 넣고,
.env.example 은 예외로 올라가게 해줘.
만들고 나서 파일 내용을 그대로 보여줘.
```

### 2. **커밋 전에 확인하는 명령 한 줄** — 이걸 습관으로 만듭니다

저장하기 직전에 **딱 한 줄** 칩니다.

```bash
git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"
```
> 지금 저장하려고 올려 둔 파일 이름 중에 `env`·`token`·`secret`·`credential`·`key`·`pem`이 들어간 게 있는지 거릅니다.

**읽는 법이 거꾸로라 헷갈립니다. 외워 두세요.**

| 결과 | 뜻 |
|---|---|
| **아무것도 안 나옴** | ✅ 안전. 그대로 커밋합니다 |
| **파일 이름이 나옴** | 🚨 **멈춥니다.** 그 파일을 빼고 `.gitignore`에 넣습니다 |

파일 이름이 나왔을 때 빼는 법.

```bash
git restore --staged .env
```
> 그 파일을 「저장할 목록」에서 뺍니다. 파일 자체는 그대로 있습니다.

### 3. 이미 한 번 올라간 파일의 추적을 끊습니다

```bash
git rm --cached .env
```
> `.env`를 저장소 추적 대상에서만 뺍니다. **내 컴퓨터의 파일은 지워지지 않습니다.** (`--cached`가 그 뜻입니다)

이 뒤에 커밋하면 앞으로는 안 따라옵니다. **단, 이미 올라간 과거 기록에는 남아 있습니다 — 위에 쓴 대로 열쇠를 새로 발급받으세요.**

### 4. 이 확인을 AI에게 맡깁니다 — 매번 손으로 치기 싫으면

```
앞으로 이 프로젝트에서 커밋하기 전에 항상 아래를 먼저 실행하고,
결과가 한 줄이라도 나오면 커밋을 멈추고 나에게 물어봐.

git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"

이 규칙을 이 프로젝트의 CLAUDE.md 에 적어줘.
```

이렇게 해 두면 **[[03-컨텍스트하네스/_스테이지|Stage 3]]에서 만든 규칙 파일이 문지기 역할**을 합니다.

### 5. 이미 새어 나갔다면 — 순서대로

1. **발급처에 들어가 그 열쇠를 폐기하고 새로 만듭니다.** (가장 먼저)
2. 새 값을 `.env`에 넣습니다.
3. `.gitignore`에 넣고 `git rm --cached`로 추적을 끊습니다.
4. 그 열쇠로 그동안 무슨 일이 있었는지 발급처의 사용 기록을 확인합니다.

**기록에서 지우려고 하지 마세요.** 과거를 뜯어고치는 명령이 있긴 하지만, 초보자가 쓰면 저장소를 통째로 망가뜨리기 쉽고 **이미 남이 복사해 갔으면 소용도 없습니다.** 새로 발급받는 게 확실하고 빠릅니다.

## 📘 말 풀이

**비밀값(secret)**
남이 알면 내 이름으로 무언가 할 수 있게 되는 값. API 키·토큰·비밀번호·인증서 파일이 전부 여기 들어갑니다. 이름이 뭐든 성질이 같으면 같게 다룹니다.

**`.gitignore`**
저장소 맨 위에 두는 텍스트 파일. 여기 적힌 이름의 파일을 Git이 못 본 척합니다. **이미 저장된 적 있는 파일에는 듣지 않는다**는 게 가장 자주 걸리는 성질입니다.

**추적(tracked) / 추적 안 함(untracked)**
Git이 지켜보고 있는 파일이 **추적 중**, 폴더 안에 있어도 Git이 신경 쓰지 않는 파일이 **추적 안 함**입니다. `.gitignore`는 추적 안 하는 파일을 계속 그 상태로 두는 장치입니다.

## ✅ 됐는지 확인

- [ ] 저장소 맨 위에 **`.gitignore` 파일이 있나**
- [ ] 그 안에 **`.env`가 들어 있나**
- [ ] `git status`를 쳤을 때 목록에 **`.env`가 안 보이나** (보이면 아직 안 막힌 것)
- [ ] **커밋 전에 비밀값을 확인하는 습관이 생겼나** — 위의 한 줄 명령을 실제로 한 번 이상 쳐 봤나
- [ ] 그 명령의 결과를 **거꾸로 읽는 법**을 아나 (아무것도 안 나와야 안전)
- [ ] 실수로 올렸을 때 **지우는 게 아니라 새로 발급받는다**는 걸 아나
