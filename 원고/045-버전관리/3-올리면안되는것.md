이 장에서 가장 위험한 자리입니다. 앞 절들에서 잘못하면 «안 되는» 정도지만, 여기서 잘못하면 남의 카드로 결제가 되거나 내 계정으로 돈이 나갑니다.

## ① 지워도 남는 이유를 본다

보통의 파일은 «올렸다가 잘못됐네 → 지운다 → 없어진다»입니다. 저장소에서는 다릅니다. 지우면 지웠다는 사실이 새로 기록될 뿐, 올렸던 순간은 그대로 남습니다.

되감기 되는 영상이라 그렇습니다. 중간의 한 장면을 도려내도 누구든 그 지점으로 되감으면 비밀값이 그대로 보입니다. 그래서 답이 정해져 있습니다.

> 실수로 올렸으면 **지우는 게 아니라 새로 발급받습니다.**

발급처(결제 서비스, AI 서비스, 데이터베이스)에 들어가 그 열쇠를 폐기하고 새 열쇠를 만드세요. 그 순간 올라간 옛 열쇠는 쓸모없는 글자 줄이 됩니다. 비공개 저장소여도 마찬가지이고, 공개 저장소는 새어 나온 열쇠를 자동으로 주워 가는 프로그램이 실제로 돌아다녀서 더 급합니다.

## ② 무엇이 비밀값인지 가른다

이름이 달라도 성질이 같으면 전부 비밀값입니다.

| 부르는 이름 | 무엇 |
|---|---|
| API 키(API key) | 바깥 서비스를 쓸 때 "나 맞습니다"를 증명하는 긴 글자 줄 |
| 토큰(token) | 같은 역할. 기한이 있는 경우가 많습니다 |
| 비밀번호(password) | 데이터베이스·서버 접속용 |
| 접속 문자열(connection string) | 주소와 비밀번호가 한 줄에 붙어 있는 것 |
| 인증서 파일(`.pem`, `.key`) | 서버 접속용 열쇠 파일 |
| 서비스 계정 파일(`.json`) | 구글 등에서 내려받는 자격증명 파일 |

판단 기준 한 줄 — **"이걸 남이 보면 내 이름으로 뭔가 할 수 있나?"** 그렇다면 비밀값입니다.

## ③ .gitignore를 만든다

`.gitignore`는 저장소 맨 위에 두는 평범한 텍스트 파일입니다. 여기 적힌 이름의 파일은 Git이 아예 못 본 척하니 실수할 기회 자체가 사라집니다.

```
# 비밀값 — 절대 올리지 않는다
.env
.env.*
!.env.example
*.key
*.pem
secrets.json
credentials.json

# 프로그램이 자동으로 만드는 것 — 올릴 이유가 없다
node_modules/
.next/
dist/
build/
__pycache__/
*.log

# 맥이 몰래 만드는 것
.DS_Store
```

| 적는 법 | 뜻 |
|---|---|
| `.env` | 정확히 이 이름의 파일 |
| `.env.*` | `.env.`로 시작하는 모든 파일 |
| `!.env.example` | 예외. 값이 비어 있는 견본이라 올려야 합니다 |
| `*.key` | 확장자가 `.key`인 모든 파일 |
| `node_modules/` | 이 이름의 폴더 통째로 |
| `#`로 시작하는 줄 | 사람이 읽는 메모 |

`.env`는 비밀값을 코드 밖으로 빼서 모아 두는 파일입니다. 코드에는 "이 이름의 값을 가져다 써"라고만 적고 실제 값은 `.env`에 둡니다. **코드는 올리고 `.env`는 안 올리는** 구조가 여기서 나옵니다.

## ④ 커밋 전 확인 한 줄을 익힌다

저장하기 직전에 딱 한 줄 칩니다.

```bash
git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"
```
> 지금 저장하려고 올려 둔 파일 이름 중에 `env`·`token`·`secret`·`credential`·`key`·`pem`이 들어간 게 있는지 거릅니다.

읽는 법이 거꾸로라 헷갈립니다.

| 결과 | 뜻 |
|---|---|
| 아무것도 안 나옴 | 안전. 그대로 커밋합니다 |
| 파일 이름이 나옴 | **멈춥니다.** 그 파일을 빼고 `.gitignore`에 넣습니다 |

```bash
git restore --staged .env
```
> 그 파일을 「저장할 목록」에서 뺍니다. 파일 자체는 그대로 있습니다.

## ⑤ 새어 나갔을 때 순서를 본다

1. 발급처에 들어가 그 열쇠를 폐기하고 새로 만듭니다. 가장 먼저입니다.
2. 새 값을 `.env`에 넣습니다.
3. `.gitignore`에 넣고 아래 명령으로 추적을 끊습니다.
4. 그 열쇠로 그동안 무슨 일이 있었는지 발급처의 사용 기록을 확인합니다.

```bash
git rm --cached .env
```
> `.env`를 저장소 추적 대상에서만 뺍니다. 내 컴퓨터의 파일은 지워지지 않습니다.

**기록에서 지우려고 하지 마세요.** 과거를 뜯어고치는 명령이 있긴 하지만 초보자가 쓰면 저장소를 통째로 망가뜨리기 쉽고, 이미 남이 복사해 갔으면 소용도 없습니다.

## ⚡ 따라 하기

1. 작업 폴더로 가서 AI에게 `.gitignore`를 만들게 하세요. 첫 커밋보다 먼저여야 실수할 기회가 생기지 않습니다. 파일 내용이 그대로 화면에 보이면 된 것입니다.

```bash
cd ~/projects/내폴더이름
```
> 작업 폴더로 이동합니다.

```
이 폴더 맨 위에 .gitignore 파일을 만들어줘.
.env, .env.*, *.key, *.pem, secrets.json, credentials.json,
node_modules/, dist/, build/, __pycache__/, *.log, .DS_Store 를 넣고,

만들고 나서 파일 내용을 그대로 보여줘.
```

2. `git status`를 쳐서 목록에 `.env`가 안 보이는지 확인하세요. 보이면 아직 안 막힌 것입니다.

3. ④의 확인 명령을 지금 한 번 쳐 보세요. 습관은 처음 한 번을 손으로 쳐야 생깁니다. 아무것도 안 나와야 정상입니다.

4. 이 확인을 AI에게 맡기세요. 매번 손으로 치면 언젠가 빠뜨립니다. 규칙 파일에 한 줄이 추가되면 [[03-컨텍스트하네스/_스테이지|Stage 3]]에서 만든 규칙 파일이 **문지기 역할**을 하게 됩니다.

```
앞으로 이 프로젝트에서 커밋하기 전에 항상 아래를 먼저 실행하고,
결과가 한 줄이라도 나오면 커밋을 멈추고 나에게 물어봐.

git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"

이 규칙을 이 프로젝트의 CLAUDE.md 에 적어줘.
```

## 📘 말 풀이

**비밀값(secret)** — 남이 알면 내 이름으로 무언가 할 수 있게 되는 값. API 키·토큰·비밀번호·인증서 파일이 전부 여기 들어갑니다.

**`.gitignore`** — 저장소 맨 위에 두는 텍스트 파일. 여기 적힌 이름의 파일을 Git이 못 본 척합니다. 이미 저장된 적 있는 파일에는 듣지 않습니다.

**추적(tracked) / 추적 안 함(untracked)** — Git이 지켜보고 있는 파일이 추적 중, 폴더 안에 있어도 신경 쓰지 않는 파일이 추적 안 함입니다.

## ⚠️ 함정

**`.gitignore`에 적었는데도 계속 올라갑니다.** `.gitignore`는 아직 한 번도 저장한 적 없는 파일에만 듣습니다. 이미 커밋된 파일은 `git rm --cached`로 추적을 끊어야 합니다.

**AI 대화창에 열쇠를 그대로 붙여넣습니다.** 파일에 안 올려도 대화 기록에 남습니다. AI에게는 "`.env`의 `STRIPE_KEY` 값을 읽어서 써"라고 시킵니다.

**스크린샷에 열쇠가 찍힙니다.** 터미널 화면이나 설정 화면을 캡처해 올릴 때 자주 샙니다.

**AI가 알아서 걸러 줄 거라 믿습니다.** AI는 `.env`를 커밋 목록에 넣어도 대개 그냥 넣습니다. 확인은 사람 몫입니다.
