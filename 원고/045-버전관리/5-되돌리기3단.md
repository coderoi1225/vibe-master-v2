이 장 전체가 이 절을 위해 있습니다. 앞의 네 절은 전부 망했을 때 되돌리기 위한 준비였습니다.

## ① 어느 단계인지 가른다

되돌리는 법은 하나가 아닙니다. 인터넷에서 아무 명령이나 찾아 치다가 멀쩡한 것까지 날리는 자리가 여기입니다. 기준은 딱 하나 — **얼마나 멀리 갔느냐**입니다.

| # | 상황 | 무엇을 하나 | 명령 |
|---|---|---|---|
| ② | 아직 저장(커밋) 안 함 | 바뀐 것을 버린다 | `git restore` |
| ③ | 저장은 했는데 안 올렸음 | 내 컴퓨터에서만 되감는다 | `git reset` |
| ④ | 이미 올렸음 | 역사를 지우지 말고 되돌린다 | `git revert` |
| ⑤ | 날린 것 같을 때 | 먼저 여기부터 본다 | `git reflog` |

어느 단계인지 모르겠으면 `git status`를 치세요. 지금 어디쯤인지 알려 줍니다.

## ② 커밋 안 한 것을 버린다

AI에게 시켰는데 결과가 엉망이고 아직 커밋은 안 한 상태. 가장 흔하고 가장 안전한 경우입니다.

```bash
git restore 파일이름
```
> 그 파일을 마지막 커밋 상태로 되돌립니다. 바꾼 내용은 사라집니다. 전부 되돌리려면 `git restore .` 을 씁니다.

```bash
git restore --staged 파일이름
```
> `git add`로 장바구니에 이미 담았다면 먼저 이걸로 빼고, 그다음 위 명령으로 내용을 되돌립니다.

> **⚠️ 이건 진짜로 사라집니다.** 커밋 안 한 변경은 Git이 기록한 적이 없어서 ⑤의 `reflog`로도 못 찾습니다. 버리기 전에 한 번 더 봅니다.

버리기 아까우면 `restore` 대신 서랍에 넣어 두세요. 초보자에게는 이쪽이 더 안전합니다.

```bash
git stash
```
> 지금 바꾼 것을 서랍에 넣어 두고 깨끗한 상태로 되돌립니다. 다시 꺼내려면 `git stash pop`.

## ③ 안 올린 커밋을 되감는다

커밋까지 했는데 아직 `git push`는 안 한 상태. 내 컴퓨터 밖으로 안 나갔으니 마음대로 되감아도 됩니다.

```bash
git log --oneline
```
> 최근 커밋 목록을 한 줄씩 보여 줍니다. 되감기 전에 항상 여기서 확인합니다.

```bash
git reset --soft HEAD~1
```
> **가장 안전한 되감기.** 마지막 커밋 하나를 취소하되 바꾼 내용은 그대로 둡니다. `HEAD~1`은 「지금에서 한 칸 뒤」입니다.

```bash
git reset --hard HEAD~1
```
> 바꾼 내용까지 통째로 버립니다. 진짜로 그 시점으로 되돌아갑니다.

> **⚠️ `--hard`는 조심합니다.** 되돌린 뒤에 「그건 살릴걸」 해도 파일에 안 남습니다. 커밋된 것은 ⑤의 `reflog`로 대개 찾지만, 커밋 안 한 변경은 진짜로 사라집니다. 먼저 `--soft`를 쓰고, 그걸로 안 되면 그때 `--hard`를 생각하세요.

## ④ 올린 것을 되돌린다

`git push`까지 해서 GitHub에 올라가 있는 상태. 여기서 규칙이 바뀝니다.

> 이미 올린 것은 **지우지 않습니다. 덮어씁니다.**

남들이 이미 받아 갔을 수 있기 때문입니다. 자동 검사 도구도, 배포 서버도 그 기록을 이미 봤습니다. 그래서 「없던 일로」가 아니라 「그 반대를 하는 새 커밋을 하나 더 얹습니다」.

```bash
git revert a3f9c21
```
> 그 커밋이 한 일을 정확히 반대로 하는 새 커밋을 만듭니다. 주소는 `git log --oneline`에서 앞 일곱 글자를 찾습니다. 만든 뒤 `git push`로 올립니다.

결과는 이렇게 남습니다. 지저분해 보이지만 이게 맞습니다.

```
a3f9c21  결제 화면 새로 만듦        ← 남아 있음
b7d1e88  결제 화면 새로 만든 것 되돌림  ← 새로 얹힘
```

> ### ⚠️ 절대 하지 말 것 — 강제로 밀어내기
>
> 인터넷에서 `git push --force`를 봅니다. **초보자는 쓰지 마세요.** 「내 컴퓨터 상태로 인터넷 창고를 통째로 덮어써라」는 뜻이라 남이 올려 둔 작업이 소리 없이 사라지고, 되돌릴 방법이 없는 경우도 있습니다. 이미 올린 것을 되돌릴 때는 `revert` 하나면 됩니다. 과거 커밋을 합치거나 지우는 「역사를 다시 쓰는」 명령도 안 올린 ③단계에서만 씁니다.

## ⑤ 날린 것을 reflog로 찾는다

포기하기 전에 여기부터 봅니다. 대부분 여기서 찾습니다. Git은 내가 지운 것도 한동안 몰래 들고 있고, 「지금까지 내 저장소가 지나온 자리」 목록이 `reflog`입니다. 보관 기간은 대략 30일입니다.

```bash
git reflog
```
> 내 저장소가 지나온 모든 자리를 최근 순으로 보여 줍니다.

```
a3f9c21 HEAD@{0}: reset: moving to HEAD~1
b7d1e88 HEAD@{1}: commit: 결제 화면 새로 만듦     ← 날린 줄 알았던 그것
c2e4f77 HEAD@{2}: commit: 로그인 여백 정리
```

맨 왼쪽이 그 시점의 주소, 오른쪽이 그때 무슨 일을 했는지입니다. 날리기 직전 줄을 찾았으면 **바로 되돌리지 말고 옆에 가지를 하나 내서 확인합니다.** 잘못 짚었을 때 또 되돌려야 하기 때문이고, 가지를 내는 건 아무것도 망가뜨리지 않습니다.

```bash
git switch -c 복구 b7d1e88
```
> 그 시점의 상태로 새 가지를 만들어 그리로 옮겨 갑니다. 지금 상태는 그대로 남습니다.

AI에게 맡길 때는 마지막 줄이 중요합니다. 「건드리지 마」를 빼면 AI가 알아서 되돌려 버릴 수 있습니다.

```
방금 git reset을 잘못 써서 커밋 하나를 날린 것 같아.
git reflog 를 읽어서 날리기 직전 상태가 어느 줄인지 찾아줘.
찾으면 그 시점으로 새 브랜치를 만드는 명령만 알려줘.
지금 상태는 절대 건드리지 마.
```

## ⚡ 따라 하기

읽기만 하면 정작 필요할 때 손이 안 움직입니다. 연습용 폴더를 새로 만들어 세 번 망가뜨리세요. 진짜 프로젝트에서 하지 마세요.

1. 연습장을 만드세요. 커밋 하나가 있어야 되돌아갈 지점이 생깁니다. 마지막 줄에서 「1 file changed」가 보이면 준비된 것입니다.

```bash
mkdir ~/git-연습 && cd ~/git-연습
git init
echo "첫 줄입니다" > 연습.txt
git add 연습.txt
git commit -m "첫 커밋"
```
> 폴더를 만들고 → 저장소로 만들고 → 파일 하나 만들고 → 담아서 → 저장합니다.

2. 파일을 망가뜨린 뒤 `restore`로 되돌리세요. 커밋 안 한 것을 버리는 감각을 익히는 단계입니다. 두 번째 `cat`에서 「첫 줄입니다」만 남아 있어야 합니다.

```bash
echo "엉망으로 고침" >> 연습.txt
cat 연습.txt
git restore 연습.txt
cat 연습.txt
```
> 망가뜨리고 → 눈으로 보고 → 되돌리고 → 원래대로인지 확인합니다.

3. 이번엔 커밋까지 한 뒤 `reset`으로 되감으세요. 안 올린 커밋은 없던 일로 만들 수 있다는 걸 손으로 확인하는 단계입니다. 두 번째 `git log`에서 목록이 한 줄로 줄어야 합니다.

```bash
echo "잘못된 두 번째 줄" >> 연습.txt
git add . && git commit -m "잘못된 커밋"
git log --oneline
git reset --hard HEAD~1
git log --oneline
```
> 망가뜨려서 커밋하고 → 두 줄 확인 → 한 칸 되감고 → 한 줄로 줄었는지 확인합니다.

4. 방금 날린 커밋을 `reflog`로 다시 살리세요. **이 단계가 가장 중요합니다** — 진짜로 날렸을 때 손이 여기로 갑니다. `cat`에서 「잘못된 두 번째 줄」이 돌아와 있어야 합니다.

```bash
git reflog
git switch -c 복구연습 여기에복사한주소
cat 연습.txt
git switch -
```
> 지나온 자리에서 「잘못된 커밋」 줄의 주소를 복사하고 → 그 시점으로 새 가지를 내고 → 파일을 확인하고 → 원래 가지로 돌아옵니다.

5. (선택) 2절에서 만든 진짜 저장소에서 사소한 변경 하나를 커밋하고 `push`한 뒤 `revert`해 보세요. 올린 것은 지우지 않고 덮어쓴다는 걸 눈으로 보는 단계입니다. GitHub 웹페이지에서 커밋이 원래 것과 되돌린 것 두 개 다 보여야 합니다.

```bash
git log --oneline
git revert 방금커밋주소
git push
```
> 커밋 주소를 찾고 → 반대로 하는 커밋을 만들고 → 올립니다.

6. 연습장을 치우세요. **`rm -rf`는 되돌릴 수 없는 명령입니다.** 경로가 `~/git-연습`이 맞는지 눈으로 한 번 더 확인하고 치세요.

```bash
rm -rf ~/git-연습
```
> 연습 폴더를 지웁니다.

### 이렇게 해 봤습니다 — 2026-09-09 · 네 가지를 실제로 돌려 봤습니다

연습용 저장소를 하나 만들어 일부러 망가뜨리고 네 가지 방법으로 되살려 봤습니다.

| 상황 | 한 일 | 결과 |
|---|---|---|
| 아직 저장 안 함 | 파일을 엉뚱한 내용으로 덮어씀 → `restore` | 원래 내용으로 돌아옴 |
| 저장했는데 안 올림 | 잘못된 커밋을 만듦(3개) → `reset` | 커밋 2개로 줄고 파일도 돌아옴 |
| 이미 올림 | `revert` | 커밋이 3개 → 4개로 «늘었습니다». 지운 게 아니라 «되돌리는 커밋»이 하나 더 쌓입니다 |
| 날린 것 같을 때 | 두 개를 날린 뒤 `reflog` | 날린 커밋이 목록에 그대로 남아 있었고, 그 번호로 되살렸습니다 |

세 번째 줄이 가장 헷갈리는 자리입니다. 되돌렸는데 커밋 수가 늘어나서 "안 된 건가?" 싶지만, 그게 맞게 된 것입니다. 남들이 받아 간 역사를 지우는 대신 「이걸 취소합니다」라는 기록을 새로 남기는 것입니다.

네 번째가 이 절에서 제일 중요합니다. 날렸다고 생각한 것이 실제로는 남아 있었습니다. **당황해서 다시 만들기 전에 `reflog`부터 봅니다.**

## 📘 말 풀이

**`reset` — 되감기** — 「없던 일로」 만듭니다. 커밋 자체가 사라집니다. 아직 안 올린 것에만 씁니다. `--soft`(커밋만 취소, 내용 유지)와 `--hard`(내용까지 버림)를 구분해서 기억하세요.

**`revert` — 반대로 하기** — 「반대되는 일을 새로 합니다.」 원래 커밋은 남고 그것을 무르는 커밋이 하나 더 얹힙니다. 이미 올린 것에는 이것만 씁니다.

**`reflog` — 지나온 자리 기록** — 내 저장소가 거쳐 간 모든 지점의 목록. 커밋 목록(`log`)과 달리 되감아서 사라진 것까지 남아 있습니다. 약 30일 보관.

## ⚠️ 함정

**인터넷에서 찾은 명령을 상황 확인 없이 칩니다.** 대부분의 사고가 여기서 납니다. `git status`와 `git log --oneline`을 먼저 치고 지금이 ②③④ 중 어디인지 정한 다음 명령을 고릅니다.

**이미 올린 것에 `reset`을 씁니다.** 내 컴퓨터와 GitHub이 어긋나 `push`가 거부되고, 당황해서 `--force`를 치면 진짜 사고가 됩니다. 올린 것은 `revert`입니다.

**날렸다고 판단하고 처음부터 다시 만듭니다.** `reflog`를 안 봐서 그렇습니다. 30일 안이면 대개 살아 있습니다.

**커밋 안 한 변경도 `reflog`로 찾을 수 있다고 믿습니다.** 못 찾습니다. Git이 기록한 적이 없기 때문입니다. 커밋을 자주 하는 이유가 이것입니다.

**되돌린 다음 `push`를 안 합니다.** 내 컴퓨터만 되돌아가고 GitHub은 그대로입니다.
