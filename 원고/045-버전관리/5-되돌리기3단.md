## 왜 이걸 하나

**이 장 전체가 이 절을 위해 있습니다.**

앞의 네 절은 전부 준비였습니다. 저장소를 만들고, 비밀값을 막고, 커밋을 나눈 이유는
**망했을 때 되돌리기 위해서**입니다.

그런데 되돌리는 법이 **하나가 아닙니다.** 여기가 초보자가 가장 헷갈리는 자리입니다.
인터넷에서 아무 명령이나 찾아 치다가 **멀쩡한 것까지 날립니다.**

기준은 딱 하나 — **얼마나 멀리 갔느냐**입니다.

## 되돌리기 3단 + 1

| # | 상황 | 무엇을 하나 | 명령 |
|---|---|---|---|
| **①** | **아직 저장(커밋) 안 함** | 바뀐 것을 **버린다** | `git restore` |
| **②** | **저장은 했는데 안 올렸음** | 내 컴퓨터에서만 **되감는다** | `git reset` |
| **③** | **이미 올렸음** | 역사를 지우지 말고 **되돌린다** | `git revert` |
| **④** | **날린 것 같을 때** | **먼저 여기부터 본다** | `git reflog` |

**어느 단계인지 모르겠으면 `git status`를 칩니다.** 지금 어디쯤인지 알려 줍니다.

## ① 아직 저장(커밋) 안 함 → 바뀐 것 버리기

**언제** — AI에게 시켰는데 결과가 엉망입니다. 아직 커밋은 안 했습니다.
가장 흔하고, 가장 안전한 경우입니다. 커밋된 상태로 **되돌아가기만** 하면 됩니다.

```bash
git restore 파일이름
```
> 그 파일을 마지막 커밋 상태로 되돌립니다. 바꾼 내용은 사라집니다.

```bash
git restore .
```
> 바꾼 것 **전부**를 마지막 커밋 상태로 되돌립니다.

`git add`로 장바구니에 이미 담았다면 두 걸음입니다.

```bash
git restore --staged 파일이름
git restore 파일이름
```
> 먼저 장바구니에서 빼고, 그다음 내용을 되돌립니다.

> **⚠️ 이건 진짜로 사라집니다.** 커밋 안 한 변경은 Git이 기록한 적이 없어서 ④의 `reflog`로도 못 찾습니다. **버리기 전에 한 번 더 봅니다.**

**버리기 아까울 때 — 잠깐 치워 두기**

```bash
git stash
```
> 지금 바꾼 것을 서랍에 넣어 두고 깨끗한 상태로 되돌립니다. 사라지지 않습니다.

```bash
git stash pop
```
> 서랍에 넣어 둔 것을 다시 꺼냅니다.

「이게 맞나 싶은데 버리긴 아깝다」 싶으면 `restore` 대신 `stash`를 씁니다. **초보자에게는 이쪽이 더 안전합니다.**

## ② 저장은 했는데 안 올렸음 → 로컬에서 되감기

**언제** — 커밋까지 했는데 아직 `git push`는 안 했습니다.
아직 **내 컴퓨터 밖으로 안 나갔으니** 마음대로 되감아도 됩니다. 아무도 못 봤습니다.

```bash
git log --oneline
```
> 최근 커밋 목록을 한 줄씩 보여 줍니다. **되감기 전에 항상 여기서 확인합니다.**

```bash
git reset --soft HEAD~1
```
> **가장 안전한 되감기.** 마지막 커밋 하나를 취소하되, **바꾼 내용은 그대로 둡니다.** 메시지를 잘못 썼거나 커밋을 나누고 싶을 때 씁니다. (`HEAD~1`은 「지금에서 한 칸 뒤」라는 뜻입니다)

```bash
git reset --mixed HEAD~1
```
> 커밋을 취소하고 장바구니에서도 뺍니다. 내용은 파일에 남아 있습니다.

```bash
git reset --hard HEAD~1
```
> **바꾼 내용까지 통째로 버립니다.** 진짜로 그 시점으로 되돌아갑니다.

> **⚠️ `--hard`는 조심합니다.** 되돌린 뒤에 「아 그건 살릴걸」 해도 파일에 안 남습니다. 다만 **커밋된 것은 ④의 `reflog`로 대개 찾습니다.** 커밋 안 한 변경만 진짜로 사라집니다.
> **초보자에게 권하는 순서 — 먼저 `--soft`를 씁니다.** 그걸로 안 되면 그때 `--hard`를 생각합니다.

## ③ 이미 올렸음 → 역사를 지우지 말고 되돌리기

**언제** — `git push`까지 했습니다. **GitHub에 올라가 있습니다.**

여기서 규칙이 바뀝니다.

> ## 이미 올린 것은 **지우지 않습니다. 덮어씁니다.**

이유는 간단합니다. **남들이 이미 받아 갔을 수 있습니다.**
협업자도 그렇고, 자동 검사 도구도, 배포 서버도 그 기록을 이미 봤습니다.
올라간 역사를 뜯어고치면 그걸 받아 간 모든 곳이 **어긋납니다.**

그래서 「없던 일로」가 아니라 **「그 반대를 하는 새 커밋을 하나 더 얹습니다.」**

```bash
git log --oneline
```
> 되돌릴 커밋의 주소(앞 일곱 글자면 충분합니다)를 찾습니다.

```bash
git revert a3f9c21
```
> 그 커밋이 한 일을 **정확히 반대로 하는 새 커밋**을 만듭니다. 기록은 그대로 남고, 결과만 되돌아갑니다.

```bash
git push
```
> 되돌린 것을 올립니다.

**결과가 이렇게 남습니다.**

```
a3f9c21  결제 화면 새로 만듦        ← 남아 있음
b7d1e88  결제 화면 새로 만든 것 되돌림  ← 새로 얹힘
```

지저분해 보이지만 **이게 맞습니다.** 「무엇을 했다가 왜 물렀는지」가 기록으로 남는 게 오히려 자산입니다.

> ### ⚠️ 절대 하지 말 것 — 강제로 밀어내기
>
> 인터넷에서 이런 걸 봅니다.
>
> ```
> git push --force
> ```
>
> **초보자는 쓰지 마세요.** 「내 컴퓨터 상태로 인터넷 창고를 통째로 덮어써라」는 뜻입니다.
> 남이 올려 둔 작업이 **소리 없이 사라집니다.** 되돌릴 방법이 없는 경우도 있습니다.
> 이미 올린 것을 되돌릴 때는 **`revert` 하나면 됩니다.** 강제로 밀어야 할 일은 혼자 작업하는 동안 거의 없습니다.
>
> 마찬가지로 **「역사를 다시 쓰는」 명령**(과거 커밋을 합치거나 지우는 것)도 **이미 올린 것에는 쓰지 않습니다.** 안 올린 ②단계에서만 씁니다.

## ④ 날린 것 같을 때 → 먼저 `reflog`부터

**포기하기 전에 여기부터 봅니다. 대부분 여기서 찾습니다.**

Git은 **내가 지운 것도 한동안 몰래 들고 있습니다.** 커밋을 되감았든, 브랜치를 지웠든,
「지금까지 내 저장소가 지나온 자리」를 따로 적어 둡니다. 그 목록이 `reflog`입니다.
**보관 기간은 대략 30일**입니다.

```bash
git reflog
```
> 내 저장소가 지나온 모든 자리를 최근 순으로 보여 줍니다.

이런 게 나옵니다.

```
a3f9c21 HEAD@{0}: reset: moving to HEAD~1
b7d1e88 HEAD@{1}: commit: 결제 화면 새로 만듦     ← 날린 줄 알았던 그것
c2e4f77 HEAD@{2}: commit: 로그인 여백 정리
```

**읽는 법** — 맨 왼쪽이 그 시점의 **주소**, 오른쪽이 그때 무슨 일을 했는지입니다.
날리기 **직전** 줄을 찾으면 됩니다.

찾았으면 **바로 되돌리지 말고, 옆에 가지를 하나 내서 확인합니다.**

```bash
git switch -c 복구 b7d1e88
```
> 그 시점의 상태로 **새 가지**를 하나 만들어 그리로 옮겨 갑니다. 지금 상태는 그대로 남습니다.

거기서 파일을 열어 **찾던 게 맞는지 눈으로 확인**한 뒤, 맞으면 그 가지에서 계속 일하거나 `main`에 합칩니다.

> **왜 `git reset --hard`로 바로 안 가나** — 잘못 짚었을 때 또 되돌려야 하기 때문입니다. **가지를 내는 건 아무것도 망가뜨리지 않습니다.** 초보자에게는 이 길이 훨씬 안전합니다.

**AI에게 맡기는 법**

```
방금 git reset을 잘못 써서 커밋 하나를 날린 것 같아.
git reflog 를 읽어서 날리기 직전 상태가 어느 줄인지 찾아줘.
찾으면 그 시점으로 새 브랜치를 만드는 명령만 알려줘.
지금 상태는 절대 건드리지 마.
```

**마지막 줄이 중요합니다.** 「건드리지 마」를 빼면 AI가 알아서 되돌려 버릴 수 있습니다.

## 📘 말 풀이

**`reset` — 되감기**
「없던 일로」 만듭니다. 커밋 자체가 사라집니다. **아직 안 올린 것에만** 씁니다. `--soft`(커밋만 취소, 내용 유지) / `--hard`(내용까지 버림) 두 가지를 구분해서 기억하세요.

**`revert` — 반대로 하기**
「반대되는 일을 새로 합니다.」 원래 커밋은 그대로 남고 그것을 무르는 커밋이 하나 더 얹힙니다. **이미 올린 것에는 이것만** 씁니다.

**`reflog` — 지나온 자리 기록**
내 저장소가 거쳐 간 모든 지점의 목록. 커밋 목록(`log`)과 달리 **되감아서 사라진 것까지** 남아 있습니다. 약 30일 보관. **날린 것 같으면 무조건 여기부터.**

## ⚠️ 자주 걸리는 함정

- **인터넷에서 찾은 명령을 상황 확인 없이 칩니다.** 대부분의 사고가 여기서 납니다. **`git status`와 `git log --oneline`을 먼저** 치고, 지금이 ①②③ 중 어디인지 정한 다음에 명령을 고릅니다.
- **이미 올린 것에 `reset`을 씁니다.** 내 컴퓨터와 GitHub이 어긋납니다. 그다음 `push`가 거부되고, 당황해서 `--force`를 치면 진짜 사고가 됩니다. **올린 것은 `revert`입니다.**
- **`--hard`를 먼저 시도합니다.** 대부분은 `--soft`로 충분합니다. 순서를 지킵니다.
- **날렸다고 판단하고 처음부터 다시 만듭니다.** `reflog`를 안 봐서 그렇습니다. **30일 안이면 대개 살아 있습니다.**
- **커밋 안 한 변경도 `reflog`로 찾을 수 있다고 믿습니다.** 못 찾습니다. Git이 기록한 적이 없기 때문입니다. **커밋을 자주 하는 이유가 이것입니다.**
- **되돌린 다음 `push`를 안 합니다.** 내 컴퓨터만 되돌아가고 GitHub은 그대로입니다.

## ⚡ 이렇게 하세요 — 일부러 망치고 되돌리는 연습

**읽기만 하면 정작 필요할 때 손이 안 움직입니다. 지금 15분 써서 세 번 망가뜨립니다.**
연습용 폴더를 하나 새로 만들어서 합니다. 진짜 프로젝트에서 하지 마세요.

### 준비 — 연습장 만들기

```bash
mkdir ~/git-연습 && cd ~/git-연습
git init
echo "첫 줄입니다" > 연습.txt
git add 연습.txt
git commit -m "첫 커밋"
```
> 폴더를 만들고 → 저장소로 만들고 → 파일 하나 만들고 → 담아서 → 저장합니다.

### 연습 ① 아직 커밋 안 한 것 버리기

```bash
echo "엉망으로 고침" >> 연습.txt
cat 연습.txt
```
> 파일을 망가뜨리고 → 망가진 걸 눈으로 봅니다.

```bash
git restore 연습.txt
cat 연습.txt
```
> 되돌리고 → **「첫 줄입니다」만 남았는지 확인합니다.** 남았으면 ① 성공입니다.

### 연습 ② 커밋했는데 안 올린 것 되감기

```bash
echo "잘못된 두 번째 줄" >> 연습.txt
git add . && git commit -m "잘못된 커밋"
git log --oneline
```
> 망가뜨려서 커밋까지 하고 → 목록에 **두 줄**이 보이는 걸 확인합니다.

```bash
git reset --hard HEAD~1
git log --oneline
cat 연습.txt
```
> 한 칸 되감고 → 목록이 **한 줄로 줄었는지**, 파일이 원래대로인지 확인합니다. 줄었으면 ② 성공입니다.

### 연습 ③ 날린 것 찾아내기 — **가장 중요합니다**

방금 ②에서 날린 커밋을 **다시 살립니다.**

```bash
git reflog
```
> 지나온 자리 목록을 봅니다. **「잘못된 커밋」이라는 글자가 아직 보입니다.** 그 줄 맨 앞 주소를 복사합니다.

```bash
git switch -c 복구연습 여기에복사한주소
cat 연습.txt
```
> 그 시점으로 새 가지를 내고 → 파일에 **「잘못된 두 번째 줄」이 돌아왔는지** 확인합니다. 돌아왔으면 ③ 성공입니다.

**이 순간을 기억하세요.** 진짜로 날렸을 때 손이 여기로 갑니다.

```bash
git switch -
```
> 원래 가지로 돌아옵니다.

### 연습 ④ 이미 올린 것 되돌리기 (선택)

2절에서 만든 진짜 저장소에서 해 봅니다. 사소한 변경 하나를 커밋하고 `push`한 뒤,

```bash
git log --oneline
git revert 방금커밋주소
git push
```
> 커밋 주소를 찾고 → 반대로 하는 커밋을 만들고 → 올립니다.

GitHub 웹페이지에서 **커밋이 두 개(원래 것 + 되돌린 것) 다 보이는지** 확인합니다. 이게 「역사를 지우지 않고 되돌린다」의 모습입니다.

### 연습장 치우기

```bash
rm -rf ~/git-연습
```
> 연습 폴더를 지웁니다. **`rm -rf`는 되돌릴 수 없는 명령입니다.** 경로가 `~/git-연습`이 맞는지 눈으로 한 번 더 확인하고 치세요.

### 이렇게 해 봤습니다 — 2026-09-09 · 네 가지를 실제로 돌려 봤습니다

연습용 저장소를 하나 만들어 **일부러 망가뜨리고 네 가지 방법으로 되살려** 봤습니다. 결과입니다.

| 상황 | 한 일 | 결과 |
|---|---|---|
| 아직 저장 안 함 | 파일을 엉뚱한 내용으로 덮어씀 → `restore` | **원래 내용으로 돌아옴** |
| 저장했는데 안 올림 | 잘못된 커밋을 만듦(3개) → `reset` | **커밋 2개로 줄고 파일도 돌아옴** |
| 이미 올림 | `revert` | **커밋이 3개 → 4개로 «늘었습니다».** 지운 게 아니라 «되돌리는 커밋»이 하나 더 쌓입니다 |
| 날린 것 같을 때 | 두 개를 날린 뒤 `reflog` | **날린 커밋이 목록에 그대로 남아 있었고**, 그 번호로 되살렸습니다 |

**세 번째 줄이 가장 헷갈리는 자리입니다.** 되돌렸는데 커밋 수가 늘어나서 *"안 된 건가?"* 싶습니다.
**그게 맞게 된 것입니다.** 남들이 이미 받아 간 역사를 지우면 그쪽이 깨지니까, 지우는 대신 **「이걸 취소합니다」라는 기록을 새로 남기는** 것입니다.

**네 번째가 이 절에서 제일 중요합니다.** 날렸다고 생각한 것이 실제로는 남아 있었습니다.
**당황해서 다시 만들기 전에 `reflog`부터 봅니다.**

## ✅ 됐는지 확인

- [ ] **일부러 망치고 되돌려 봤나** — 읽기만 한 게 아니라 위의 연습 ①②③을 실제로 손으로 쳐 봤나
- [ ] 연습 ③에서 **날린 커밋을 `reflog`로 다시 찾아냈나**
- [ ] 「아직 커밋 안 함 / 커밋했는데 안 올림 / 이미 올림」 **셋의 처리가 다르다**는 걸 아나
- [ ] 날린 것 같을 때 **가장 먼저 칠 명령**이 `git reflog`라는 걸 아나
- [ ] **이미 올린 것에는 `reset`이 아니라 `revert`**를 쓴다는 걸 아나
- [ ] `git push --force`가 **왜 위험한지** 한 문장으로 말할 수 있나
- [ ] 지금 어느 단계인지 모를 때 **먼저 칠 명령**(`git status`)을 아나

하나라도 «아니오»면 연습으로 돌아갑니다. **이 절만은 읽고 넘어가면 안 됩니다.**
