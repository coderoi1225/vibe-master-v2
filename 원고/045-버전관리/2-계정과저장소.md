초보자가 이 장에서 가장 많이 멈추는 자리가 여기입니다. 저장소까지는 잘 만들어 놓고, 내 컴퓨터의 파일을 인터넷 창고로 올리는 순간 이런 게 뜹니다.

```
remote: Support for password authentication was removed.
fatal: Authentication failed
```

## ① 세 걸음을 표로 본다

위 메시지를 옮기면 "비밀번호로는 안 받습니다"입니다. GitHub은 웹사이트 로그인 비밀번호로 파일을 올리는 걸 막았기 때문에, **아이디와 비밀번호를 아무리 정확히 쳐도 실패합니다.** 별도의 로그인 절차가 따로 필요합니다.

| 걸음 | 어디서 | 무엇을 |
|---|---|---|
| 계정 만들기 | 웹브라우저 | GitHub에 가입 |
| 저장소 만들기 | 웹브라우저 | 인터넷 쪽 창고를 하나 판다 |
| 내 컴퓨터와 연결 | 터미널 | 로그인 → 내 폴더를 창고에 연결 |

앞 둘은 웹사이트에서 버튼만 누르면 됩니다. 셋째가 함정입니다.

## ② 계정을 만든다

브라우저에서 github.com 에 들어가 **Sign up**을 누르세요. 이메일·비밀번호·사용자 이름(username)을 넣고, 이메일로 온 숫자를 넣어 인증합니다.

사용자 이름은 나중에 `github.com/사용자이름/저장소이름` 형태의 주소가 됩니다. 회사 이름이나 앞으로 쓸 활동명으로 정하는 편이 낫습니다. 나중에 바꾸면 예전 주소가 전부 깨집니다.

가입 직후 2단계 인증(2FA)을 켜라고 나옵니다. 켜세요. 코드를 올리는 곳이라 계정을 뺏기면 피해가 큽니다.

## ③ 저장소를 만든다

오른쪽 위 **+** → **New repository**를 누르세요. 채울 칸은 넷입니다.

| 칸 | 무엇을 넣나 |
|---|---|
| Repository name | 영어 소문자와 하이픈으로 (`my-service`). 띄어쓰기·한글은 피합니다 |
| Description | 한 줄 설명. 비워도 됩니다 |
| Public / Private | 아래 표를 보고 고릅니다 |
| Add a README file | 체크합니다. 빈 저장소는 연결이 한 단계 더 번거롭습니다 |

| | 공개(Public) | 비공개(Private) |
|---|---|---|
| 누가 보나 | 주소만 알면 누구나 | 나와 내가 초대한 사람만 |
| 좋은 점 | 자동 검사·보안 스캔 도구가 제약 없이 붙습니다 | 아무도 못 봅니다 |
| 나쁜 점 | 실수로 올린 비밀값을 전 세계가 봅니다 | 일부 무료 검사 도구가 제한됩니다 |

추천 — 처음 만드는 것은 비공개로 시작합니다. 아직 3절의 비밀값 다루기가 손에 안 붙었기 때문입니다. 비공개→공개는 설정에서 한 번에 되지만, 한 번 공개된 것은 이미 복사됐다고 봐야 합니다.

대안 — 비밀값이 하나도 안 들어가는 글·문서만 담을 폴더라면 공개로 시작해도 됩니다.

## ④ 로그인 도구를 깔고 로그인한다

터미널에서 GitHub에 로그인하려면 **GitHub CLI**라는 공식 명령줄 도구를 씁니다. 이걸 쓰면 비밀번호 문제가 통째로 사라집니다.

```bash
brew install gh
```
> 맥에서 GitHub CLI를 깝니다. `brew`가 없다고 나오면 AI에게 「Homebrew 깔아줘」라고 시킵니다.

```bash
gh auth login
```
> GitHub에 로그인합니다. 화면에서 몇 가지를 물어봅니다.

| 질문 | 고를 것 |
|---|---|
| Where do you use GitHub? | GitHub.com |
| Preferred protocol? | HTTPS |
| Authenticate Git with your GitHub credentials? | Yes |
| How would you like to authenticate? | Login with a web browser |

마지막을 고르면 여덟 글자 코드(예: `A1B2-C3D4`)가 뜨고 `Enter`를 누르면 브라우저가 열립니다. 그 코드를 붙여넣고 Authorize를 누르면 끝입니다. 비밀번호를 치는 곳이 아예 없다는 점을 눈여겨보세요.

## ⑤ 내 폴더를 연결한다

```bash
cd ~/projects/my-service
```
> 내가 작업할 폴더로 이동합니다. 경로는 본인 폴더에 맞게 바꿉니다.

```bash
git init
```
> 이 폴더를 저장소로 만듭니다. 숨은 기록 창고가 이때 생깁니다.

```bash
git remote add origin https://github.com/사용자이름/저장소이름.git
```
> ③에서 만든 저장소를 「이 폴더가 올라갈 곳」으로 지정합니다. `사용자이름`과 `저장소이름`은 본인 것으로 바꿉니다.

```bash
git remote -v
```
> 이 폴더가 어디로 올라가는지 보여 줍니다. **주소 두 줄이 나오면 성공입니다.**

## ⚡ 따라 하기

한 줄씩 실행하고 결과를 본 뒤 다음으로 가세요.

1. 브라우저에서 github.com 에 가입하고 2단계 인증을 켜세요. 계정을 뺏기면 코드까지 뺏기기 때문입니다. 프로필 화면이 열리면 된 것입니다.
2. **+ → New repository**에서 이름을 짓고 Private을 고르고 Add a README를 체크한 뒤 Create repository를 누르세요. 저장소 페이지가 열리고 README 한 장이 보여야 합니다.
3. 터미널을 열고 아래를 차례로 치세요. 비밀번호 대신 쓸 열쇠를 컴퓨터에 심는 단계입니다.

```bash
brew install gh
gh auth login
```
> GitHub CLI를 깔고 로그인합니다. ④의 표대로 답하면 브라우저가 열립니다.

```bash
gh auth status
```
> 지금 누구로 로그인돼 있는지 보여 줍니다. 내 사용자 이름이 나오면 성공입니다.

4. 작업 폴더에서 아래를 치세요. 이 폴더가 어느 창고로 올라갈지 정하는 단계입니다. 마지막 줄에서 주소 두 줄이 보여야 합니다.

```bash
cd ~/projects/내폴더이름
git init
git remote add origin https://github.com/내사용자이름/내저장소이름.git
git remote -v
```
> 폴더로 이동 → 저장소로 만들기 → 올라갈 곳 지정 → 확인.

5. 막히면 화면에 뜬 글자를 요약하지 말고 그대로 AI에게 붙여넣으세요. 요약하면 단서가 빠집니다. 한 줄 명령이 돌아오면 그것만 칩니다.

```
아래는 터미널에 뜬 내용 그대로야. 무슨 뜻인지 알려주고,
지금 내가 쳐야 할 명령 한 줄만 알려줘. 여러 개 말고 한 줄만.

(여기에 화면 내용을 그대로 붙여넣기)
```

## ✅ 확인

- [ ] github.com에서 내 저장소 페이지가 열리고 이름 옆에 Private 표시가 보이나
- [ ] `gh auth status`를 쳤을 때 내 사용자 이름이 나오나
- [ ] `git remote -v`를 쳤을 때 주소 두 줄이 나오나
- [ ] 「비밀번호로는 안 되고 별도 로그인이 필요하다」는 걸 아나

하나라도 «아니오»면 다음 절로 넘어가지 않습니다. 여기서 막힌 채로 가면 뒤가 전부 막힙니다.

## 📘 말 풀이

**원격 저장소(remote)와 로컬 저장소(local)** — 로컬은 내 컴퓨터 안의 저장소, 원격은 GitHub에 있는 같은 저장소. 둘은 자동으로 같아지지 않습니다. `origin`은 「내가 주로 쓰는 원격 저장소」의 관행적 별명입니다.

**푸시(push)와 클론(clone)** — 푸시는 내 컴퓨터의 기록을 GitHub으로 올리는 것, 클론은 GitHub의 저장소를 통째로 내 컴퓨터에 내려받는 것입니다.

**인증(authentication)** — "이 사람이 진짜 그 사람인가"를 확인하는 절차. GitHub CLI로 로그인하면 컴퓨터 안에 안전한 열쇠가 저장되고, 이후로는 묻지 않습니다.

## ⚠️ 함정

**`Authentication failed`가 계속 뜹니다.** 비밀번호를 아무리 정확히 쳐도 안 됩니다. `gh auth login`을 먼저 해야 합니다.

**예전에 실패한 로그인 정보가 남아 방해합니다.** 맥의 키체인 접근(Keychain Access) 앱에서 `github.com`을 검색해 낡은 항목을 지운 뒤 다시 `gh auth login` 하면 풀립니다.

**폴더를 잘못 잡고 `git init`을 합니다.** 홈 폴더(`~`)에서 실행하면 컴퓨터 전체가 저장소가 됩니다. 반드시 작업할 폴더 안에서 실행합니다.

**회사 계정과 개인 계정을 한 컴퓨터에서 섞어 씁니다.** `gh auth status`로 지금 누구로 로그인돼 있는지 확인하는 습관을 들입니다.
