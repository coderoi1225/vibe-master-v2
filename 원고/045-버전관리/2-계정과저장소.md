## 왜 이걸 하나

**초보자가 이 장 전체에서 가장 많이 멈추는 자리가 여기입니다.**

멈추는 지점은 신기할 만큼 똑같습니다. 저장소까지는 잘 만들어 놓고,
**내 컴퓨터의 파일을 인터넷 창고로 올리는 순간** 이런 게 뜹니다.

```
remote: Support for password authentication was removed.
fatal: Authentication failed
```

한국어로 옮기면 **"비밀번호로는 안 받습니다"**입니다.
GitHub은 몇 해 전부터 웹사이트 로그인 비밀번호로 파일을 올리는 걸 막았습니다.
**아이디와 비밀번호를 아무리 정확히 쳐도 실패합니다.** 별도의 로그인 절차가 따로 필요합니다.

이 절을 끝내면 저장소 하나와 **막히지 않는 로그인**이 손에 남습니다.

## 전체 그림 — 세 걸음

| 걸음 | 어디서 | 무엇을 |
|---|---|---|
| ① 계정 만들기 | 웹브라우저 | GitHub에 가입 |
| ② 저장소 만들기 | 웹브라우저 | 인터넷 쪽 창고를 하나 판다 |
| ③ 내 컴퓨터와 연결 | 터미널 | 로그인 → 내 폴더를 창고에 연결 |

**③이 함정입니다.** ①②는 웹사이트에서 버튼만 누르면 되는데, ③은 터미널에서 별도 로그인이 필요합니다.

## ① 계정 만들기

1. 브라우저에서 **github.com** 에 들어갑니다.
2. **Sign up**을 누릅니다.
3. 이메일 · 비밀번호 · 사용자 이름(username)을 넣습니다.
4. 이메일로 온 숫자를 넣어 인증합니다.

**사용자 이름은 나중에 주소가 됩니다.** `github.com/사용자이름/저장소이름` 형태로 남에게 보이는 이름이니, 회사 이름이나 앞으로 쓸 활동명으로 정하는 편이 낫습니다. 나중에 바꿀 수는 있지만 예전 주소가 전부 깨집니다.

가입 직후 **2단계 인증(2FA)을 켜라**고 나옵니다. **켜세요.** GitHub은 코드를 올리는 곳이라 계정을 뺏기면 피해가 큽니다. 휴대폰 인증 앱으로 30초면 끝납니다.

## ② 저장소 만들기 — 공개할까 비공개할까

오른쪽 위 **+** → **New repository**를 누릅니다. 채울 칸은 넷입니다.

| 칸 | 무엇을 넣나 |
|---|---|
| **Repository name** | 영어 소문자와 하이픈으로. 띄어쓰기·한글은 피합니다 (`my-service`) |
| **Description** | 한 줄 설명. 비워도 됩니다 |
| **Public / Private** | 아래 표를 보고 고릅니다 |
| **Add a README file** | **체크합니다.** 빈 저장소는 연결이 한 단계 더 번거롭습니다 |

**공개(Public)와 비공개(Private) 고르는 기준**

| | 공개(Public) | 비공개(Private) |
|---|---|---|
| 누가 보나 | 주소만 알면 **누구나** | 나와 내가 초대한 사람만 |
| 좋은 점 | 자동 검사·보안 스캔 도구가 **제약 없이** 붙습니다. 남에게 보여 주기 쉽습니다 | 아무도 못 봅니다 |
| 나쁜 점 | 실수로 올린 비밀값을 **전 세계가 봅니다.** 자동으로 훑어가는 프로그램이 실제로 돌아다닙니다 | 일부 무료 검사 도구가 제한됩니다 |

**추천 — 처음 만드는 것은 비공개(Private)로 시작합니다.**
아직 3절의 비밀값 다루기가 손에 안 붙었기 때문입니다. 손에 붙은 뒤에 공개로 바꾸는 건 설정에서 한 번에 됩니다. 반대는 안 됩니다 — **한 번 공개된 것은 이미 복사됐다고 봐야 합니다.**

**대안** — 처음부터 남에게 보여 줄 목적이거나, 비밀값이 하나도 안 들어가는 글·문서만 담을 폴더라면 공개로 시작해도 됩니다. 자동 검사가 더 넉넉하게 붙습니다.

## ③ 내 컴퓨터와 연결하기 — 여기가 진짜

### 먼저 로그인 도구를 깝니다

터미널에서 GitHub에 로그인하려면 **GitHub CLI**라는 공식 명령줄 도구를 씁니다.
이름 그대로 「명령줄에서 쓰는 깃허브」입니다. 이걸 쓰면 비밀번호 문제가 통째로 사라집니다.

```bash
brew install gh
```
> 맥에서 GitHub CLI를 깝니다. `brew`는 맥용 프로그램 설치 도구입니다. `brew` 자체가 없다고 나오면 AI에게 「Homebrew 깔아줘」라고 시키면 됩니다.

### 로그인합니다

```bash
gh auth login
```
> GitHub에 로그인합니다. 화면에서 몇 가지를 물어봅니다.

물어보는 순서와 **고를 답**은 이렇습니다.

| 질문 | 고를 것 |
|---|---|
| Where do you use GitHub? | **GitHub.com** |
| Preferred protocol? | **HTTPS** |
| Authenticate Git with your GitHub credentials? | **Yes** |
| How would you like to authenticate? | **Login with a web browser** |

마지막을 고르면 화면에 **여덟 글자 코드**(예: `A1B2-C3D4`)가 뜨고 `Enter`를 누르면 브라우저가 열립니다.
그 코드를 브라우저에 붙여넣고 **Authorize**를 누르면 끝입니다.

**이게 아까 그 「별도 로그인」입니다.** 비밀번호를 치는 곳이 아예 없다는 점을 눈여겨보세요.

### 내 폴더를 창고에 연결합니다

이제 실제로 작업할 폴더로 갑니다.

```bash
cd ~/projects/my-service
```
> 내가 작업할 폴더로 이동합니다. 경로는 본인 폴더에 맞게 바꿉니다.

```bash
git init
```
> 이 폴더를 저장소로 만듭니다. 숨은 기록 창고가 이때 생깁니다.

```bash
gh repo create
```
> GitHub에 저장소를 만들고 이 폴더와 연결합니다. ②를 웹에서 이미 했다면 아래를 대신 씁니다.

```bash
git remote add origin https://github.com/사용자이름/저장소이름.git
```
> 이미 웹에서 만든 저장소를 「이 폴더가 올라갈 곳」으로 지정합니다. `사용자이름`과 `저장소이름`은 본인 것으로 바꿉니다.

연결이 됐는지 봅니다.

```bash
git remote -v
```
> 이 폴더가 어디로 올라가는지 보여 줍니다. 주소 두 줄이 나오면 성공입니다.

## 📘 말 풀이

**원격 저장소(remote)와 로컬 저장소(local)**
**로컬**은 내 컴퓨터 안의 저장소, **원격**은 GitHub에 있는 같은 저장소입니다. 둘은 자동으로 같아지지 않습니다. 내가 **밀어야(push)** 올라가고 **당겨야(pull)** 내려옵니다. `origin`은 「내가 주로 쓰는 원격 저장소」에 붙는 관행적인 별명입니다.

**푸시(push)와 클론(clone)**
**푸시**는 내 컴퓨터의 기록을 GitHub으로 올리는 것, **클론**은 GitHub의 저장소를 통째로 내 컴퓨터에 내려받는 것입니다. 새 컴퓨터에서 일을 이어 하려면 클론부터 합니다.

**인증(authentication)**
"이 사람이 진짜 그 사람인가"를 확인하는 절차. GitHub은 터미널에서 **웹사이트 비밀번호를 받지 않습니다.** GitHub CLI로 로그인하면 컴퓨터 안에 안전한 열쇠가 저장되고, 이후로는 묻지 않습니다.

## ⚠️ 자주 걸리는 함정

- **`Authentication failed`가 계속 뜹니다.** 비밀번호를 아무리 정확히 쳐도 안 됩니다. `gh auth login`을 먼저 해야 합니다. 이게 이 절의 핵심입니다.
- **예전에 실패한 로그인 정보가 남아 방해합니다.** 맥의 **키체인 접근(Keychain Access)** 앱을 열고 `github.com`을 검색해 낡은 항목을 지운 뒤 다시 `gh auth login` 하면 풀립니다.
- **저장소 이름에 한글이나 띄어쓰기를 넣습니다.** 주소가 깨집니다. 영어 소문자와 하이픈만 씁니다.
- **README 체크를 안 해서 빈 저장소가 됩니다.** 빈 저장소는 첫 연결 때 단계가 하나 더 늘어납니다. 체크해 두면 편합니다.
- **회사 계정과 개인 계정을 한 컴퓨터에서 섞어 씁니다.** 어느 계정으로 올라갔는지 헷갈립니다. `gh auth status`로 지금 누구로 로그인돼 있는지 항상 확인할 수 있습니다.
- **폴더를 잘못 잡고 `git init`을 합니다.** 홈 폴더(`~`)에서 실행하면 컴퓨터 전체가 저장소가 됩니다. 반드시 **작업할 폴더 안에서** 실행합니다.

## ⚡ 이렇게 하세요

순서대로 합니다. **한 줄씩 실행하고 결과를 보고 다음으로 갑니다.**

1. 브라우저에서 github.com 가입 → 2단계 인증 켜기
2. **+ → New repository** → 이름 짓기 → **Private** 고르기 → **Add a README** 체크 → **Create repository**
3. 터미널을 열고 아래를 차례로 실행합니다.

```bash
brew install gh
gh auth login
```
> GitHub CLI를 깔고 로그인합니다. 위 표대로 답하면 브라우저가 열립니다.

```bash
gh auth status
```
> 지금 누구로 로그인돼 있는지 보여 줍니다. 내 사용자 이름이 나오면 성공입니다.

4. 작업 폴더에서 연결합니다.

```bash
cd ~/projects/내폴더이름
git init
git remote add origin https://github.com/내사용자이름/내저장소이름.git
git remote -v
```
> 폴더로 이동 → 저장소로 만들기 → 올라갈 곳 지정 → 확인.

5. 막히면 AI에게 화면에 뜬 글자를 **요약하지 말고 그대로** 붙여넣고 물어봅니다.

```
아래는 터미널에 뜬 내용 그대로야. 무슨 뜻인지 알려주고,
지금 내가 쳐야 할 명령 한 줄만 알려줘. 여러 개 말고 한 줄만.

(여기에 화면 내용을 그대로 붙여넣기)
```

## ✅ 됐는지 확인

- [ ] github.com에 로그인해서 **내 저장소 페이지가 열리나**
- [ ] 그 저장소 이름 옆에 **Private**(또는 Public) 표시가 보이나
- [ ] 터미널에서 `gh auth status`를 쳤을 때 **내 사용자 이름이 나오나**
- [ ] `git remote -v`를 쳤을 때 **주소 두 줄이 나오나** (아무것도 안 나오면 연결이 안 된 것)
- [ ] 「비밀번호로는 안 되고 **별도 로그인이 필요하다**」는 걸 아나

하나라도 «아니오»면 다음 절로 넘어가지 않습니다. 여기서 막힌 채로 가면 뒤가 전부 막힙니다.
