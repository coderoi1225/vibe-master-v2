버전 관리는 여러 명이 같이 일할 때 쓰는 것이라고 알려져 있어서, 혼자 만드는 사람은 대개 건너뜁니다. 혼자인데도 해야 하는 이유는 하나 — **AI에게 크게 시키기 위해서**입니다.

## ① 안전망이 있을 때와 없을 때를 비교한다

AI에게 "이 폴더 전체를 정리해줘"라고 시켜 본 적이 있다면 압니다. 시키는 순간 불안해집니다. 잘못되면 되돌릴 방법이 없기 때문입니다.

| 안전망이 없을 때 | 안전망이 있을 때 |
|---|---|
| "이 파일 한 줄만 고쳐줘" | "이 기능 전체를 다시 짜줘" |
| 결과를 손으로 검사 | 마음에 안 들면 한 줄로 되감기 |
| 미리 파일을 복사해 둠 | 복사해 둘 필요가 없음 |
| 큰 실험을 안 하게 됨 | 실험이 공짜가 됨 |

조심스러우면 손으로 하는 것보다 조금 빠른 정도로 끝납니다. **되돌릴 수 있으면 시키는 크기가 달라집니다.** 그게 이 장의 전부입니다.

## ② 폴더 복사의 구멍 셋을 본다

많은 분이 이미 나름의 버전 관리를 하고 있습니다.

```
기획서.docx
기획서_최종.docx
기획서_최종_진짜최종.docx
기획서_최종_진짜최종_수정본.docx
```

이 방식에는 구멍이 셋입니다. 무엇이 바뀌었는지 모르고, 왜 바꿨는지 모르고, 일부만 되돌릴 수 없습니다. 3개월 뒤의 나는 남이고 **AI는 기억이 아예 없습니다.**

버전 관리는 이 셋을 한꺼번에 해결합니다. 무엇이·왜·언제 바뀌었는지가 파일과 함께 보관되고, 원하는 지점 하나만 골라 되돌릴 수 있습니다.

## ③ 사진첩이 아니라 영상으로 본다

저장소를 "백업 폴더"로 이해하면 절반만 맞습니다.

- **사진첩** — 특정 순간의 사진 여러 장. 사진 사이에 무슨 일이 있었는지는 없습니다.
- **되감기 되는 영상** — 처음부터 지금까지가 끊기지 않고 들어 있습니다. 아무 지점으로나 되감을 수 있습니다.

저장소는 뒤쪽입니다. 파일의 현재 모습만이 아니라 그 파일이 지나온 모든 순간을 같이 들고 있습니다.

## ④ 이 장에서 손에 남는 것을 확인한다

| 만드는 것 | 어디에 쓰이나 |
|---|---|
| 내 저장소 하나 | 앞으로 만드는 코드가 전부 여기에 쌓입니다 |
| `.gitignore` 파일 | 비밀값이 실수로 새어 나가는 걸 막습니다 |
| 커밋 규칙 한 줄 | AI가 대신 지켜 줍니다 |
| 되돌리기 연습 1회 | 진짜로 망했을 때 손이 먼저 움직입니다 |

> **THE CHAIN** — 여기서 만드는 저장소가 [[07-배포PR/_스테이지|Stage 7]]에서 PR과 자동 검사가 걸리는 자리가 됩니다. 저장소가 없으면 Stage 7이 통째로 막힙니다.

## ⚡ 따라 하기

1. 지금 쓰는 AI 도구 대화창에 아래를 그대로 붙여넣으세요. 저장소를 만들기 전에 도구가 깔려 있는지부터 봐야 합니다. 버전 숫자 한 줄이 돌아오면 준비된 것입니다.

```
내 맥에 git이 깔려 있는지 확인해줘.
`git --version`을 실행하고, 안 깔려 있으면 어떻게 까는지 알려줘.
깔려 있으면 버전만 한 줄로 보고해줘.
```

2. 이어서 아래를 붙여넣으세요. 내가 모르는 새 이미 저장소가 된 폴더가 있는지 알아 두기 위해서입니다. 표가 나오거나 «없다»는 답이 옵니다 — **아무것도 없어도 정상입니다.** 다음 절에서 처음부터 하나 만듭니다.

```
내 홈 폴더 아래에서 이미 git 저장소인 폴더가 있는지 찾아줘.
있으면 폴더 이름과 마지막으로 저장된 날짜를 표로 보여줘. 내용은 건드리지 마.
```

## ✅ 확인

- [ ] `git --version`을 실행했을 때 에러가 아니라 글자와 숫자가 한 줄 나왔나
- [ ] 「저장소는 지금 모습만이 아니라 지나온 과정을 같이 갖고 있다」를 한 문장으로 말할 수 있나
- [ ] 「Git은 내 컴퓨터, GitHub은 인터넷 창고」 둘이 다른 것이라는 걸 아나

## 📘 말 풀이

**저장소(repository, 줄여서 repo)** — 파일과 그 파일이 지나온 모든 순간을 함께 보관하는 폴더. 겉보기엔 그냥 폴더인데 숨은 기록 창고가 하나 더 들어 있습니다.

**Git과 GitHub** — Git은 내 컴퓨터에서 도는 프로그램으로, 순간을 기록하고 되감습니다. GitHub은 그 기록을 인터넷에 올려 두는 남의 창고입니다. Git만 있어도 되돌리기는 전부 됩니다.

**커밋(commit)** — 지금 상태를 이름 붙여 저장하는 것. 영상으로 치면 되감기 표시를 하나 꽂는 일입니다. 4절에서 다룹니다.

## ⚠️ 함정

**"코드가 없으면 필요 없다"고 생각합니다.** 기획서·설계문서·설정 파일도 전부 대상입니다. 오히려 글이 더 자주 뒤집힙니다.

**"나중에 붙이면 되지"라고 미룹니다.** 버전 관리는 망하기 전에 있어야 의미가 있습니다. 망한 뒤에 시작하면 되돌릴 과거가 없습니다.

**완벽하게 이해한 뒤에 시작하려 합니다.** Git에는 명령이 백 개 넘게 있지만 혼자 쓰는 데 필요한 건 열 개 안쪽입니다.

**AI가 알아서 해 줄 거라 믿습니다.** AI는 시키면 커밋해 줍니다. 하지만 무엇을 되돌릴지 정하는 건 사람입니다.
