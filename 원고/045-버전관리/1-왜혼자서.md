## 왜 이걸 하나

버전 관리는 **여러 명이 같이 일할 때 쓰는 것**이라고 알려져 있습니다.
그래서 혼자 만드는 사람은 대개 건너뜁니다.

혼자인데도 해야 하는 이유는 딱 하나입니다.
**AI에게 크게 시키기 위해서**입니다.

이 절을 건너뛰면 뒤의 모든 장에서 **AI에게 작게밖에 못 시킵니다.**

## 안전망이 없으면 조심스러워집니다

AI에게 "이 폴더 전체를 정리해줘"라고 시켜 본 적이 있다면 알 겁니다.
시키는 순간 **가슴이 철렁**합니다. 잘못되면 되돌릴 방법이 없으니까요.

그래서 이렇게 됩니다.

| 안전망이 없을 때 | 안전망이 있을 때 |
|---|---|
| "이 파일 한 줄만 고쳐줘" | "이 기능 전체를 다시 짜줘" |
| 시키고 나서 결과를 **손으로** 검사 | 마음에 안 들면 **한 줄로 되감기** |
| 잘못될까 봐 미리 파일을 복사해 둠 | 복사해 둘 필요가 없음 |
| 큰 실험을 안 하게 됨 | 실험이 공짜가 됨 |

**조심스러우면 AI를 제대로 못 씁니다.** 손으로 하는 것보다 조금 빠른 정도로 끝납니다.
되돌릴 수 있으면 시키는 크기가 달라집니다. 그게 이 장의 전부입니다.

## 폴더 복사로는 안 되는 이유

많은 분이 이미 나름의 버전 관리를 하고 있습니다.

```
기획서.docx
기획서_최종.docx
기획서_최종_진짜최종.docx
기획서_최종_진짜최종_수정본.docx
```

이 방식에는 세 가지 구멍이 있습니다.

1. **무엇이 바뀌었는지 모릅니다.** 두 파일을 나란히 놓고 눈으로 찾아야 합니다.
2. **왜 바꿨는지 모릅니다.** 3개월 뒤의 나는 남이고, **AI는 기억이 아예 없습니다.**
3. **일부만 되돌릴 수 없습니다.** 세 가지를 고친 뒤 그중 하나만 무르고 싶어도 방법이 없습니다.

버전 관리는 이 셋을 한꺼번에 해결합니다.
**무엇이 · 왜 · 언제** 바뀌었는지가 파일과 함께 보관되고, 원하는 지점 하나만 골라 되돌릴 수 있습니다.

## 사진첩이 아니라 되감기 되는 영상

저장소를 "백업 폴더"로 이해하면 절반만 맞습니다.

- **사진첩** — 특정 순간의 사진 여러 장. 사진 사이에 무슨 일이 있었는지는 없습니다.
- **되감기 되는 영상** — 처음부터 지금까지가 **끊기지 않고** 들어 있습니다. 아무 지점으로나 되감을 수 있고, 그 지점부터 다시 갈 수도 있습니다.

저장소는 뒤쪽입니다.
파일의 **현재 모습**만이 아니라 **그 파일이 지나온 모든 순간**을 같이 들고 있습니다.

## 이 장에서 손에 남는 것

| 만드는 것 | 어디에 쓰이나 |
|---|---|
| 내 저장소 하나 | 앞으로 만드는 코드가 전부 여기에 쌓입니다 |
| `.gitignore` 파일 | 비밀값이 실수로 새어 나가는 걸 막습니다 |
| 커밋 규칙 한 줄 | AI가 대신 지켜 줍니다 |
| **되돌리기 연습 1회** | 진짜로 망했을 때 손이 먼저 움직입니다 |

## 📘 말 풀이

**저장소(repository, 줄여서 repo)**
파일과 **그 파일이 지나온 모든 순간**을 함께 보관하는 폴더. 겉보기엔 그냥 폴더인데, 그 안에 숨은 기록 창고가 하나 더 들어 있습니다. 사진첩이 아니라 **되감기 되는 영상**에 가깝습니다.

**Git과 GitHub — 다른 것입니다**
**Git**은 내 컴퓨터에서 도는 프로그램입니다. 순간을 기록하고 되감는 일을 합니다. **GitHub**은 그 기록을 인터넷에 올려 두는 남의 창고입니다. Git만 있어도 되돌리기는 전부 됩니다. GitHub은 「내 컴퓨터가 고장 나도 남아 있게」와 「나중에 자동 검사를 걸게」를 위해 씁니다.

**커밋(commit)**
지금 상태를 이름 붙여 저장하는 것. 영상으로 치면 **되감기 표시를 하나 꽂는 일**입니다. 자세한 건 4절에서 다룹니다.

## ⚠️ 자주 걸리는 함정

- **"코드가 없으면 필요 없다"고 생각합니다.** 아닙니다. 기획서·설계문서·설정 파일도 전부 대상입니다. 오히려 글이 더 자주 뒤집힙니다.
- **"나중에 붙이면 되지"라고 미룹니다.** 버전 관리는 **망하기 전에** 있어야 의미가 있습니다. 망한 뒤에 시작하면 되돌릴 과거가 없습니다.
- **완벽하게 이해한 뒤에 시작하려 합니다.** Git에는 명령이 백 개 넘게 있지만 **혼자 쓰는 데 필요한 건 열 개 안쪽**입니다. 나머지는 여러 명이 얽힐 때 쓰는 것입니다.
- **AI가 알아서 해 줄 거라 믿습니다.** AI는 시키면 커밋해 줍니다. 하지만 **무엇을 되돌릴지 정하는 건 사람**입니다. 판단이 내 몫이라 최소한은 알아야 합니다.

## ⚡ 이렇게 하세요

지금 쓰는 AI 도구 대화창에 아래를 그대로 붙여넣습니다.
설치 여부부터 확인하는 것이 첫 걸음입니다.

```
내 맥에 git이 깔려 있는지 확인해줘.
`git --version`을 실행하고, 안 깔려 있으면 어떻게 까는지 알려줘.
깔려 있으면 버전만 한 줄로 보고해줘.
```

이어서, 내가 이미 뭘 갖고 있는지 봅니다.

```
내 홈 폴더 아래에서 이미 git 저장소인 폴더가 있는지 찾아줘.
있으면 폴더 이름과 마지막으로 저장된 날짜를 표로 보여줘. 내용은 건드리지 마.
```

**아무것도 없어도 정상입니다.** 다음 절에서 처음부터 하나 만듭니다.

## ✅ 됐는지 확인

- [ ] `git --version`을 실행했을 때 **글자와 숫자가 한 줄 나오나** (에러 메시지가 아니라)
- [ ] "저장소는 파일의 **지금 모습만이 아니라 지나온 과정**을 같이 갖고 있다"를 남에게 한 문장으로 말할 수 있나
- [ ] 「Git은 내 컴퓨터, GitHub은 인터넷 창고」 **둘이 다른 것**이라는 걸 아나
