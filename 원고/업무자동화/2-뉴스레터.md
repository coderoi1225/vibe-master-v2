뉴스레터는 1인 회사가 가진 유일하게 남의 알고리즘을 안 타는 통로입니다. 단, 2026년 현재 대형 메일 서비스들은 인증이 안 된 발신자의 메일을 스팸함에 넣는 게 아니라 아예 거부하므로, **발신 인증이 이 섹션 전체의 1번 전제**입니다.

## ① 도메인부터 확보한다

포털 무료 메일 주소로는 **발신 인증 자체가 안 됩니다.** 인증이란 「이 도메인의 주인이 이 발송 서비스에 권한을 줬다」를 도메인 설정에 적어 두는 것입니다. 남의 도메인에는 내가 적을 수 없습니다.

그래서 순서는 도메인 사기 → DNS 설정 화면에 들어갈 수 있는지 확인 → 발송 서비스 가입입니다. 도메인 없이 발송 서비스부터 가입하면 첫 화면에서 막힙니다.

## ② 인증 3종을 DNS에 넣는다

발송 서비스가 알려 주는 값을 도메인 DNS에 붙여넣는 일입니다. 어려운 건 없고, 붙여넣고 몇 분 기다리면 됩니다.

| 무엇 | 하는 일 | 한 줄로 |
|---|---|---|
| **SPF** | 이 도메인 이름으로 메일을 보낼 수 있는 서버 목록 | "이 사람들만 내 이름으로 보낼 수 있다" |
| **DKIM** | 메일에 도장(전자서명)을 찍어 도중에 안 바뀐 걸 증명 | "이 메일은 진짜 내가 보낸 것이다" |
| **DMARC** | 위 둘이 실패했을 때 어떻게 처리할지 지시 | "가짜면 버려라" |
| **원클릭 수신거부** | 받은 사람이 버튼 하나로 구독 해지 | 메일 프로그램이 직접 처리 |

**2026년 현재, 넷 중 하나라도 없으면 메일은 스팸함이 아니라 아예 거부됩니다.** 원클릭 수신거부는 예의가 아니라 요구 조건입니다 — 해지를 어렵게 만들면 사람들이 대신 「스팸 신고」를 누르고, 신고가 쌓이면 그 도메인 전체가 막힙니다. 해지를 쉽게 만드는 게 내 도메인을 지키는 길입니다.

## ③ 정보통신망법 50조를 확인한다

한국에서 광고성 정보를 메일로 보낼 때 지켜야 하는 조문입니다. 핵심 넷입니다.

| # | 규칙 | 실무에서 |
|---|---|---|
| 1 | **명시적 사전 동의** | 체크박스를 미리 체크해 두면 안 됩니다. 받는 사람이 직접 체크해야 합니다 |
| 2 | **수신거부하면 전송 금지** | 해지 즉시 목록에서 빠져야 합니다. "다음 호부터"가 아닙니다 |
| 3 | **21시~익일 8시는 별도 동의** | 야간 발송은 동의를 따로 받아야 합니다. 예약 시각을 낮으로 잡으면 간단히 피합니다 |
| 4 | **표시 의무** | 전송자 이름·연락처·수신거부 방법을 본문에 적고, **제목 맨 앞에 `(광고)`** |

2026-03 개정 안내서가 새로 금지한 것이 있습니다. *"혜택 안내를 받겠습니다"*, *"유용한 정보를 받겠습니다"* 같은 애매한 표현으로 광고 수신 동의를 받는 것이 금지됐습니다. 「광고」라는 말을 피해서 동의를 받으면 동의를 받은 것으로 치지 않으므로, 동의 문구에는 광고성 정보를 보낸다는 사실이 그대로 적혀 있어야 합니다.

무엇이 광고인가 — 판단이 애매하면 광고로 봅니다. 새 상품 소식, 할인, 강의 모집은 명백히 광고이고, 순수한 정보 소식지라도 "지금 신청하기" 버튼이 하나라도 있으면 광고 쪽입니다. 애매하면 `(광고)`를 붙이는 쪽이 안전합니다 — 붙여서 손해 보는 건 열어 보는 비율이고, 안 붙여서 손해 보는 건 과태료입니다.

> 이 절의 법 이야기는 **법률 자문이 아닙니다.** 실제 발송 전에 조문과 최신 안내서를 직접 확인하거나 전문가에게 묻습니다.

`[확인 필요]` — 수신동의를 2년마다 다시 확인해야 하는 조문의 정확한 적용 범위. 조문 번호와 대상을 확인하지 못했습니다. 발송 서비스가 이 기능을 제공하는 경우가 많으니 가입 후 설정 화면에서 찾아봅니다.

## ④ 발송 서비스를 고른다

두 갈래이고, 시작은 국내 한글 서비스입니다.

| 갈래 | 서비스 | 언제 |
|---|---|---|
| **국내 한글 서비스** | **스티비**, **메일리** | 화면이 한글이고, 구독 폼·수신거부·통계가 이미 들어 있습니다. `(광고)` 표기와 야간 발송 안내도 한국 법에 맞춰져 있습니다 |
| 개발형 | **Resend**, **Mailgun** | 내가 만든 서비스가 회원가입 확인 메일 같은 걸 **스스로** 보내야 할 때. 화면이 아니라 코드로 부릅니다 |

둘을 섞어 쓰는 게 정상입니다 — 사람이 읽는 소식지는 국내 서비스로, 서비스가 자동으로 뱉는 메일은 개발형으로. 다만 이번 달에 켜는 건 **국내 서비스 하나**면 충분합니다. 요금과 구독자 한도는 본문에 두지 않습니다 → [[부록/_스테이지|부록]]의 「버전과 값」.

## ⑤ AI와 사람의 자리를 가른다

| AI가 하는 것 | 사람이 남는 자리 |
|---|---|
| 초안 쓰기 | **발송 버튼** |
| 제목 후보 여러 개 뽑기 | 사실관계 확인 — 날짜·가격·이름이 맞나 |
| 긴 글을 소식지 길이로 줄이기 | **링크를 실제로 클릭해 보기** |
| 대상별로 문장 바꾸기(신규 구독자용 / 기존 구독자용) | 이름 치환이 제대로 됐나 — `{{이름}}` 이 그대로 나가지 않았나 |

**발송 버튼은 사람이 누릅니다. 예외 없습니다.** 한 번 나가면 회수 불가입니다 — 웹페이지는 고치면 되고 SNS는 지우면 되지만, 메일은 이미 상대 받은편지함에 있습니다.

자주 나가는 사고는 셋입니다. `안녕하세요 {{이름}}님`이 그대로 나감(치환 변수 이름을 틀렸을 때), 링크가 초안 주소로 나감(복사해 온 링크를 안 고쳤을 때), 지난 호 제목이 그대로 나감(복제해서 만들고 제목을 안 바꿨을 때). 셋 다 본인에게 시험 발송 한 통이면 잡히므로, 시험 발송이 자동화의 예외 자리입니다.

## ⚡ 따라 하기

**도메인과 인증** — 한 번만 합니다.

1. 도메인을 사고 DNS 설정 화면에 들어가 보세요. 인증 값을 여기 붙여넣을 것이라, 들어가지지 않으면 뒤가 전부 막힙니다.
2. 발송 서비스에 가입하고 「발신 도메인 인증」 메뉴를 여세요. 화면에 SPF·DKIM·DMARC 세 값이 나옵니다.
3. 그 값을 DNS에 그대로 붙여넣으세요. DNS는 퍼지는 데 시간이 걸리니, 화면에 「인증 완료」가 뜰 때까지 보내지 마세요.
4. 내 주소로 시험 발송 한 통을 보내세요. 스팸함이 아니라 받은편지함에 도착하면 인증이 끝난 것입니다.

**최소 루프** — 구독 폼 → 환영 메일 → 정기 발송.

5. 구독 폼을 하나 만들고 동의 문구를 아래 형태로 적으세요. 「광고성 정보」라는 말이 그대로 들어가야 동의로 칩니다.

```
[ ] (필수) 광고성 정보 수신에 동의합니다.
    ○○○(회사명)이 새 소식·강의 모집·할인 안내 등 광고성 정보를
    이메일로 보내는 것에 동의합니다.
    언제든지 메일 하단의 수신거부 버튼으로 해지할 수 있습니다.
```

체크박스는 미리 체크해 두지 않습니다.

6. 환영 메일 한 통을 만들어 「구독 즉시 발송」으로 걸어 두세요. 직접 구독해 보면 환영 메일이 와야 합니다 — 여기까지가 자동입니다.
7. 정기 발송은 월 2회로 잡으세요. 주 1회는 1인 회사가 못 지킵니다.

**초안을 AI에게 시킬 때** — 아래를 붙여넣고 재료를 이어서 적으세요. 제목 후보 다섯과 숫자 자리가 비워진 본문이 돌아와야 합니다.

```
아래 재료로 이번 달 뉴스레터 초안을 써 줘.

조건:
- 제목 후보 5개를 먼저 주고, 각 후보 옆에 왜 그 제목인지 한 줄.
- 제목에는 (광고) 표기가 들어갈 자리를 비워 둬. 내가 붙인다.
- 본문은 소식 3개 이하. 각 소식은 3~5문장.
- 맨 아래에 전송자 이름·연락처·수신거부 안내가 들어갈 자리를 표시해 둬.
- 날짜·가격·인원 같은 숫자는 내가 준 재료에 있는 것만 써라.
  재료에 없는 숫자는 절대 만들지 말고 [숫자 확인 필요]로 비워 둬.
- 링크도 마찬가지다. 내가 준 링크만 써라.

[여기에 재료를 붙여넣습니다]
```

**발송 전 사람이 하는 4줄 점검** — 넷을 다 통과한 뒤에 사람이 발송 버튼을 누르세요.

```
□ 시험 발송을 내 주소로 보냈고, 받은편지함(스팸함 아님)에 도착했다
□ 본문의 링크를 전부 클릭해 봤고, 전부 의도한 곳으로 갔다
□ 이름 치환이 실제 이름으로 바뀌어 보인다 ({{ }} 가 안 보인다)
□ 제목에 (광고), 하단에 전송자 정보와 수신거부가 있다
```

## ✅ 확인

- [ ] 발송 서비스 화면에 「발신 도메인 인증 완료」가 보이고, 내 주소로 보낸 시험 메일이 스팸함이 아니라 받은편지함에 있나
- [ ] 구독 폼의 동의 문구에 「광고성 정보」라는 말이 그대로 들어 있나
- [ ] 새로 구독하면 환영 메일이 자동으로 오나(직접 구독해 보고 확인)
- [ ] 메일 하단의 수신거부 버튼을 눌러 실제로 해지가 되나

## 📘 말 풀이

**DNS** — 도메인 이름을 실제 서버 주소로 바꿔 주는 인터넷 전화번호부. 여기에 인증 값(SPF·DKIM·DMARC)을 적어 두면, 받는 쪽 메일 서버가 그걸 읽어 진짜 발신자인지 확인합니다.

**치환 변수(merge tag)** — `{{이름}}`처럼 발송할 때 사람마다 다른 값으로 바뀌는 자리표. 이름을 틀리면 안 바뀌고 글자 그대로 나갑니다.

**시험 발송(test send)** — 구독자 목록이 아니라 내 주소로만 한 통 보내 보는 것. 실제 발송과 똑같은 처리를 거치므로 치환·링크 오류가 그대로 드러납니다.

## ⚠️ 함정

**포털 메일 주소로 시작합니다.** 가입은 되는데 인증에서 막힙니다. 도메인이 먼저입니다.

**인증 값을 넣고 바로 보냅니다.** DNS는 퍼지는 데 시간이 걸립니다. 발송 서비스 화면에 「인증됨」이 뜬 뒤에 보냅니다.

**명함 받은 사람을 목록에 넣습니다.** 명함을 준 것은 광고 수신 동의가 아닙니다. 구독 폼을 통해 본인이 직접 신청한 사람만 목록에 넣습니다.

**밤에 예약을 걸어 둡니다.** 21시~익일 8시는 별도 동의가 필요합니다. 낮 시각으로 잡으면 이 문제 자체가 없어집니다.

**제목에서 `(광고)`를 뺍니다.** "열어 보는 비율이 떨어져서" 빼는 경우가 많은데, 표시 의무 위반입니다.

**수신거부 링크를 작게 숨깁니다.** 스팸 신고로 이어지고, 스팸 신고는 도메인 평판을 깎습니다.

**AI 초안을 그대로 보냅니다.** 초안에는 없는 날짜와 없는 혜택이 섞여 들어옵니다. 광고 표시 문제 이전에 사실관계 문제입니다.
