「내 자료로 AI가 답하게 하고 싶다」고 검색하면 거의 언제나 같은 답이 나옵니다 — *자료를 잘게 자르고 → 숫자로 바꿔서 → 전용 저장소에 넣어라.* 이 절은 그걸 지금 하지 말라는 절입니다. 방향을 잘못 잡으면 몇 주를 도구 설치와 재색인에 쓰고도 정확도는 오히려 떨어지기 때문입니다.

## ① 권장 구성 셋을 본다

2026년 들어 널리 공유된 방식은 폴더 둘과 파일 하나입니다.

```
내볼트/
├── 원본/          ← 받은 그대로. 손대지 않는다
├── 위키/          ← 내가 다시 쓴 것. 여기를 읽힌다
└── CLAUDE.md      ← "이 폴더에서 무엇을 어떻게 찾아라"
```

눈여겨볼 것은 있는 것이 아니라 없는 것입니다. **임베딩(벡터)을 일부러 안 씁니다.** 빠뜨린 게 아니라 뺀 것이고, 이유는 하나 — 모델이 좋아져서 그냥 폴더를 열어 읽고 찾게 하는 쪽이 더 정확해졌기 때문입니다.

AI 회사의 공식 안내도 같은 순서를 말합니다. *"먼저 그냥 찾아 읽게 하고, 필요할 때만 의미 검색을 더하라."* 더하라이지, 처음부터 하라가 아닙니다.

## ② 그냥 읽는 쪽이 정확한 이유를 본다

숫자로 바꿔 찾는 방식은 자료를 잘게 잘라야 합니다. 「환불은 7일 이내」라는 문장과 그 아래 「단, 이용 시작 후에는 제외」가 다른 조각으로 찢어집니다. 조각 하나만 딸려 오면 AI는 **틀린 답을 자신 있게** 합니다.

그냥 읽는 방식은 자르지 않습니다. 파일 이름을 보고, 목차를 보고, 필요한 파일을 통째로 열어서 읽습니다. 사람이 자료를 찾는 방식과 같아서, 어느 파일을 열었는지 그대로 보이니 왜 그 답이 나왔는지도 추적됩니다.

| | 위키 방식(그냥 읽기) | 벡터 방식(숫자로 찾기) |
|---|---|---|
| 준비 | 폴더 만들고 글 쓰면 끝 | 자르기·변환·저장소·재색인 |
| 자료를 고치면 | 그냥 고치면 끝 | 다시 색인해야 반영됨 |
| 근거 추적 | 어느 파일인지 그대로 보임 | 어느 조각인지 따로 봐야 함 |
| 문서 수백 개 넘으면 | 느려지고 놓치기 시작 | 여기서 이깁니다 |
| 한국어 | 영향 없음 | 품질이 갈립니다 |

## ③ 한국어에서 더 강해지는 이유를 본다

숫자로 바꿔 찾는 방식은 글을 좌표로 옮기는 품질에 전부를 겁니다. 그런데 그 변환 품질은 언어마다 다릅니다. 영어 중심으로 만들어진 도구가 많고, 한국어는 조사와 어미가 붙어 형태가 계속 바뀌어서 같은 말인데 다른 것으로, 다른 말인데 같은 것으로 잡히는 일이 잦습니다.

「환불받을 수 있나요」와 「환불 규정」이 안 걸리고 엉뚱한 글이 1등으로 올라옵니다. 그러면 사람은 자료가 없는 줄 알고 다시 씁니다. **위키 방식은 변환 단계가 없으니 이 문제를 통째로 우회합니다.**

지식 그래프 방식(GraphRAG)도 같은 흐름입니다. 2026년 현재 대표적인 구현이 유지보수 모드로 공식 선언됐고, 사유는 실패가 아니라 모델이 좋아져서입니다. 방향은 하나로 모입니다 — 미리 가공해 두는 쪽에서 그때그때 읽는 쪽으로.

## ④ 문서 수를 세어 판정한다

이 절은 손보다 판단이 먼저입니다. 볼트 폴더에서 터미널을 열고 마크다운 파일 수를 셉니다.

```
find . -name "*.md" -not -path "./.git/*" | wc -l
```

나온 숫자를 이 표에 그대로 댑니다.

```
수백 개 미만  → 위키 방식. 벡터 쓰지 않는다. (거의 모든 1인 사업자가 여기)
수백 개 이상  → 4절로. 그때 순서가 따로 있다
```

**개수 하나로 판정합니다.** 다른 이유는 지금 끌어들이지 않습니다.

## ⑤ 결정을 파일로 남긴다

3개월 뒤의 내가 또 흔들립니다. 그때 다시 조사하지 않도록 이유를 파일로 남깁니다.

```markdown
# 결정 — 지식 검색 방식

**정한 것** — 위키(폴더 + 마크다운 + 그냥 읽기). 임베딩·벡터 저장소 쓰지 않음.
**날짜** — (오늘)
**왜** — ① 문서 ○○개로 그냥 읽는 게 더 정확 ② 자료를 고쳐도 재색인 불필요
        ③ 한국어 변환 품질 문제를 우회 ④ 근거 추적이 파일 단위로 됨
**언제 뒤집나** — 문서 수백 개를 넘고, 찾는 데 눈에 띄게 오래 걸릴 때
**뒤집을 때 순서** — 단어+의미 섞어 쓰는 검색 도구 먼저, 데이터베이스 벡터는 그다음
```

이 형식은 [[02-명세/_스테이지|Stage 2]]의 결정 기록과 같습니다. **결정에는 언제나 「언제 뒤집나」가 붙습니다.**

## ⚡ 따라 하기

1. 볼트 폴더에서 터미널을 열고 ④의 `find` 명령을 **그대로 붙여넣습니다.** 판정은 감이 아니라 숫자로 해야 하기 때문입니다. 숫자 하나가 찍히면 됩니다.
2. 그 숫자를 ④의 표에 댑니다. 수백 개 미만이면 「위키 방식」이라고 소리 내어 말해 보세요 — 누가 벡터를 권할 때 댈 첫 문장입니다.
3. `위키/` 안에 `결정-지식검색방식.md` 파일을 만들고 ⑤의 틀을 붙여넣습니다. ○○ 자리에 2번의 숫자를 넣으세요.
4. 「언제 뒤집나」 줄을 다시 읽고 내 상황에 맞게 한 단어라도 고칩니다. 그대로 두면 남의 결정이고, 고치면 내 결정이 됩니다.

## ✅ 확인

- [ ] 내 마크다운 문서가 몇 개인지 숫자로 말할 수 있나
- [ ] 그 숫자로 「위키 방식」인지 「벡터가 필요한 때」인지 판정했나
- [ ] 판정 이유와 「언제 뒤집나」가 파일로 남아 있나
- [ ] 누가 벡터 저장소를 권했을 때 거절할 이유 하나를 말할 수 있나

## 📘 말 풀이

**의미 검색(semantic search)** — 글자가 안 맞아도 뜻이 비슷하면 찾아 주는 검색. 「환불」로 검색해도 「돈 돌려받기」가 걸리지만, 뜻을 숫자로 바꾸는 준비 작업이 필요합니다.

**훑어 찾기(agentic search)** — AI가 사람처럼 폴더를 열고 파일 이름을 보고 필요한 걸 골라 읽는 방식. 준비 작업이 없고, 무엇을 열었는지 그대로 보입니다.

**지식 그래프 검색(GraphRAG)** — 자료에서 「누가 무엇과 어떤 관계인가」를 미리 뽑아 그물망을 만들어 두고 그걸로 답을 찾는 방식. 2026년 현재 대표 구현이 유지보수 모드입니다.

## ⚠️ 함정

**「제대로 하려면 벡터를 써야 한다」고 믿습니다.** 대부분의 안내 글이 벡터를 파는 도구 회사의 글입니다. 도구를 안 쓰는 방법은 아무도 광고하지 않습니다.

**문서가 30개인데 전용 저장소부터 세웁니다.** 30개는 AI가 다 읽습니다. 저장소는 관리 대상만 하나 늘립니다.

**한 번 잘라 넣고 자료를 계속 고칩니다.** 저장소 안의 것은 고친 게 반영 안 되어 옛날 답을 계속 합니다. 가장 조용하고 가장 위험한 고장입니다.

**유행하는 방식을 그대로 따라 합니다.** 6개월 전 정답이 지금 유지보수 모드입니다. 왜 그렇게 하는지를 묻지 않으면 매번 갈아엎게 됩니다.
