[[00-환경/_스테이지|Stage 0]]에서 연 폴더는 아직 창고입니다. 이 절에서 둘로 나누면 AI가 어디를 읽어야 하는지 헷갈리지 않게 됩니다 — 건너뛰면 AI가 원본 회의록 열두 개를 다 읽고 그중 철회된 결정을 근거로 답합니다.

## ① 폴더 둘과 파일 하나를 만든다

```
내볼트/
├── 원본/          받은 그대로. PDF·회의록·캡처·긁어온 글
├── 위키/          내가 다시 쓴 것. AI가 주로 읽는 곳
└── CLAUDE.md      이 폴더의 안내문
```

이름은 한글이어도 됩니다. 중요한 것은 **둘로 나뉘어 있다는 사실**이지 이름이 아닙니다.

## ② 원본을 고치지 않는 이유를 본다

가장 많이 하는 실수가 원본 위에 덧쓰는 것입니다. 6개월 뒤에 *"이 숫자 어디서 나온 거지?"* 하고 거슬러 올라갔는데 원본이 이미 요약본으로 덮여 있으면 확인할 방법이 사라집니다. AI가 요약하면서 숫자 하나를 잘못 옮겼어도 영원히 못 찾습니다.

원본은 증거이고, 증거는 고치지 않습니다. 그래서 규칙은 하나입니다.

> **원본은 읽기만. 새로 아는 것은 위키에 새 글로 쓴다.**

이 학습웹 자체도 같은 규칙을 씁니다 — 옛 자료를 담은 폴더는 읽기만 하고 고치지 않습니다.

## ③ 위키 글 한 편의 모양을 본다

원본을 복사해 오는 게 아니라 다시 씁니다. 위키 글 하나는 이렇게 생겼습니다.

```markdown
---
갱신: 2026-09-10
출처: 원본/2026-05-고객인터뷰-3건.md
---

# 환불 정책을 7일로 정한 이유

**결론** — 이용 시작 전 7일 이내 전액 환불. 시작 후에는 안 함.

인터뷰 3건에서 같은 말이 나왔다. "결제하고 나서 못 쓰게 될까 봐 무섭다."
불안의 대상은 금액이 아니라 **못 쓰게 되는 상황**이었다.

시작 후 환불을 열지 않는 이유는 [[결정기록-2026-05-환불]]에 있다.

관련 — [[약관-초안]] · [[가격표]] · [[CS-자주묻는것]]
```

세 가지가 들어 있습니다.

| 무엇 | 왜 |
|---|---|
| 출처 한 줄 | 나중에 원본으로 거슬러 갈 수 있다 |
| 결론이 맨 위 | AI도 사람도 첫 줄만 읽고 판단할 때가 많다 |
| 관련 링크 | [[09-지식운영/1-창고와위키|1절]]의 연결. 없으면 외톨이 글이 된다 |

**출처 없는 위키 글은 3개월 뒤에 못 씁니다.** 어디서 나온 건지 못 밝히기 때문입니다.

## ④ 지침 파일에 찾는 법을 더한다

`CLAUDE.md`는 [[03-컨텍스트하네스/_스테이지|Stage 3]]에서 이미 만들었습니다. 여기에 「이 볼트에서 찾는 법」 칸을 하나 만들고 아래 여섯 줄을 넣으면, AI가 매번 폴더 전체를 헤매지 않고 목차를 보듯 바로 갑니다.

```
- 위키/ 를 먼저 읽는다. 원본/ 은 위키에 없는 것을 확인할 때만 연다.
- 원본/ 은 절대 고치지 않는다. 새로 알게 된 것은 위키/ 에 새 글로 쓴다.
- 결정의 이유를 물으면 → 위키/결정기록-*.md
- 고객이 한 말을 물으면 → 위키/고객-*.md (원본은 원본/인터뷰-*)
- 숫자를 인용할 때는 반드시 출처 파일 이름을 함께 말한다.
- 위키에 근거가 없으면 "위키에 없습니다"라고 답한다. 지어내지 않는다.
```

마지막 두 줄이 가장 값이 큽니다. **출처를 대게 하고, 없으면 없다고 말하게 하는 것** — [[09-지식운영/6-구독자QA|6절]]에서 서비스에 붙이는 챗봇의 안전장치와 같은 원리입니다.

## ⑤ 링크가 끊기지 않게 설정한다

`[[환불-정책]]`이라는 링크는 파일 이름을 가리킵니다. 그 파일 이름을 「환불정책-최종」으로 바꾸는 순간 그 이름을 가리키던 링크가 전부 허공을 가리킵니다. 옵시디언 설정에서 이걸 막는 항목을 켜 두세요.

```json
{
  "alwaysUpdateLinks": true,
  "newLinkFormat": "shortest",
  "useMarkdownLinks": false
}
```

다만 한계가 있습니다. 파인더나 탐색기에서 이름을 바꾸거나 AI에게 `mv`로 옮기게 하면 옵시디언은 모르고 그냥 끊깁니다. 그래서 실무 규칙은 **파일 이름은 두고 안의 제목(`# `)만 고치는 것**입니다 — `2026-05-환불정책.md`처럼 날짜가 앞에 붙은 이름이 좋은 이유가 이것입니다.

무거운 폴더는 검색에서 빼 둡니다. 빌드 결과물·원자료 덤프·`.git`이 섞이면 찾을 때마다 쓰레기가 딸려 옵니다.

```json
{
  "userIgnoreFilters": ["재료/", "발행/", ".git/"]
}
```

빼면 검색·그래프·링크 자동완성에서만 사라지고 파일은 지워지지 않습니다. 지침 파일에도 *"`발행/`과 `재료/`는 읽지 않는다"* 한 줄을 더합니다.

## ⚡ 따라 하기

1. 볼트 폴더에 `원본/`과 `위키/` **두 폴더를 만듭니다.** 흩어져 있는 자료는 전부 `원본/`으로 옮기고 `위키/`는 비어 있는 채로 둡니다 — 위키는 옮기는 곳이 아니라 새로 쓰는 곳이기 때문입니다.
2. 옵시디언 `설정 → 파일과 링크`를 엽니다. 「제외할 파일」에 무거운 폴더를 넣고, 「항상 링크 업데이트」를 켜고, 첨부파일 위치를 폴더 하나로 지정합니다. 검색창에 무거운 폴더의 파일이 안 나오면 된 것입니다.
3. [[09-지식운영/1-창고와위키|1절]]에서 고른 다섯 개 중 하나를 골라 AI에게 이렇게 시킵니다.

```
원본/(파일이름) 을 읽고, 위키/ 에 새 파일로 다시 써줘.

형식:
- 맨 위 --- 칸에 갱신 날짜와 출처 파일 경로
- # 제목은 "무엇을 왜 정했나"가 드러나게
- 첫 줄은 **결론** 한 문장
- 본문은 근거만. 원본 문장을 그대로 옮기지 말고 다시 써줘
- 맨 아래 "관련 —" 줄에 이 볼트 안의 관련 파일을 [[ ]] 링크로

⚠️ 원본/ 안의 파일은 절대 고치지 마. 읽기만 해.
숫자나 날짜는 원본에 있는 것만 쓰고, 없으면 "원본에 없음"이라고 적어줘.
```

4. 결과 글의 숫자 하나를 원본과 대조합니다. 이 한 번의 대조가 앞으로 이 위키를 믿을 근거가 됩니다 — 원본 파일의 수정 날짜가 그대로인지도 같이 봅니다.
5. `CLAUDE.md`에 ④의 여섯 줄을 붙여넣고 폴더 이름을 내 것에 맞게 고칩니다.
6. 새 대화를 열고 *"환불 정책을 왜 그렇게 정했지? 근거가 된 파일 이름도 같이 알려줘."*라고 묻습니다. 답에 파일 이름이 나오면 지침이 읽힌 것이고, 안 나오면 ④로 돌아갑니다.

## ✅ 확인

- [ ] 볼트에 `원본/`과 `위키/` 두 폴더가 보이나
- [ ] 위키에 다시 쓴 글이 최소 한 개 있고, 그 글에 출처 파일 이름이 적혀 있나
- [ ] 원본 파일의 수정 날짜가 그대로인가
- [ ] AI가 답할 때 파일 이름을 대나

## 📘 말 풀이

**색인(index, 인덱스)** — 책 뒤에 붙은 「찾아보기」. 지침 파일에 적은 「무엇은 어디에」가 AI에게는 이 역할을 합니다.

**프런트매터(front matter)** — 마크다운 파일 맨 위에 `---` 사이로 적는 정보 칸. 갱신 날짜·출처처럼 본문은 아니지만 알아야 하는 것을 여기 적습니다.

## ⚠️ 함정

**파일 이름을 바꿉니다.** 이 절에서 가장 크게 다칠 수 있는 자리입니다. 이름은 주소이고 제목은 간판이니, 간판은 바꿔도 주소는 옮기지 않습니다.

**원본을 통째로 위키에 복사합니다.** 같은 내용이 두 벌이 되고 어느 쪽이 맞는지 아무도 모르게 됩니다. 위키에는 다시 쓴 것만 둡니다.

**첨부파일이 볼트 여기저기 흩어집니다.** 이미지를 붙여넣으면 기본값은 「지금 글과 같은 폴더」입니다. 첨부 폴더를 하나로 지정해 두면 위키 폴더가 깨끗해집니다.
