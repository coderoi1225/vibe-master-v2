## 왜 이걸 하나

2절에서 `.env.local` 파일에 값을 넣었습니다. 그게 무엇이고 왜 거기 넣었는지 모른 채 넘어가면,
언젠가 AI가 "값을 코드에 직접 넣을까요?" 하고 물었을 때 "네" 하고 눌러 버립니다.

그 다음에 일어나는 일은 정해져 있습니다. **저장소를 공개로 바꾸는 순간**, 또는
저장소 하나를 남에게 보여 주는 순간, 그 열쇠는 남의 손에 있습니다.
그리고 그 열쇠로 쓴 요금은 **나에게 청구됩니다.**

무섭게 하려는 말이 아닙니다. **이건 예방만 하면 되는 일이고, 예방은 10분이면 됩니다.**
대신 뒤늦게 알면 되돌릴 수가 없습니다. 그래서 결제를 붙이기 **전에** 합니다.

## 비밀값이 뭔가

`sk-ant-...` 처럼 생긴 긴 글자들입니다. **열쇠**라고 생각하면 정확합니다.

- 데이터베이스에 들어가는 열쇠
- AI 서비스에 요청을 보낼 때 "나야"라고 밝히는 열쇠
- **결제 회사에 "이 돈을 받아 달라"고 말할 수 있는 열쇠**

마지막 것이 특히 중요합니다. 이건 남이 가지면 **내 이름으로 결제를 만질 수 있는 열쇠**입니다.

## 그래서 코드가 아니라 파일 하나에 모아 둡니다

`.env.local` 이라는 파일 하나에 전부 모읍니다. 이름이 점(`.`)으로 시작해서 눈에 잘 안 띕니다.
그리고 이 파일은 **GitHub에 올라가지 않게** 미리 막아 둡니다.

같은 폴더에 `.env.example` 이라는 파일이 하나 더 있는 게 보통입니다.
이건 **값 없이 이름만 적힌 목록**입니다. "이런 값들이 필요하다"는 안내문이라
이건 올라가도 됩니다. 실제로 이렇게 생겼습니다.

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJxxx...
SUPABASE_SERVICE_KEY=eyJxxx...
TOSS_SECRET_KEY=test_sk_xxx...
```

**값이 `xxx`인 것이 핵심입니다.** 이름만 알려 주고 진짜 값은 안 알려 줍니다.

### 이름 앞에 붙는 `NEXT_PUBLIC_`이 무슨 뜻인가

이게 이 절에서 가장 중요한 한 가지입니다.

같은 파일 안에 있어도 **둘은 완전히 다릅니다.**

| 이름 | 어디까지 가나 |
|---|---|
| `NEXT_PUBLIC_`으로 시작 | **브라우저까지 나갑니다.** 누구나 볼 수 있습니다 |
| 그냥 시작 | 서버 안에만 있습니다. 사용자는 못 봅니다 |

`NEXT_PUBLIC_`은 "공개해도 되는 값"이라는 **표시**입니다. 숨겨 주는 게 아니라 **내보내는** 것입니다.

그래서 다음 두 개는 절대 하면 안 됩니다.

```
NEXT_PUBLIC_SUPABASE_SERVICE_KEY=...   ← 절대 안 됩니다
NEXT_PUBLIC_TOSS_SECRET_KEY=...        ← 절대 안 됩니다
```

**모든 권한을 가진 열쇠와 결제 열쇠를 브라우저에 뿌리는 것**이기 때문입니다.
`anon` 키처럼 원래 공개용으로 만들어진 값만 이 접두사를 씁니다.

AI가 "브라우저에서 값을 못 읽는다"는 오류를 고치려고 **앞에 `NEXT_PUBLIC_`을 붙이자고 할 때가 있습니다.**
그때 눌러 버리는 게 실제로 가장 흔한 사고 경로입니다. 결제·관리자 열쇠에서는 **아니오**라고 답합니다.

## 📘 말 풀이

**환경변수(environment variable)**
프로그램 밖에서 넣어 주는 값. 코드는 "여기에 열쇠가 들어온다"고만 적어 두고,
진짜 열쇠는 코드가 아니라 파일이나 배포 서비스 설정에서 받아 옵니다.
그래서 같은 코드로 연습용과 진짜 서비스를 둘 다 돌릴 수 있습니다.

**.gitignore**
"이 파일들은 GitHub에 올리지 마라"고 적어 두는 목록 파일.
여기에 `.env.local`이 적혀 있어야 합니다. 이게 첫 번째 방어선입니다.

**재발급(rotate)**
열쇠를 새로 만들고 옛것을 못 쓰게 죽이는 것. 열쇠가 밖에 나갔을 때
할 수 있는 **유일한 진짜 조치**입니다.

## ⚠️ 자주 걸리는 함정

- **한 번 올라간 비밀값은 지워도 남습니다.**
  이게 이 절에서 꼭 기억할 한 가지입니다.
  파일에서 지우고 다시 커밋해도, **옛날 기록 안에 그대로 살아 있습니다.**
  GitHub에서 옛 커밋을 열면 그 값이 그대로 보입니다.
  누군가는 공개 저장소를 자동으로 훑으면서 열쇠를 줍고 있고, 보통 **몇 분 안에** 줍습니다.

  그래서 대응 순서가 정해져 있습니다.

  1. **새 열쇠를 발급받는다**
  2. **옛 열쇠를 폐기(revoke)한다** — 이게 진짜 조치입니다
  3. 새 값을 `.env.local`과 배포 서비스에 넣는다
  4. 저장소 기록을 정리하는 건 **그 다음**입니다

  순서를 바꾸지 마세요. 기록 정리부터 하면, 정리하는 동안 옛 열쇠는 여전히 살아 있습니다.
  **지우는 게 아니라 바꾸는 것입니다.**

- **비공개 저장소니까 괜찮다고 생각한다** — 비공개는 오늘의 상태일 뿐입니다.
  나중에 공개로 바꾸거나, 남에게 보여 주거나, 협업자를 넣는 순간 기록째로 넘어갑니다.

- **AI 대화창에 열쇠를 그대로 붙여넣는다** — 오류를 물어보다가 값째로 붙이는 일이 흔합니다.
  값 자리는 `xxx`로 바꿔서 붙입니다.

- **화면 캡처에 값이 찍혀 있다** — 터미널 캡처를 그대로 올리면 같습니다.

- **배포 서비스에 넣고 다시 배포를 안 한다** — 넣기만 하면 반영이 안 됩니다. 다시 배포해야 읽습니다.

- **다른 프로젝트의 열쇠를 돌려 쓴다** — 하나가 새면 전부 다시 발급받아야 합니다. 프로젝트마다 따로 만듭니다.

## ⚡ 이렇게 하세요

### 1. 막혀 있는지 먼저 확인합니다

```bash
cat .gitignore | grep -n "env"
```

`.env.local` 또는 `.env*.local`이 보이면 됩니다. 안 보이면 한 줄 넣습니다.

```bash
echo ".env.local" >> .gitignore
```

### 2. 이미 올라간 게 있는지 봅니다

```bash
git ls-files | grep -iE "^\.env|\.env$|\.env\."
```

**아무것도 안 나오면 정상입니다.** 나오면 그 파일은 이미 GitHub에 있습니다.
위의 「지워도 남습니다」 순서대로 **새로 발급**부터 합니다.

### 3. 코드 안에 열쇠가 박혀 있는지 검색합니다

```bash
git grep -nE "sk-ant-|service_role|SECRET_KEY *= *[\"'][A-Za-z0-9_-]{12,}" -- . ":(exclude).env*"
```

여기서 뭔가 나오면 그 자리를 환경변수로 바꿉니다.

### 4. 커밋 전 습관을 몸에 붙입니다 — 이게 이 절의 핵심입니다

커밋하기 직전에 **매번** 이 한 줄을 칩니다.

```bash
git diff --cached --name-only | grep -iE "\.env$|token|secret|credential|\.key$|\.pem$"
```

**아무것도 안 나오면 커밋합니다. 뭔가 나오면 커밋을 멈추고 그 파일부터 봅니다.**

기억에 기대지 말고 AI 지침 파일([[03-컨텍스트하네스/_스테이지|Stage 3]]에서 만든 것)에도 적어 둡니다.

```
비밀값 규칙 (반드시 지킬 것)
- API 키·토큰·비밀번호를 코드 파일에 직접 쓰지 않는다. 반드시 환경변수로.
- 결제 키와 관리자 권한 키에는 NEXT_PUBLIC_ 접두사를 절대 붙이지 않는다.
- 커밋 전에 스테이징된 파일 목록에서 .env·token·secret·key·pem 을 확인한다.
- 값이 밖에 나갔으면 지우지 말고 먼저 새로 발급받고 옛 키를 폐기한다.
```

### 5. 세 곳의 값이 같은지 맞춰 둡니다

| 어디 | 무엇이 있어야 하나 |
|---|---|
| `.env.local` (내 컴퓨터) | 진짜 값 |
| `.env.example` (GitHub에 올라감) | 이름만, 값은 `xxx` |
| 배포 서비스 설정 | 진짜 값 — 넣은 뒤 **다시 배포** |

## ✅ 됐는지 확인

- [ ] `.gitignore`에 `.env.local`이 **적혀 있나**
- [ ] `git ls-files`로 찾았을 때 `.env` 파일이 **하나도 안 나오나**
- [ ] **비밀값이 코드에 없나 — 검색해서 확인했나** (기억이 아니라 검색으로)
- [ ] `NEXT_PUBLIC_`이 붙은 값 중에 **공개되면 안 되는 것이 하나도 없나**
- [ ] 커밋 직전에 칠 확인 명령을 **어디에 적어 뒀는지 말할 수 있나**
- [ ] 배포된 주소가 여전히 잘 도나 (배포 쪽 값도 넣고 다시 배포했나)

세 번째가 이 장 전체의 자가 체크에 그대로 들어갑니다.
