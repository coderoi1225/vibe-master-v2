## 왜 이걸 하나

내 화면에서는 다 됩니다. 그런데 남의 기기에서는 안 됩니다.
브라우저가 다르고, 화면 크기가 다르고, 인터넷이 끊기고, 내가 안 넣어 본 값을 넣습니다.

그때 사용자가 어떻게 하는지 아세요? **아무 말 없이 나갑니다.**
"오류가 났어요"라고 알려 주는 사람은 백 명 중 한두 명입니다. 나머지는 그냥 안 돌아옵니다.

그래서 **오류가 나에게 오게 만드는 장치**가 필요합니다.
결제를 붙인 다음에 하는 이유가 있습니다. **결제와 로그인에서 나는 오류는 곧 돈**이기 때문입니다.

## 오류가 나에게 오는 길

```
사용자 기기에서 오류가 남
        │
        │  작은 조각이 자동으로 보내진다
        │  (어느 화면, 어떤 오류, 어떤 브라우저)
        ▼
   에러 수집 서비스          ← Sentry 같은 곳
        │
        │  같은 오류는 하나로 묶어서 센다
        ▼
   내 휴대폰 알림 / 대시보드
```

한 번 붙여 두면 그 다음부터는 자동입니다. 코드에 몇 줄 넣고 열쇠 하나를 넣으면 끝납니다.

## 왜 별도 서비스를 쓰나 — 로그를 보면 되지 않나

배포 서비스에도 기록(로그)이 남습니다. 하지만 그것만으로는 부족합니다.

| | 배포 서비스 로그 | 에러 수집 서비스 |
|---|---|---|
| 브라우저에서 난 오류 | **안 보입니다** | 보입니다 |
| 같은 오류 백 번 | 백 줄 | **한 덩어리로 묶어 "100회"** |
| 처음 난 오류 알림 | 없음 | 있음 |
| 어느 줄에서 났나 | 압축돼서 안 보임 | 원래 줄을 보여 줄 수 있음 |

첫 줄이 큽니다. 사용자가 겪는 오류의 상당수는 **그 사람 브라우저 안에서** 납니다.
서버 기록에는 아무것도 안 남습니다. 그래서 "아무 문제 없는데요"가 됩니다.

### 압축된 코드와 원래 줄 — 소스맵

1절에서 배포할 때 **빌드**를 한다고 했습니다. 빌드는 코드를 잘게 압축합니다.
그래서 배포본에서 난 오류를 보면 `a.b is not a function` 같은, 아무 데도 못 찾을 말이 나옵니다.

이 압축본과 원래 코드를 이어 주는 지도 같은 파일이 있는데 그걸 **소스맵**이라고 합니다.
이걸 에러 수집 서비스에 같이 올려 두면 **"어느 파일 몇 번째 줄"**로 보여 줍니다.
설정 한 번이면 되고, 안 하면 오류를 봐도 어디인지 모릅니다.

## 무료 한도는 대개 여기서 먼저 걸립니다

이 커리큘럼에서 쓰는 서비스들 중 **무료 구간이 가장 먼저 바닥나는 게 에러 수집**입니다.
데이터베이스도 배포도 아닙니다.

이유는 간단합니다. **오류 하나가 백 번, 천 번 납니다.**
사용자 한 명이 새로고침을 열 번 하면 같은 오류가 열 번 올라갑니다.
그러다 며칠 만에 한 달 치를 다 씁니다. 그러면 **정작 중요한 오류가 났을 때 안 받아 줍니다.**

막는 법은 셋입니다.

1. **무시 목록을 만듭니다** — 내가 고칠 수 없는 것들을 애초에 안 보냅니다.
   브라우저 확장 프로그램이 내는 오류, 인터넷이 끊겨서 나는 오류, 광고 차단기가 내는 오류.
   이것들이 보통 절반 넘게 차지합니다.
2. **일부만 보냅니다** — 같은 오류를 다 보낼 필요가 없습니다. 열에 하나만 보내도 있다는 건 압니다.
   단, **결제와 로그인에서 나는 오류는 전부 보냅니다.**
3. **고친 건 닫습니다** — 해결한 오류를 닫아 두면, 다시 나타났을 때 알려 줍니다.

## 알림은 켜되, 과하게 켜지 않습니다

**알림이 하루에 스무 개 오면 사람은 알림을 끕니다.** 그리고 끈 다음에 진짜 사고가 납니다.
과하게 켜는 게 안 켜는 것보다 나쁩니다.

기준은 **하나**로 잡습니다.

> **지금 사용자에게 보이는 문제인가?**

이 물음에 **예**면 부릅니다. **아니오**면 하루에 한 번 모아서 봅니다.

| 언제 | 어떻게 |
|---|---|
| **결제·로그인 경로에서 난 오류** | 즉시 휴대폰으로 |
| **한 번도 본 적 없는 새 오류** | 즉시 (처음 한 번만) |
| 이미 아는 오류가 또 남 | 안 부릅니다 |
| 오류 수가 갑자기 확 늘었을 때 | 즉시 |
| 나머지 전부 | **하루 한 번 묶어서** |

세 번째가 핵심입니다. **이미 아는 오류는 다시 부르지 않습니다.**
알림이 시끄러워지는 이유의 대부분이 이것입니다.

이 기준은 [[08-자율운영/_스테이지|Stage 8]]에서 그대로 이어집니다. 거기서는 이 기준으로
**무엇을 자동으로 두고 무엇에 나를 부를지**를 정합니다. 여기서 잘못 켜 두면 거기서 두 배로 시끄러워집니다.

## 📘 말 풀이

**에러 수집(error tracking)**
사용자 기기에서 난 오류를 자동으로 모아 보여 주는 서비스.
같은 오류를 하나로 묶어 세고, 처음 나는 오류에 알림을 줍니다.

**DSN**
에러 수집 서비스가 주는 주소 겸 열쇠. "이 오류를 어디로 보낼지"를 가리킵니다.
브라우저 쪽에 나가는 값이라 공개돼도 되게 만들어져 있지만,
**같은 화면에서 주는 다른 토큰(소스맵을 올릴 때 쓰는 것)은 공개되면 안 됩니다.** 3절대로 다룹니다.

**소스맵(source map)**
압축된 배포 코드와 원래 코드를 이어 주는 지도 파일.
이게 있어야 오류가 "어느 파일 몇 번째 줄"로 보입니다.

## ⚠️ 자주 걸리는 함정

- **개인정보가 오류 기록에 딸려 갑니다.** 이게 이 절에서 가장 조심할 것입니다.
  오류가 날 때 그 순간의 값들이 같이 담기는데, 거기에 **이메일·전화번호·로그인 토큰**이
  섞여 들어갑니다. 그러면 남의 개인정보를 **또 다른 회사에 넘기고 있는 것**이 됩니다.
  - 개인정보를 지우고 보내는 설정을 **켜 둡니다**
  - 어느 나라 회사에 맡기고 있는지 개인정보 처리방침에 적습니다 → [[부록/_스테이지|부록]]의 「법무·세무」
- **켜 놓고 안 봅니다** — 붙이는 것보다 **첫 알림을 실제로 받아 보는 것**이 중요합니다.
  받아 보지 않으면 오류가 나도 안 옵니다. 그리고 그걸 모릅니다.
- **알림을 다 켭니다** — 며칠 만에 알림을 끄게 됩니다. 위 표대로 시작합니다.
- **소스맵을 안 올립니다** — 오류를 봐도 어딘지 몰라서 결국 안 보게 됩니다.
- **소스맵을 아무나 볼 수 있게 배포합니다** — 내 코드를 통째로 공개하는 셈입니다.
  에러 수집 서비스에 **올리기만 하고**, 배포된 사이트에는 안 남게 합니다.
- **테스트 오류를 안 내 보고 됐다고 합니다** — 일부러 한 번 터뜨려 봐야 확인입니다.

## ⚡ 이렇게 하세요

**1. 에러 수집 서비스에 가입하고 프로젝트를 하나 만듭니다.** Sentry가 가장 무난합니다.
만들면 DSN을 하나 줍니다.

**2. 붙입니다.** AI에게 시킵니다.

```
이 프로젝트에 Sentry로 에러 수집을 붙여줘. 조건은 이렇다.

- DSN은 환경변수로 받는다. 코드에 직접 쓰지 않는다.
- 소스맵을 업로드하되, 배포된 사이트에서는 소스맵이 공개되지 않게 한다.
- 오류를 보낼 때 개인정보를 지운다 — 이메일, 전화번호, 인증 토큰, 쿠키를 제거한다.
- 아래 오류는 아예 보내지 않는다:
  브라우저 확장 프로그램이 내는 오류, 네트워크 끊김, 광고 차단기가 내는 오류.
- 결제와 로그인 경로의 오류는 전부 보낸다. 나머지는 일부만 보내도 된다.

먼저 고칠 파일과 추가할 환경변수 목록을 보여줘.
```

**3. 값을 넣습니다.** 3절대로 `.env.local`과 배포 서비스 양쪽에 넣고 **다시 배포**합니다.
소스맵 업로드용 토큰에는 `NEXT_PUBLIC_`을 붙이지 않습니다.

**4. 알림 규칙을 위 표대로 세 개만 만듭니다.** 처음부터 많이 만들지 않습니다.

- 처음 보는 새 오류 → 즉시
- 결제·로그인 경로 오류 → 즉시
- 나머지 → 하루 한 번 묶어서

**5. 일부러 터뜨려 봅니다.** 배포된 주소에 오류를 내는 페이지를 하나 잠깐 만들어 열어 봅니다.
그리고 **휴대폰에서 알림이 오는지** 봅니다.

**6. 일주일 뒤에 한 번 봅니다.** 쓸데없는 오류가 대부분이면 무시 목록에 넣습니다.
이 정리를 안 하면 무료 한도가 금방 찹니다.

## ✅ 됐는지 확인

- [ ] 배포된 주소에서 오류를 냈을 때, **에러 수집 화면에 그 오류가 보이나**
- [ ] 그 오류에 **어느 파일 몇 번째 줄인지**가 보이나 (소스맵이 올라갔나)
- [ ] **휴대폰에서 알림을 실제로 봤나** (설정만 한 게 아니라)
- [ ] 오류 내용에 **이메일·전화번호·토큰이 안 담겨 있나** — 열어서 확인했나
- [ ] 알림 규칙이 **세 개 이하**인가
- [ ] 이미 아는 오류가 또 났을 때 **알림이 안 오나**
- [ ] 무료 한도가 얼마이고 지금 얼마나 썼는지 **화면에서 확인할 줄 아나**

세 번째와 네 번째가 이 절의 핵심입니다.
