2절에서 표를 만들었는데 목록이 비어 있었을 겁니다. "자기 것만 볼 수 있다"는 규칙이 켜져 있는데
**아직 "자기"가 없기 때문**입니다. 로그인이 붙어야 그 규칙이 뜻을 갖습니다.

그리고 결제는 로그인 없이는 못 붙입니다. 돈을 낸 사람과 서비스를 받는 사람이
**같은 사람이라는 걸 증명할 방법**이 없으니까요.

## ① 비밀번호를 직접 받으면 안 되나요

받을 수는 있습니다. 하지만 그 순간 **남의 비밀번호를 보관하는 사람**이 됩니다.

- 비밀번호를 안전하게 저장하는 법을 알아야 합니다(그냥 저장하면 안 됩니다)
- 비밀번호 찾기 화면과 메일 보내기를 만들어야 합니다
- 새어 나가면 **내 책임**입니다. 그리고 사람들은 같은 비밀번호를 다른 곳에도 씁니다

혼자 만드는 사람에게 이건 **안 하는 게 이깁니다.**

## ② 소셜 로그인 — 카카오에게 대신 확인시킨다

"카카오로 시작하기" 버튼 하나를 답니다. 그러면 이렇게 됩니다.

- **비밀번호가 내 서비스에 아예 들어오지 않습니다.** 없는 것은 새어 나갈 수 없습니다.
- 한국 사용자는 **이미 카카오 계정이 있습니다.** 가입 화면에서 떠나는 사람이 확 줍니다.
- 비밀번호 찾기·재설정 화면을 안 만들어도 됩니다.

혼자 만드는 사람에게 유리한 이유가 셋 다 **"안 만들어도 되는 것"**이라는 데 있습니다.

### 흐름 — 여섯 걸음

```
① 사용자가 내 사이트에서 [카카오로 시작하기] 를 누른다
                    │
                    ▼
② 카카오 로그인 화면으로 넘어간다      ← 내 사이트가 아닙니다
                    │
③ 사용자가 동의를 누른다               ← 비밀번호는 여기서만 오갑니다
                    │
                    ▼
④ 카카오가 "이 사람 맞다"는 표를 들려서
   내가 미리 등록해 둔 주소로 돌려보낸다    ← 이 주소가 콜백 주소
                    │
                    ▼
⑤ 내 서버가 그 표를 확인하고 세션을 만든다  ← 이제 "누구인지"를 안다
                    │
                    ▼
⑥ users 표에 그 사람 한 줄이 생긴다
```

**④가 이 절에서 유일하게 손으로 설정하는 자리입니다.** 그리고 여기서 거의 모두가 한 번 막힙니다.
카카오는 아무 주소로나 사람을 돌려보내 주지 않습니다. **내가 미리 등록해 둔 주소로만** 보냅니다.
등록을 안 했거나 한 글자 다르면 로그인이 끝나고 빈 화면이 뜹니다.

### ⑥은 자동으로 되게 해 둡니다

로그인이 됐다고 내 표에 사람이 저절로 생기지는 않습니다. 그래서 보통
**"인증 쪽에 새 사람이 생기면 내 `users` 표에도 한 줄 만들어라"**는 규칙을 데이터베이스에 심어 둡니다.
2절에서 실행한 스키마 파일 안에 이미 들어 있는 경우가 많습니다.
없으면 이때 넣습니다. 안 넣으면 **로그인은 되는데 내 표는 계속 비어 있는** 이상한 상태가 됩니다.

## 📘 말 풀이

**소셜 로그인(OAuth)**
비밀번호 확인을 카카오·구글 같은 곳에 맡기고, 나는 "확인됐다"는 표만 받는 방식.
비밀번호가 내 서비스로 들어오지 않는 게 핵심입니다.

**콜백 주소(redirect URI)**
카카오가 확인을 끝낸 뒤 사용자를 되돌려보낼 내 사이트의 주소.
미리 등록한 주소로만 보내 줍니다. 로그인 사고의 절반이 여기서 납니다.

**세션(session)**
"지금 이 브라우저는 이 사람"이라는 상태. 로그인 뒤 한동안 유지돼서
페이지를 옮겨도 다시 로그인하지 않아도 됩니다.

## ⚠️ 함정

- **로그인은 됐는데 빈 화면이나 오류로 떨어진다** — 콜백 주소가 등록이 안 됐거나 다릅니다.
  등록할 곳이 **두 군데**입니다. 카카오 개발자 화면과 데이터베이스 서비스의 인증 설정.
  그리고 **내 컴퓨터 주소(`http://localhost:3000/...`)와 배포 주소를 둘 다** 넣어야 합니다.
  하나만 넣으면 로컬에서는 되고 배포본에서는 안 되거나, 그 반대가 됩니다.

- **배포 주소가 바뀌었는데 등록을 안 고쳤다** — 미리보기 배포는 주소가 매번 다릅니다.
  로그인 확인은 **고정된 주소**에서 합니다.

- **인증 라이브러리를 함부로 올린다 — 이게 가장 아픕니다.**
  인증 도구 중에는 **켜질 때 데이터베이스 표 구조가 자기가 아는 모양과 같은지 검사하는 것**이 있고,
  그 검사가 **실서비스에서는 기본으로 켜져 있습니다.**
  판을 올리면서 기대하는 표 모양이 조금만 바뀌어도, 검사에 걸려 **로그인이 통째로 막힙니다.**
  더 나쁜 건 이게 **내 컴퓨터에서는 안 나고 배포본에서만 난다**는 것입니다.
  - 인증 관련 도구는 **이유 없이 올리지 않습니다.**
  - 올려야 하면 **혼자 따로** 올립니다. 다른 것과 같이 올리면 무엇이 깼는지 못 찾습니다.
  - 올린 뒤 **로그인을 실제로 한 번 해 보기 전에는 넘어가지 않습니다.**
  - AI가 "패키지를 최신으로 정리했습니다"라고 할 때, **인증 쪽이 같이 올라갔는지 확인합니다.**

- **로그인이 되니 다 된 줄 안다** — 로그인의 목적은 "들어가기"가 아니라 **"남의 것을 못 보게 하기"**입니다.
  다른 계정으로 들어가서 앞 사람 데이터가 보이면, 로그인이 붙은 게 아니라 문만 달린 것입니다.

- **필요 없는 정보까지 받는다** — 동의 항목을 다 켜 두면 사용자는 겁먹고 나갑니다.
  그리고 받은 정보는 **지켜야 할 책임**이 됩니다. 정말 쓰는 것만 켭니다.

## ⚡ 따라 하기

**1. 카카오 개발자 사이트에서 애플리케이션을 하나 만듭니다.**
카카오 로그인을 켜고, 받을 정보는 **최소한만** 고릅니다(대개 닉네임과 이메일이면 충분합니다).

**2. 콜백 주소를 등록합니다.** 데이터베이스 서비스(Supabase)의 인증 설정에 있는
콜백 주소를 그대로 복사해서 카카오 쪽에 붙여넣습니다.

**3. 데이터베이스 서비스 쪽에서 카카오를 켭니다.**
Authentication → Providers → Kakao를 켜고, 카카오에서 받은 키를 넣습니다.
같은 화면의 URL 설정에 **내 배포 주소와 `http://localhost:3000`을 둘 다** 넣습니다.

**4. 화면에 버튼을 답니다.** AI에게 이렇게 시킵니다.

```
이 프로젝트에 카카오 소셜 로그인을 붙여줘. 조건은 이렇다.

- Supabase Auth의 카카오 provider를 쓴다. 인증 로직을 직접 만들지 않는다.
- 로그인 버튼, 콜백을 받는 페이지, 로그아웃 버튼 세 개만 만든다.
- 로그인한 사람만 볼 수 있는 페이지를 하나 정하고, 로그인 안 했으면 로그인 화면으로 보낸다.
- 새 키나 패키지를 추가해야 하면 먼저 무엇을 왜 추가하는지 말하고 멈춰라.
- 인증 관련 패키지의 버전은 지금 잠겨 있는 그대로 두고 올리지 마라.

먼저 어떤 파일을 만들고 고칠지 목록만 보여줘. 내가 확인하면 그때 실행해.
```

**5. 표에 사람이 생기는지 확인합니다.** 로그인한 뒤 `users` 표를 열어 봅니다.
줄이 안 생겼으면 자동 생성 규칙이 없는 것입니다. 이렇게 물어봅니다.

```
Supabase Auth로 새 사용자가 만들어질 때 public.users 표에도 한 줄이 자동으로 생기게 하고 싶다.
지금 supabase 스키마 파일에 그 트리거가 있는지 확인하고, 없으면 추가할 SQL을 보여줘.
실행은 내가 SQL Editor에서 직접 한다.
```

**6. 계정 두 개로 확인합니다.** 이게 진짜 확인입니다.
계정 A로 로그인해서 데이터를 하나 만들고, 로그아웃하고, **계정 B로 로그인해서
A의 데이터가 안 보이는지** 봅니다. 보이면 권한 규칙이 안 걸린 것입니다.

## ✅ 확인

- [ ] 카카오 버튼을 눌렀을 때 **카카오 화면으로 넘어가나**
- [ ] 동의 후 **내 사이트로 돌아오나** (빈 화면이나 오류가 아니라)
- [ ] 돌아온 뒤 화면에 **내 이름이나 이메일이 보이나**
- [ ] `users` 표에 **내 줄이 생겼나**
- [ ] **다른 계정으로 로그인했을 때 앞 사람 데이터가 안 보이나**
- [ ] **배포된 주소에서도** 로그인이 되나 (내 컴퓨터에서만이 아니라)
- [ ] 로그아웃하면 로그인해야만 볼 수 있는 화면이 **막히나**

다섯 번째가 이 절의 목적입니다. 나머지가 다 되고 그것만 «아니오»면 로그인이 아직 안 붙은 것입니다.
