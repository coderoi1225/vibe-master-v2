지금 화면에 이름 하나를 입력하면 목록에 뜹니다. 잘 돌아가는 것처럼 보입니다.
그런데 **새로고침을 하면 사라집니다.** 또는 다른 기기에서 열면 없습니다.

AI에게 화면을 만들어 달라고 하면 대부분 **가짜 데이터**를 넣어 줍니다.
그게 나쁜 게 아닙니다. 화면 모양을 먼저 보라고 넣어 준 것입니다.
문제는 **그걸 진짜라고 착각한 채로 다음 단계로 가는 것**입니다.
로그인을 붙여도 저장될 곳이 없고, 결제를 받아도 누가 냈는지 남지 않습니다.

이 절에서 **처음으로 진짜 데이터가 생깁니다.**

## ① 지금 그 숫자는 어디서 오나 — 셋 중 하나입니다

| 어디 | 어떻게 알아보나 | 진짜인가 |
|---|---|---|
| **코드에 박혀 있다** | 새로고침해도 늘 똑같은 이름·똑같은 숫자 | 아니오 |
| **브라우저에만 있다** | 새로고침해도 남는데, **다른 기기에서는 없다** | 아니오 |
| **데이터베이스에 있다** | 다른 기기, 다른 사람 화면에서도 같다 | 예 |

두 번째가 특히 헷갈립니다. 새로고침해도 남으니까 저장된 것 같습니다.
하지만 그건 **그 브라우저 안에만** 있습니다. 브라우저 기록을 지우면 같이 사라집니다.

## ② 데이터베이스는 결국 표(table)입니다

엑셀 시트를 떠올리면 거의 맞습니다. 차이는 **규칙이 세다**는 것뿐입니다.

- **표(테이블)** = 시트 한 장. `구독자` 표, `발송기록` 표.
- **열(컬럼)** = 시트의 세로 칸. 이름·이메일·가입일.
- **행(row)** = 가로 한 줄. 사람 한 명, 결제 한 건.

엑셀과 다른 점은 열마다 **"여기엔 이런 것만 들어온다"**를 미리 정해 둔다는 것입니다.
가입일 칸에 "몰라요"를 못 넣습니다. 그래서 나중에 데이터가 안 썩습니다.

그 "미리 정해 둔 것"을 글로 적어 놓은 파일이 **스키마 파일**입니다.
보통 프로젝트 안 `supabase/schema.sql` 같은 자리에 있습니다.

### 관통 프로젝트(AI 뉴스레터)의 표는 다섯 개입니다

| 표 | 무엇을 담나 |
|---|---|
| `users` | 가입한 사람 |
| `subscriptions` | 누가 어떤 요금제를 언제부터 쓰나 · 다음 결제일 |
| `newsletters` | 보낼 글 |
| `send_logs` | 누구에게 언제 보냈고 열어 봤나 |
| `webhook_events` | 결제사가 보내온 알림 (5절에서 씁니다) |

**표를 다섯 개나 미리 만드는 이유**가 있습니다. 나중에 결제와 해지를 붙일 때
넣을 자리가 없으면 표를 뜯어고쳐야 하는데, 그때는 이미 진짜 사람의 데이터가 들어 있습니다.
**빈 표를 고치는 건 5분이고, 데이터가 든 표를 고치는 건 하루입니다.**

## ③ 데이터베이스 서비스는 네 가지를 같이 줍니다

혼자 만들 때 데이터베이스만 따로 구하고, 로그인은 또 따로 구하고 하면 연결하는 데만 며칠이 갑니다.
Supabase 같은 서비스를 쓰는 이유는 **네 개가 한 곳에 붙어 있어서**입니다.

| 역할 | 무엇 | 이 커리큘럼에서 |
|---|---|---|
| **저장** | 표에 데이터를 담는다 | 이 절 |
| **인증** | 누가 로그인했는지 관리한다 | 4절 |
| **파일** | 사진·PDF를 올려 둔다 | 프로필 사진 정도 |
| **실시간·서버 함수** | 값이 바뀌면 바로 알려 주고, 서버에서 도는 작은 프로그램을 둔다 | 5절의 결제 알림 받기 |

**네 개를 한꺼번에 켤 필요는 없습니다.** 오늘은 첫 번째만 켭니다.

### 개인정보가 어느 나라에 사는지는 알아 두세요

데이터베이스를 만들 때 **지역(region)**을 고릅니다. 서울을 고를 수 있으면 서울로 합니다.
빨라서만이 아닙니다. 사용자의 개인정보를 **어느 나라 회사에 맡기고 있는지**를
개인정보 처리방침에 적어야 하기 때문입니다. 자세한 건 [[부록/_스테이지|부록]]의 「법무·세무」에 있습니다.

## ④ API와 JSON — 화면과 표 사이의 심부름꾼

화면(브라우저)이 데이터베이스를 직접 뒤지게 두면 안 됩니다. 누구든 남의 것을 볼 수 있게 되니까요.
그래서 사이에 **창구**를 하나 둡니다. 화면은 창구에만 말하고, 창구가 표를 대신 봅니다. 이 창구가 **API**입니다.

식당으로 치면 손님(화면)이 웨이터(API)에게 주문하고, 웨이터가 주방(서버)과 창고(표)를 오갑니다.
손님이 창고에 직접 들어가지 않습니다.

주고받는 종이의 양식이 정해져 있는데 그게 **JSON**입니다. 이렇게 생겼습니다.

```json
{
  "name": "이준호",
  "plan": "monthly",
  "topics": ["IT", "AI"],
  "active": true
}
```

읽는 법은 네 가지면 끝납니다.

1. `"이름": 값` — 이름 옆에 콜론
2. `[ ]` — 여러 개 묶음
3. `{ }` — 한 덩어리 (안에 또 들어갈 수 있음)
4. 글자는 따옴표, 숫자와 `true`/`false`는 따옴표 없음

## 📘 말 풀이

**API**
화면과 데이터베이스 사이의 창구. 화면은 표를 직접 못 보고 창구에만 말합니다.
"이 사람 정보 줘", "이 줄 새로 넣어 줘" 같은 부탁을 받는 자리입니다.

**JSON**
그 창구가 주고받는 종이의 정해진 양식. `{ "이름": 값 }` 꼴로 생겼습니다.
사람이 눈으로 읽을 수 있는 형태라, 오류가 나면 여기를 보면 대개 보입니다.

**표(table)와 열(column)**
표는 엑셀 시트 한 장, 열은 그 세로 칸. 열마다 "여기엔 이런 것만 들어온다"가
미리 정해져 있고, 그 정해 둔 내용을 적은 파일이 스키마 파일입니다.

## ⚠️ 함정

### 일주일 쉬면 데이터베이스가 잠듭니다

**무료 데이터베이스는 1주 동안 아무도 안 쓰면 일시정지됩니다.** (2026-09-09 공식 요금 페이지 확인)

배우는 사람이 가장 자주 걸리는 자리입니다. 주말을 끼고 며칠 쉬었다 돌아오면
**어제까지 되던 화면이 오늘 안 됩니다.** 코드를 고친 적이 없는데 말입니다.

**고장이 아닙니다.** 대시보드에 들어가 다시 켜면 됩니다. 데이터도 그대로 있습니다.
다만 **깨우는 데 몇 분 걸리니**, 남에게 보여주기로 한 날 아침에 미리 한 번 열어 두세요.

무료로 **활성 프로젝트는 2개까지**입니다. 연습용을 여러 개 만들다 보면 여기서도 막힙니다.


- **연결이 안 됐는데 잘 되는 줄 안다** — 가장 위험한 함정입니다.
  잘 만든 프로젝트일수록 **연결이 없으면 조용히 가짜 데이터로 돕니다.** 오류를 안 냅니다.
  실제로 이런 코드가 들어 있습니다.

```ts
export function isSupabaseConfigured() {
  return Boolean(process.env.NEXT_PUBLIC_SUPABASE_URL && process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY);
}
```

  값 두 개가 없으면 `false`를 돌려주고, 화면은 **미리 넣어 둔 데모 데이터**를 보여 줍니다.
  화면만 보면 다 된 것 같습니다. **표를 직접 열어 보기 전까지는 됐다고 하지 않습니다.**

- **응답은 성공인데 목록이 비어 있다** — 거의 항상 **행 단위 권한(RLS)** 때문입니다.
  "자기 것만 볼 수 있다"는 규칙이 켜져 있는데 아직 로그인을 안 했으니, 내 것이 하나도 없는 게 맞습니다.
  오류가 아닙니다. 4절에서 로그인을 붙이면 풀립니다.
  **급하다고 이 규칙을 꺼 놓고 그대로 배포하지 마세요.** 끄면 아무나 남의 줄을 볼 수 있습니다.

- **스키마를 두 번 실행해서 오류가 난다** — "이미 있다"는 오류면 이미 만들어진 것입니다. 정상입니다.

- **로컬은 되는데 배포본만 죽는다** — 배포 서비스 쪽에도 값을 따로 넣어야 합니다.
  내 컴퓨터의 파일은 배포 서비스가 못 봅니다. 넣은 뒤 **다시 배포**해야 반영됩니다.

- **표는 만들었는데 화면이 텅 비어 있다** — 표가 비어 있으면 화면도 빕니다.
  스키마 파일 맨 아래에 넣어 둔 **시드(seed) 데이터** 몇 줄을 같이 실행하면 눈으로 확인하기 쉽습니다.

## ⚡ 따라 하기

### 실습 — 스키마 파일은 있는데 연결이 안 된 프로젝트를 연결한다

손에 든 프로젝트 중에 이런 게 하나쯤 있습니다.
`supabase/schema.sql`은 만들어져 있는데, 데이터베이스에 연결이 안 돼서 **데모 데이터로 도는 것.**
화면은 멀쩡하고 클릭도 되니 다 된 것 같지만, 새로고침하면 원래대로 돌아갑니다.
이걸 오늘 진짜로 연결합니다.

**1. 지금 상태를 확인합니다.** 프로젝트 폴더에서 이렇게 물어봅니다.

```
이 프로젝트가 지금 데이터를 어디서 읽고 있는지 확인해줘.
데이터베이스에 실제로 연결돼 있나, 아니면 코드에 넣어 둔 데모 데이터로 돌고 있나?
근거가 되는 파일 이름과 함수 이름을 대고 답해줘.
```

**2. 데이터베이스 프로젝트를 하나 만듭니다.** Supabase에 가입하고 새 프로젝트를 만듭니다.
지역은 **서울**을 고릅니다. 만드는 데 1~2분 걸립니다.

**3. 스키마 파일을 통째로 실행합니다.** 프로젝트 안의 스키마 파일을 엽니다.

```bash
cat supabase/schema.sql
```

내용을 전부 복사해서, Supabase 화면의 **SQL Editor**에 붙여넣고 실행합니다.
왼쪽 **Table Editor**에 표들이 생겨 있으면 성공입니다. 지금은 줄이 하나도 없는 게 정상입니다.

**4. 연결에 필요한 값 두 개를 가져옵니다.** Supabase의 **Settings → API**에서 둘을 복사합니다.

- 프로젝트 주소 (`https://...supabase.co`)
- `anon` 키 — 브라우저에 나가도 되는 공개용 열쇠입니다

같은 화면에 `service_role`이라는 키가 하나 더 있습니다. **그건 오늘 안 씁니다.**
그건 모든 권한을 가진 열쇠라서, 브라우저 쪽에 넣으면 사고가 납니다. 3절에서 다시 다룹니다.

**5. 프로젝트 폴더에 `.env.local` 파일을 만들고 채웁니다.**

```bash
cp .env.example .env.local
```

```
NEXT_PUBLIC_SUPABASE_URL=여기에_복사한_프로젝트_주소
NEXT_PUBLIC_SUPABASE_ANON_KEY=여기에_복사한_anon_키
```

**이 파일은 절대 GitHub에 올라가면 안 됩니다.** 왜 그런지와 확인하는 법은 바로 다음 3절입니다.

**6. 다시 켭니다.** 이미 켜져 있었다면 **껐다가 다시** 켜야 합니다. 값은 켤 때 한 번만 읽습니다.

```bash
npm run dev
```

**7. 진짜로 저장되는지 확인합니다.** 화면에서 무언가를 하나 새로 만듭니다.
그리고 **Supabase의 Table Editor를 열어 그 줄이 보이는지** 봅니다.
화면에 보이는 것으로는 확인이 안 됩니다. **표에서 봐야 확인입니다.**

**8. 배포 쪽에도 같은 값을 넣습니다.** 배포 서비스 설정의 환경변수 자리에
`.env.local`과 **똑같은 이름, 똑같은 값**으로 넣고 다시 배포합니다.

이 장의 실습 재료로 쓰려던 뉴스레터 예제 저장소를 **실제로 내려받아 파일을 하나씩 열어 봤습니다.**
파일 25개짜리인데, **있는 것과 없는 것이 뚜렷하게 갈렸습니다.**

| 있는 것 | 없는 것 |
|---|---|
| 데이터베이스 **표 5개와 접근 규칙 6개** (완성돼 있음) | **결제 코드 — 없습니다** |
| **검사 자동 실행 파일** (타입·정리·테스트·빌드) | **로그인 코드 — 없습니다** |
| 지침 파일 · 요구사항 · 구조 문서 · 스킬 3개 | |
| AI에게 묻는 통로 1개 | |

「가격 계산」이라는 파일이 있어서 결제인 줄 알았는데, 열어 보니 **값을 곱하고 나누는 계산 함수**였습니다.
결제사에 요청을 보내는 코드도, 결제 결과를 받는 코드도 없습니다.
결제사 이름은 **환경변수 예시 파일과 계획 문서에만** 적혀 있습니다. 이메일 발송 도구도 **설치만 돼 있고 쓰는 코드가 없습니다.**

> **그래서 이 저장소는 「완성된 예제」가 아니라 「출발점」입니다.**
> 데이터가 앉을 자리와 문 앞 검사는 세워져 있고, **돈과 로그인은 이 장에서 직접 붙이는 것**입니다.
> 남이 다 해 놓은 것을 구경하는 것보다, 절반이 비어 있는 것을 채우는 쪽이 훨씬 많이 남습니다.

## ✅ 확인

- [ ] 데이터베이스 화면의 Table Editor에 **표가 보이나**
- [ ] 화면에서 하나 만든 뒤, **그 줄이 Table Editor에도 보이나**
- [ ] **새로고침을 해도** 그대로 있나
- [ ] **다른 기기**에서 열었을 때도 같은 것이 보이나
- [ ] 이제 이 프로젝트가 **데모 데이터가 아니라 데이터베이스에서 읽고 있다**고 말할 수 있나 — 근거가 표에 있나
- [ ] 배포된 주소에서도 같은 데이터가 보이나
