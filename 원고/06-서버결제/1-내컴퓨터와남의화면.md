## 왜 이걸 하나

Stage 5까지 오면 화면에 무언가가 뜹니다. 그러면 이렇게 하고 싶어집니다 —
"이거 친구한테 보여줘야지." 그래서 주소창의 글자를 복사해서 카톡으로 보냅니다.
상대방은 **아무것도 열리지 않는다**고 답합니다.

여기서 많은 사람이 "내가 뭘 잘못했나" 하고 멈춥니다. 잘못한 게 아닙니다.
**아직 남에게 줄 수 있는 것을 만들지 않았을 뿐입니다.**

이 절을 건너뛰면 뒤의 모든 것이 헛돕니다. 로그인을 붙여도 나만 로그인하고,
결제를 붙여도 나만 결제합니다. **남이 열 수 있는 주소가 없으면 사용자가 없습니다.**

## 지금 내 화면에 뜬 것의 정체

주소창에 `localhost:3000` 같은 글자가 보일 겁니다.

`localhost`는 영어로 "이 컴퓨터"라는 뜻입니다. 주소가 아니라 **"여기"**라는 말입니다.
그래서 남이 그 글자를 쳐도 남의 컴퓨터에서는 남의 컴퓨터를 가리킵니다. 내 것이 아니라.

집 안에서 방 이름을 부르는 것과 같습니다. 우리 집에서 "안방"은 통하지만,
그 말을 남에게 보내면 남은 **자기 집 안방**을 봅니다.

### 폴더째 보내면 되지 않나요

안 됩니다. 세 가지가 그쪽에 없기 때문입니다.

| 없는 것 | 그래서 |
|---|---|
| 코드를 돌려주는 프로그램 | 상대는 개발 도구를 깔아야 합니다 |
| 내가 채워 둔 비밀값 | 그건 애초에 보내면 안 되는 것입니다(3절) |
| 늘 켜져 있는 컴퓨터 | 내 노트북을 닫으면 사이트도 닫힙니다 |

## 그래서 필요한 것 셋

### ① 주소 — 남이 칠 수 있는 이름

인터넷의 컴퓨터에는 숫자로 된 번호가 붙어 있습니다. 사람이 외우기 어려우니
그 번호에 이름을 붙여 놓은 것이 **주소(도메인)**입니다. `example.com` 같은 것.

처음에는 **내 이름을 살 필요가 없습니다.** 배포 서비스가 공짜 주소를 하나 줍니다.
`내프로젝트이름.vercel.app` 같은 형태입니다. 이것도 완전한 주소입니다. 남이 엽니다.
내 이름을 가진 주소는 팔 사람이 생겼을 때 사도 늦지 않습니다.

### ② 서버 — 늘 켜져 있으면서 답하는 컴퓨터

누군가 주소를 치면 **누군가는 답을 해 줘야** 합니다.
그 답하는 쪽을 서버라고 부릅니다. 특별한 기계가 아니라, **꺼지지 않는 컴퓨터**입니다.

내 노트북을 서버로 쓸 수도 있지만 하지 않습니다. 노트북을 닫으면 사이트가 죽고,
집 인터넷이 끊기면 사이트가 죽고, 내 컴퓨터가 인터넷에 그대로 노출됩니다.
**남의 컴퓨터를 빌립니다.** 그게 Vercel 같은 배포 서비스가 파는 것입니다.

### ③ 빌드 — 내가 쓴 것을 브라우저가 읽을 수 있게 바꾸는 일

내가 쓴(정확히는 AI가 쓴) 코드는 사람이 읽기 좋게 생겼습니다.
브라우저는 그걸 그대로는 빠르게 못 읽습니다. 그래서 배포하기 전에 한 번
**번역하고 압축하는 과정**을 거칩니다. 이걸 빌드라고 합니다.

빌드는 컴퓨터가 알아서 합니다. 다만 **여기서 처음으로 진짜 오류가 납니다.**
내 컴퓨터에서는 대충 넘어가던 것을 빌드는 안 넘어가 주기 때문입니다. 그건 좋은 일입니다.
빌드가 잡아 준 것은 사용자가 안 겪습니다.

## 어떻게 이어지나

```
내 컴퓨터의 폴더
      │  올린다(push)
      ▼
   GitHub 저장소          ← Stage 4.5에서 만든 것
      │  "새 코드가 왔다"고 알림
      ▼
   배포 서비스
      │  ① 코드를 내려받고
      │  ② 빌드하고
      │  ③ 자기 서버에 올린다
      ▼
   https://내주소   ← 남이 여는 곳
```

**한 번 연결해 두면 그 다음부터는 자동입니다.** 코드를 GitHub에 올리기만 하면
배포 서비스가 알아서 새로 짓고 바꿔 답니다. 이 자동 연결을 더 다듬는 건 Stage 7입니다.

## 📘 말 풀이

**주소(domain)**
`example.com`처럼 사람이 칠 수 있는 인터넷 이름. 그 뒤에는 숫자로 된 진짜 번호가 있습니다.
처음에는 배포 서비스가 주는 공짜 주소로 충분합니다.

**서버(server)**
꺼지지 않고 켜져 있으면서, 누가 주소를 치면 화면을 내려 주는 컴퓨터.
내 노트북 말고 남의 컴퓨터를 빌려 씁니다.

**빌드(build)**
내가 쓴 코드를 브라우저가 빨리 읽을 수 있는 형태로 번역·압축하는 과정.
여기서 나는 오류는 사용자가 안 겪는 오류라서, 나면 다행입니다.

## ⚠️ 자주 걸리는 함정

- **`localhost:3000`을 남에게 보낸다** — 가장 흔합니다. 그건 "여기"라는 말이지 주소가 아닙니다.
- **"내 컴퓨터에서는 되는데요"** — 배포본만 죽는 원인은 거의 셋입니다.
  ① **비밀값을 배포 쪽에 안 넣었다**(가장 흔함, 3절) ② **파일 이름의 대소문자**가 다르다
  ③ 내 컴퓨터와 서버의 프로그램 판이 다르다.
  ②는 특히 맥에서 안 걸립니다. 맥은 `Header.tsx`와 `header.tsx`를 같은 것으로 보는데
  서버는 다른 것으로 봅니다. **내 컴퓨터에서만 되는 이름이 되어 버립니다.**
- **와이파이로 확인한다** — 내 휴대폰이 같은 와이파이에 있으면 "남의 기기"가 아닐 수 있습니다.
  **와이파이를 끄고 데이터로** 열어 봐야 진짜 확인입니다.
- **처음부터 내 도메인을 산다** — 아직 팔 것이 없습니다. 공짜 주소로 먼저 남에게 보여 주세요.
- **비공개 저장소인데 배포가 안 붙는다** — 저장소를 배포 서비스에 볼 수 있게 권한을 줘야 합니다.

## ⚡ 이렇게 하세요

1. Stage 4.5에서 만든 GitHub 저장소에 지금 코드가 올라가 있는지 확인합니다.
2. 올리기 전에 **빌드가 내 컴퓨터에서 되는지** 먼저 봅니다. 여기서 걸리면 배포에서도 걸립니다.

```bash
npm run build
```

3. 배포 서비스(Vercel)에 GitHub 계정으로 들어가서, 그 저장소를 고르고 배포를 누릅니다.
4. 배포가 끝나면 주소가 하나 나옵니다. 그 주소를 **휴대폰에서 와이파이를 끄고** 엽니다.
5. 빌드가 실패하면 화면에 나온 오류를 **줄이지 말고 그대로** AI에게 줍니다.

```
아래는 배포 빌드 로그다. 내 컴퓨터에서는 되는데 배포에서만 실패한다.
원인을 하나로 좁히고, 고쳐야 할 파일과 줄을 알려줘. 추측이면 추측이라고 말해줘.

(여기에 오류를 그대로 붙여넣기)
```

6. 여기서 "환경변수가 없다"는 말이 나오면 정상입니다. **3절에서 채웁니다.**

## ✅ 됐는지 확인

- [ ] `npm run build`가 **끝까지 성공**했나
- [ ] `localhost`가 아닌 주소가 하나 생겼나
- [ ] **내 컴퓨터를 끄거나 닫은 상태에서** 그 주소가 열리나
- [ ] **남의 기기**에서 열리나 — 휴대폰 와이파이를 끄고 데이터로 열어 봤나
- [ ] 화면이 뜨긴 하는데 **데이터가 비어 있나** (그러면 정상입니다. 2절로 갑니다)

하나라도 «아니오»면 이 절을 다시 봅니다. 특히 마지막에서 두 번째가 이 절의 전부입니다.
