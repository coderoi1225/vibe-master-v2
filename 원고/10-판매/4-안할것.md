사람들에게 보여 주기 시작하면 곧 "○○ 기능도 있으면 좋겠는데요"가 들어옵니다. 혼자 하는 사람의 시간은 정해져 있고 요청은 정해져 있지 않아서, 다 따라가면 여섯 달 뒤 아무것도 제대로 안 되는 물건 하나가 남습니다.

## ① 안 할 것을 파일로 못 박는다

할 일 목록은 유혹이 왔을 때 힘이 없습니다. 한 줄 더 적으면 그만이니까요. 막아 주는 건 **"이건 안 하기로 이미 정했다"** 한 줄입니다.

| | 할 일 목록 | 안 할 것 목록 |
|---|---|---|
| 유혹이 왔을 때 | 한 줄 추가하면 끝 | 정한 것을 뒤집어야 함 |
| 남에게 거절할 때 | 근거가 없음 | "그건 안 하기로 정했습니다" |
| 여섯 달 뒤 | 늘어나 있음 | 그대로 있음 |

```markdown
안 할 것 — [날짜]

이건 안 한다:
- 한 사람만 말한 기능 — 세 사람이 같은 말을 하기 전에는 안 만든다
- 내가 안 쓸 기능 — 내가 매일 안 쓰는 것은 남도 안 쓴다
- 「나중에 필요할 것 같아서」 미리 만드는 것
- [내 서비스에만 해당하는 것 두세 개를 여기에]

미룬 것 (지운 게 아니다):
- [거절한 요청과 누가 말했는지]

이건 언제 다시 볼까:
- 세 사람이 같은 요청을 하면 → 그때 다시 본다
- 지금 하는 것이 끝나면 → 그때 다시 본다

요청이 들어오면 이 순서로 본다:
1. 판단 기준 파일에 걸리나 → 걸리면 여기서 끝
2. 세 사람 이상이 같은 말을 했나 → 아니면 적어만 두고 안 만든다
3. 지금 만들고 있는 것을 멈춰야 하나 → 멈춰야 하면 안 한다
```

## ② 들어온 요청을 대 본다

[[09-지식운영/_스테이지|Stage 9]]에서 적은 판단 기준 파일이 여기서 실제로 쓰입니다. 요청이 들어올 때마다 처음부터 고민하지 않고, 두 파일에 대 봅니다. AI에게 두 파일을 같이 읽히면 **내 기준대로** 답합니다.

## ③ 이 장에서 되는 것과 안 되는 것을 가른다

첫 유료 사용자는 커리큘럼으로 만들어지지 않습니다 — 실제로 팔아야 생깁니다. 소개 한 장, 다섯 명, 판단선은 **팔 준비**이지 파는 일이 아닙니다. 파는 일은 값을 정해서 사람에게 말을 걸고 거절을 여러 번 듣는 일이라, 적어서 되는 게 아니라 해야 되는 일입니다.

| 이 장에서 되는 것 | 이 장에서 안 되는 것 |
|---|---|
| 처음 보는 사람이 30초 안에 알게 만들기 | 첫 결제 받기 |
| 다섯 명 앞에서 막히는 데 찾기 | 값을 얼마로 정할지 |
| 방향을 바꿀 선을 미리 정하기 | 계속 쓰게 만드는 운영 |

값 정하기·고객 응대·운영은 다음 버전에서 따로 다룹니다.

## ⚡ 따라 하기

1. ①의 「안 할 것」 틀을 파일로 만들어 Stage 9의 판단 기준 파일 옆에 두세요. 같은 폴더에 두 파일이 나란히 보이면 됩니다.
2. 지금 하고 싶은 것 중 세 개를 골라 「이건 안 한다」에 먼저 넣으세요. 남이 요청한 것 말고 내가 만들고 싶은 것부터 — 유혹은 대개 밖이 아니라 안에서 옵니다. 세 줄이 채워지면 됩니다.
3. 새 대화를 열고 아래를 붙여넣은 뒤, 두 파일과 2절에서 받아 적은 요청을 넣으세요. 요청마다 「지금 만든다 / 적어만 둔다 / 안 한다」가 돌아옵니다.

```
아래 두 가지를 읽고, 들어온 요청들을 분류해라.

1. 각 요청이 "안 할 것" 목록에 걸리나. 걸리면 어느 줄에 걸리는지 그대로 인용해라
2. 걸리지 않은 것 중에서, 같은 말을 세 사람 이상이 한 것이 있나
3. 2번에 해당하는 것이 없으면 "지금 만들 것 없음"이라고 답해라.
   억지로 하나를 고르지 마라
4. 각 요청을 "지금 만든다 / 적어만 둔다 / 안 한다" 셋 중 하나로 나눠라

새 기능을 제안하지 마라. 내가 준 목록 안에서만 판단해라.

--- 안 할 것 목록 ---
[파일 내용 붙여넣기]

--- Stage 9의 판단 기준 파일 ---
[파일 내용 붙여넣기]

--- 들어온 요청 ---
[다섯 명에게 들은 것 붙여넣기]
```

4. "지금 만들 것 없음"이 나와도 그대로 받아들이세요. 그게 오히려 흔한 답입니다.
5. 안 하기로 한 것은 지우지 말고 **「미룬 것」** 칸에 옮기세요. 세 번째 사람이 같은 말을 할 때 바로 알아봅니다. 그 칸이 채워지면 이 장이 끝난 것입니다.

## ✅ 확인

- [ ] 「이건 안 한다」 목록이 파일로 있고, 내가 만들고 싶었던 것이 하나라도 들어 있나
- [ ] 거절한 요청을 지우지 않고 「미룬 것」에 적어 뒀나
- [ ] 「첫 결제는 아직 없다」를 그대로 인정하고 있나

## 📘 말 풀이

**기능 요청(feature request)** — 쓰는 사람이 "이것도 있으면 좋겠다"고 말하는 것. 요청은 정보이지 할 일이 아닙니다.

**기능 비대(feature creep)** — 거절을 못 해서 기능이 계속 늘어나다가, 결국 무엇을 위한 물건인지 아무도 모르게 되는 상태.

## ⚠️ 함정

**머릿속에만 둡니다.** 안 적은 원칙은 유혹 앞에서 없는 것과 같습니다. 파일로 있어야 합니다.

**첫 결제를 받은 척합니다.** 본인 카드로 결제해 보는 건 기능 확인이지 판매가 아닙니다. 헷갈리면 판단이 통째로 틀어집니다.
