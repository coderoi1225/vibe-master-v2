도구를 둘 쓰면 위험이 **더해지는 게 아니라 곱해집니다.** 왜 그런지와, 오늘 30분 안에 막을 수 있는 것 셋.

## 왜 이걸 하나

Stage 0에서 도구를 둘 고르고, Stage 7에서 커밋 직전에 다른 도구로 리뷰를 받습니다. 그 구성이 **왜 순차여야 하는지**의 답이 이 장에 있습니다.

이 장을 건너뛰면 이렇게 됩니다. 두 도구를 동시에 켜 두고 같은 폴더에서 돌립니다. 편해 보입니다. 그런데 **한쪽에 뚫린 구멍이 다른 쪽으로 그대로 이어집니다.** 그리고 뚫린 줄 모릅니다 — 화면에는 아무 일도 안 일어나기 때문입니다.

## 한 문장으로

> **설정 파일에 쓸 수 있는 권한 = 코드를 실행할 수 있는 권한.**

AI 코딩 도구는 자기 폴더 안의 설정 파일과 지침 파일을 읽고 **거기 적힌 대로 명령을 실행합니다.** 그게 기능입니다. 그래서 누군가 그 파일에 한 줄을 넣을 수 있으면, 그 사람은 **내 컴퓨터에서 명령을 실행할 수 있는 것**과 같습니다.

바이러스 파일을 심을 필요가 없습니다. **글자만 넣으면 됩니다.**

## 실제로 일어난 것 셋

교훈이 다릅니다. 셋 다 읽으세요.

### ① 도커 소켓 하나 → 에이전트 셋이 동시에 호스트에 닿았다

컨테이너 안에서 AI를 안전하게 돌리려고 격리를 했는데, **도커 소켓 하나를 컨테이너에 열어 줬습니다.** 그 순간 격리가 사라집니다. 도커 소켓은 "컨테이너를 마음대로 만들고 지울 수 있는 손잡이"라서, 그걸 쥐면 **호스트 컴퓨터 전체에 닿습니다.**

에이전트가 셋 돌고 있었고, **셋 다 같은 손잡이를 쥐고 있었습니다.**

> **교훈** — 격리는 가장 약한 구멍의 크기만큼만 작동합니다.

### ② 악성 패키지가 홈 폴더를 훑어 발견되는 모든 AI 도구 설정에 훅을 주입했다

의존성으로 들어온 나쁜 패키지가 홈 폴더를 뒤져서, **거기 있는 AI 도구 설정 파일을 전부 찾아** 자동 실행되는 항목(훅)을 하나씩 심었습니다.

**백신에 안 잡혔습니다.** 악성 바이너리가 없었기 때문입니다. 심은 것은 **텍스트 한 줄**이었습니다.

> **교훈** — 도구가 둘이면 심을 자리도 둘입니다. 그리고 한 번의 침입으로 **양쪽이 동시에** 오염됩니다.

### ③ 저장소에 지침 파일을 넣었더니, 다섯 종의 에이전트가 저장소를 여는 순간 실행됐다

공개 저장소에 지침 파일을 하나 넣어 뒀습니다. 그 저장소를 **클론해서 열기만 하면** 에이전트가 그 파일을 읽고 시키는 대로 했습니다. 서로 다른 다섯 종류의 도구가 전부 걸렸습니다.

**사용자는 아무것도 클릭하지 않았습니다.** 저장소를 열었을 뿐입니다.

> **교훈** — 남의 저장소를 여는 것은 **남의 지시문을 내 도구에 먹이는 것**입니다.

### 그래서 왜 "곱하기"인가

| 도구가 하나일 때 | 도구가 둘일 때 |
|---|---|
| 뚫릴 자리가 하나 | 뚫릴 자리가 둘 |
| 설정 파일 한 벌 | 설정 파일 두 벌 — **한 침입으로 둘 다** |
| 권한을 한 곳에서 확인 | **어느 도구에 무슨 권한을 줬는지 헷갈림** |
| 최신 유지 대상 하나 | **하나만 낡아도 통로가 됨** |

> **가장 약한 하나가 나머지 전부의 통로가 됩니다.** 이것이 "더하기"가 아니라 "곱하기"인 이유입니다.

## 에이전트 둘의 법칙

기억할 것은 이 셋입니다.

| 셋 | 무슨 뜻인가 | 예 |
|---|---|---|
| **신뢰할 수 없는 입력** | 내가 안 쓴 글이 에이전트에게 들어감 | 남의 저장소 · 웹 페이지 · 사용자가 보낸 문의 · 이슈 본문 |
| **시크릿 접근** | 비밀값을 읽을 수 있음 | `.env` · API 키 · 데이터베이스 접속 정보 |
| **외부 통신** | 바깥으로 내보낼 수 있음 | 인터넷 요청 · 메일 발송 · 저장소 push |

> **한 에이전트가 이 셋을 동시에 가지면 안 됩니다.**

왜인지는 간단합니다. 셋이 모이면 **"남이 쓴 글을 읽고 → 내 비밀값을 찾아 → 바깥으로 보내는"** 경로가 완성됩니다. 중간에 사람이 없습니다.

**둘까지는 괜찮습니다.** 하나만 끊으면 됩니다.

| 상황 | 무엇을 끊나 |
|---|---|
| 남의 저장소를 열어 본다 | **시크릿 접근을 끊는다** — 그 폴더에 `.env`가 없게 |
| 비밀값을 다루는 작업을 한다 | **신뢰할 수 없는 입력을 끊는다** — 그 세션에서 웹을 안 읽게 |
| 인터넷에서 자료를 모은다 | **시크릿 접근과 push 권한을 끊는다** |

## AI 코드 검증 4종

AI가 짠 코드를 그대로 믿지 않기 위한 최소 장치 넷입니다. **회사들이 수렴한 한 문장은 이겁니다 — "AI가 초안을 쓰고, 사람이 수락한다. 수락한 사람이 책임진다."**

### ① 실패하는 테스트를 먼저

고쳐야 할 것을 **먼저 실패하는 테스트로** 만듭니다. 그다음에 AI에게 고치라고 합니다.

**왜** — AI는 *"고쳤습니다"*라고 아주 자신 있게 말합니다. 실패하던 테스트가 통과로 바뀌는 것을 보기 전에는 그 말이 근거가 없습니다.

### ② 검사 셋을 켠다 — 코드 검사 · 의존성 경보 · 시크릿 스캔

| 검사 | 무엇을 잡나 |
|---|---|
| **코드 검사** | 흔한 취약 패턴 |
| **의존성 경보** | 내가 쓰는 패키지에 알려진 구멍이 생겼을 때 알림 |
| **시크릿 스캔** | 키·비밀번호가 코드에 섞여 들어갔을 때 |

셋 다 **저장소 설정에서 켜는 것**이고, 켜는 데 몇 분 걸립니다. 공개 저장소인지 비공개 저장소인지에 따라 무료 범위가 다릅니다 — 「버전과 값」 절에서 확인 날짜와 함께 관리합니다.

### ③ 실서비스 자격증명을 격리한다

**AI가 도는 자리에 실서비스 키를 두지 않습니다.**

- 개발용 키와 실서비스 키를 **다른 파일·다른 프로젝트**로 분리합니다.
- 실서비스 데이터베이스에 붙는 키는 **내 컴퓨터에 아예 두지 않는 것**이 가장 안전합니다.
- 결제는 **테스트 모드**로만 개발합니다. (「돈 없이 어디까지」 절 참고)

**왜 이렇게까지 하나** — 코드 동결 기간에 에이전트가 실서비스 데이터베이스를 지운 일이 실제로 있었습니다. *"실서비스는 건드리지 마"*가 **지침 파일에만 적혀 있었고, 실행 경로에는 막는 장치가 없었습니다.** 글로 적은 규칙은 규칙이 아닙니다. **닿을 수 없게 만드는 것이 규칙입니다.**

### ④ 신뢰 못 할 콘텐츠를 실행시키지 않는다

- 웹에서 긁어 온 코드를 **AI에게 "실행해 봐"라고 하지 않습니다.** 읽게만 합니다.
- 남의 저장소를 열 때는 **자동 실행되는 훅이 있는지 먼저 봅니다.**
- 사용자 문의 내용을 에이전트에게 통째로 넘길 때는 **권한이 낮은 세션에서** 합니다.

## 그래서 순차 방식이 옳습니다

Stage 0에서 도구를 둘 고르고, Stage 7에서 커밋 직전에 리뷰를 받습니다. 그 구성은 이렇게 생겼습니다.

| | 순차 (권장) | 동시 |
|---|---|---|
| 어떻게 | 짜기는 도구 하나로. **커밋 직전에** 다른 하나로 리뷰 | 둘을 켜 두고 같은 폴더를 함께 만짐 |
| 실행 권한 | **한 번에 하나만** 파일을 만짐 | 둘 다 만짐 |
| 사고가 나면 | 어느 도구가 했는지 안다 | **누가 했는지 모른다** |
| 되돌리기 | 커밋 단위로 깔끔 | 서로 덮어써서 엉킴 |
| 리뷰 도구의 권한 | **읽기만** 주면 됨 | 쓰기를 줘야 함 |

> **둘을 동시에 켜 두는 구성은 비개발자 1인이 감당할 위험이 아닙니다.** 성능 이야기가 아니라 안전 이야기입니다.

그리고 순차 방식에는 덤이 있습니다 — **리뷰 도구에는 쓰기 권한을 안 줘도 됩니다.** 「에이전트 둘의 법칙」에서 한 축이 통째로 사라집니다.

> **정직하게** — 교차 리뷰가 **얼마나 이득인지는 측정된 적이 없습니다.** 많은 개발자가 그렇게 한다는 사실만 확인됐습니다. 하지만 **안전 면에서 순차가 나은 것은 별개로 참**입니다.

## 📘 말 풀이

**훅(hook)**
"이럴 때 이걸 자동으로 실행해라"를 적어 두는 자리. 편할수록 위험합니다 — **남이 여기에 한 줄을 넣으면 내 컴퓨터에서 그 줄이 자동으로 돕니다.**

**도커 소켓**
컨테이너(격리된 작은 방)를 만들고 지우는 손잡이. 이 손잡이를 방 안에 넣어 주면 **방 안에 있던 것이 방 바깥, 즉 내 컴퓨터 전체에 닿을 수 있게** 됩니다. 절대 노출하지 않습니다.

**프롬프트 인젝션**
남이 써 둔 글에 *"이제부터 이렇게 해"*라는 지시를 숨겨 두고, AI가 그 글을 읽으면서 지시로 착각해 따르게 만드는 공격. **AI에게는 자료와 명령이 똑같은 글자로 보입니다.**

## ⚠️ 자주 걸리는 함정

| 함정 | 왜 위험한가 |
|---|---|
| **`.env`를 프로젝트 폴더에 두고 AI를 그 폴더에서 돌린다** | AI가 파일을 읽는 것은 기능입니다. 막지 않으면 읽습니다 |
| **남의 저장소를 클론해서 바로 AI로 연다** | 저장소 안의 지침 파일이 **여는 순간** 실행될 수 있습니다 |
| **도커로 격리했으니 안전하다고 생각** | 소켓 하나를 열어 주면 격리가 없는 것과 같습니다 |
| **도구를 하나만 업데이트** | 낡은 쪽이 통로가 됩니다. **둘 다 최신으로** |
| **에러 로그를 통째로 복사해 붙임** | 로그 안에 **키·토큰·접속 정보**가 섞여 있을 수 있습니다 |
| **"자동 승인" 모드를 켜 두고 자리를 뜸** | 승인 창이 없다는 것은 **막을 사람이 없다**는 뜻입니다 |
| **백신을 믿음** | ②번 사례는 악성 파일이 없어서 안 잡혔습니다 |
| **취약점 번호를 검색해 그대로 인용** | 이름이 비슷한 **다른 제품의 것이 섞여 나옵니다.** 원문 대조 전에는 쓰지 않습니다 |

## ⚡ 이렇게 하세요

### 오늘 할 것 셋 (30분)

**① 두 도구를 최신으로 유지한다**

각 도구의 업데이트 확인 방법을 찾아 **오늘 한 번 실행**하고, 달마다 확인하는 날을 정합니다. 구체적인 명령과 최신 버전 번호는 **「버전과 값」** 절에서 확인 날짜와 함께 관리합니다.

**② `.env`를 에이전트가 못 읽게 막는다**

세 겹으로 막습니다.

```
1) .gitignore 에 넣는다        → 저장소에 안 올라간다
2) 도구 설정의 접근 금지 목록에 넣는다 → AI가 못 읽는다
3) 실서비스 키는 아예 안 둔다      → 있어도 개발용만
```

도구마다 접근 금지를 적는 자리가 다릅니다. **양쪽 도구에 각각 적어야 합니다** — 두 도구는 서로의 설정을 읽지 않습니다.

확인은 이렇게 합니다.

```
내 프로젝트의 .env 파일 내용을 그대로 보여 줘.
```

**"읽을 수 없습니다"** 또는 접근 차단 메시지가 나오면 성공입니다. 내용이 나오면 아직 안 막힌 것입니다.

**③ 도커 소켓을 절대 노출하지 않는다**

컨테이너 설정에서 아래 모양이 있으면 **지웁니다.**

```
/var/run/docker.sock
```

AI가 만들어 준 설정 파일에 이게 들어 있는 경우가 있습니다. **"편의를 위해"라는 주석이 붙어 있으면 특히 그렇습니다.** 지우고, 왜 필요한지 다시 물어보세요.

### 남의 저장소를 열기 전 30초 점검

```
이 저장소에서 아래를 찾아서 목록으로 보여 줘. 실행하지는 마.
1) AI 도구 지침 파일 (이름이 어떤 것이든)
2) 자동 실행되는 훅 설정
3) 설치·빌드 때 도는 스크립트
4) .env 파일이나 키처럼 보이는 값
```

**읽기만 시키는 것이 핵심입니다.** 목록을 보고 이상하면 열지 않습니다.

### 커밋 직전 리뷰를 시킬 때

리뷰 도구에는 **읽기 권한만** 줍니다. 그리고 이렇게 묻습니다.

```
이 변경분을 리뷰해 줘. 고치지는 말고 지적만 해 줘.
특히 이 넷을 봐 줘.
1) 키·비밀번호·토큰이 코드나 로그에 섞여 있나
2) 남이 보낸 값을 검사 없이 실행하거나 쿼리에 넣는 곳이 있나
3) 남의 데이터를 볼 수 있게 되는 경로가 있나
4) 실서비스 자격증명이 개발 코드에 닿는 곳이 있나

확실하지 않으면 "확인 필요"라고 적어 줘. 지어내지 마.
```
