증상으로 찾습니다. **원인을 몰라도 됩니다.** 화면에 보이는 것으로 찾으세요.

## 왜 이걸 하나

혼자 만들다 막히면 **막힌 것 자체보다 "이게 흔한 일인지 내가 이상한 건지 모르는 것"이 더 사람을 지치게 합니다.**

여기 있는 것들은 전부 **흔합니다.** 흔하다는 걸 아는 것만으로 절반은 풀립니다.

**쓰는 법 — 세 걸음**

1. 화면에 보이는 **증상**으로 찾습니다.
2. **먼저 볼 것**을 확인합니다. 대개 여기서 끝납니다.
3. 안 되면 **그래도 안 되면** 칸으로 갑니다.

> **버전 번호·요금이 필요한 항목은 여기에 적지 않았습니다.** 「버전과 값」 절에서 확인 날짜와 함께 봅니다.

## 🚑 먼저 — 여섯 가지 큰 상황

가장 자주, 가장 크게 막히는 자리입니다. 위의 카탈로그보다 먼저 보세요.

### ① 결제 연동이 막힐 때

| 증상 | 먼저 볼 것 | 그래도 안 되면 |
|---|---|---|
| 결제 창이 아예 안 뜬다 | 브라우저 개발자 도구의 콘솔. **키가 비어 있다**는 에러가 대부분 | 테스트 키와 실서비스 키를 **바꿔 넣었는지** 확인 |
| 결제는 되는데 **내 서버가 모른다** | 결제 대행사 대시보드의 웹훅 로그. **주소가 `localhost`로 박혀 있으면** 대행사가 못 부릅니다 | 배포된 주소로 웹훅 주소를 바꾸고, 대행사 대시보드에 **다시 등록** |
| 같은 결제가 **두 번 처리**된다 | 웹훅은 여러 번 올 수 있습니다. **처리한 결제 번호를 저장**하고 있는지 | 결제 번호를 유일 키로 저장 → 이미 있으면 그냥 성공 응답만 |
| 정기결제가 **다음 달에 실패** | 카드 만료·한도 초과가 대부분 | 실패 시 재시도 횟수와 **사용자 알림**을 정해 둡니다 |
| **금액이 다르게** 결제됐다 | 결제 금액을 **화면에서 받아 그대로 믿고 있지 않은지** | 금액은 **항상 서버가 다시 계산**합니다. 화면이 보낸 값을 믿지 않습니다 |
| 국내 간편결제로 **정기결제가 안 된다** | 계약 형태에 따라 **되는 것과 안 되는 것이 갈립니다** | 「버전과 값」 표 ④를 보고, 안 되면 통합 결제 서비스를 검토 |
| 해외 결제 서비스 가입이 **거절**된다 | 한국 판매자를 받는지 공식 지원 국가 페이지 확인 | 판매 대행(MoR) 방식을 검토 |

> ⚠️ **웹훅은 반드시 진짜인지 검증합니다.** 검증 없이 받으면 **아무나 "결제됐다"고 내 서버에 알릴 수 있습니다.** 대행사 문서의 서명 검증 절차를 그대로 구현하세요.
> ⚠️ **자동 환불을 만들지 마세요.** 환불은 사람이 누릅니다. 자동 환불은 분쟁을 만들고 되돌릴 수 없습니다.

### ② 로그인이 안 될 때

| 증상 | 먼저 볼 것 | 그래도 안 되면 |
|---|---|---|
| 로그인 후 **404 페이지** | 인증 서비스 설정의 **돌아올 주소(redirect URL) 목록**에 내 주소가 등록됐는지 | 개발용 주소와 배포용 주소를 **둘 다** 등록 |
| **배포본에서 로그인했는데 내 컴퓨터 주소로 돌아감** | 코드에 돌아올 주소가 **박혀 있지 않은지**. 화면 주소를 그대로 쓰면 이렇게 됩니다 | 돌아올 주소를 **환경변수**로 빼고, 배포 환경에 값을 넣습니다 |
| `invalid redirect_uri` 같은 에러 | 소셜 로그인 콘솔에 등록한 주소와 **글자 하나까지** 같은지. 끝의 슬래시, 앞뒤 공백 | 개발용 앱과 배포용 앱을 **따로** 만드는 것도 방법 |
| 로그인은 되는데 **이메일이 비어 있음** | 소셜 로그인의 **동의 항목** 설정. 이메일은 추가 심사가 필요한 경우가 있습니다 | 콘솔에서 필요한 신청 절차를 먼저 마칩니다. 며칠 걸립니다 |
| 한참 뒤에 **자동 로그아웃** | 인증 토큰의 만료 시간과 **자동 갱신**이 붙어 있는지 | 인증 서비스가 권장하는 표준 연동 방식을 그대로 씁니다 |
| **아무나 관리자 페이지에 들어감** | 화면에서만 숨겼고 **서버에서 안 막았을** 가능성 | 권한 확인을 **서버 쪽**에 둡니다. 화면 숨김은 보안이 아닙니다 |
| 데이터가 **빈 배열**로 온다 (에러는 없음) | 데이터베이스의 **행 단위 접근 정책**. 기본이 "전부 차단"입니다 | 정책을 만들고 **다른 계정 두 개로** 서로 안 보이는지 확인 |

### ③ 배포는 됐는데 남의 기기에서 안 열릴 때

**내 컴퓨터에서 되는 것과 남이 여는 것은 다릅니다.** 순서대로 확인하세요.

| # | 확인 | 어떻게 |
|---|---|---|
| 1 | **주소가 맞나** | 내 컴퓨터 주소(`localhost`)를 보내지 않았는지. 그 주소는 **그 컴퓨터에서만** 열립니다 |
| 2 | **환경변수가 배포 환경에 들어갔나** | 내 컴퓨터의 `.env`는 **올라가지 않습니다.** 배포 서비스 대시보드에 따로 넣습니다 |
| 3 | **화면에서 쓰는 값에 접두사가 붙었나** | 브라우저가 읽어야 하는 환경변수는 **정해진 접두사**가 있어야 합니다. 없으면 값이 비어 옵니다 |
| 4 | **빌드가 진짜 성공했나** | 배포 서비스의 빌드 로그. 실패했는데 **이전 버전이 그대로 떠 있는** 경우가 많습니다 |
| 5 | **주소 목록에 배포 주소를 등록했나** | 인증·결제·데이터베이스 각각의 허용 주소 목록 |
| 6 | **HTTPS 인증서가 발급됐나** | 직접 산 도메인을 붙였다면 DNS 설정이 퍼지는 데 시간이 걸립니다 |
| 7 | **로그인이 필요한 화면 아닌가** | 남에게는 로그인 화면만 보일 수 있습니다. **로그아웃 상태로 직접 열어 보세요** |
| 8 | **시크릿 창으로 열어 봤나** | 내 브라우저에만 남아 있는 로그인·캐시 때문에 나만 되는 경우 |

> **가장 빠른 확인법** — 휴대폰에서 **와이파이를 끄고** 그 주소를 엽니다. 이러면 내 컴퓨터·내 네트워크·내 브라우저가 전부 빠집니다.

### ④ 같은 에러가 세 번 반복될 때

**여기가 이 절에서 가장 중요합니다.**

> **세 번 같은 에러가 나오면 멈춥니다.** 네 번째 시도는 하지 않습니다.

AI는 안 되면 **다른 방법을 찾는 게 아니라 같은 방법을 조금 바꿔서 또 합니다.** 그러면 토큰만 타고 코드가 지저분해집니다.

**세 번째에 하는 것 — 순서대로**

| # | 무엇 | 왜 |
|---|---|---|
| 1 | **멈춘다** | 더 시켜도 같은 자리를 돕니다 |
| 2 | **되돌린다** | 세 번 시도하는 동안 붙은 임시 코드를 전부 버립니다. 되돌리기가 가장 빠른 복구입니다 |
| 3 | **에러를 요약하지 말고 그대로 붙인다** | *"에러가 나요"*가 아니라 **에러 전문을 통째로.** 줄 번호와 파일 이름이 답인 경우가 많습니다 |
| 4 | **로그를 먼저 붙인다** | 코드보다 로그입니다. 서버 로그·빌드 로그·브라우저 콘솔 |
| 5 | **전략을 바꾼다** | 같은 대화에서 또 시키지 않습니다. **새 대화를 열고 문제를 처음부터 다시 설명**합니다 |
| 6 | **더 작게 쪼갠다** | *"로그인이 안 돼"* → *"인증 서비스가 토큰을 주는 데까지는 되는지"* |

**세 번째에 쓰는 프롬프트**

```
같은 에러가 세 번 반복됐어. 지금까지의 방법은 버리자.

에러 전문:
[여기에 그대로 붙여넣기]

관련 로그:
[여기에 그대로 붙여넣기]

이렇게 해 줘.
1) 지금까지 시도한 방향이 왜 안 됐는지 먼저 말해.
2) 완전히 다른 접근을 두 가지 제안해.
3) 코드는 아직 고치지 마. 어느 쪽으로 갈지 내가 고를게.
```

**그리고 자동으로 멈추게 만들어 둘 수 있습니다.** Stage 3의 훅으로 *"같은 에러가 3회 반복되면 중단"*을 걸어 두는 것이 정석입니다.

### ⑤ 옵시디언 금고를 잘못 만들었을 때

**「새 금고 만들기」를 눌러 빈 폴더가 생기는 것이 가장 흔한 사고입니다.**

원인은 하나입니다 — **금고(vault)는 새로 만드는 게 아니라, 이미 있는 폴더를 여는 것**입니다.

| 증상 | 왜 | 어떻게 |
|---|---|---|
| 금고를 만들었는데 **안이 비어 있다** | 새 폴더를 만든 것입니다. 내 파일은 원래 폴더에 그대로 있습니다 | 빈 폴더를 **휴지통으로** 옮기고, **「폴더를 금고로 열기」**로 원래 폴더를 엽니다 |
| 빈 금고가 **두세 개** 생겼다 | 안 열려서 여러 번 눌렀습니다 | 안이 빈 것만 골라 휴지통으로. **파일이 있는 것은 건드리지 않습니다** |
| 파일이 사라진 것 같다 | 대개 **다른 금고를 보고 있는 것**입니다 | 왼쪽 아래에서 **금고 전환**으로 원래 금고를 고릅니다 |
| 열었는데 파일이 안 보인다 | 폴더 안에 폴더가 한 겹 더 있는 경우 | 파일 탐색기에서 실제 폴더 구조를 확인합니다 |
| 설정이 이상해졌다 | 금고마다 설정이 **따로**입니다 | 금고를 바꾸면 설정도 바뀝니다. 이상한 게 아닙니다 |

> **기억할 한 줄** — **금고는 그냥 폴더입니다.** 특별한 형식이 아닙니다. 그래서 이미 쓰던 폴더를 그대로 열면 됩니다. 그리고 **지울 때는 반드시 휴지통으로.** 완전 삭제하지 않습니다.

### ⑥ 깃허브 인증이 막힐 때

| 증상 | 왜 | 어떻게 |
|---|---|---|
| `Permission denied (publickey)` | 열쇠(SSH 키)를 안 만들었거나, 만든 열쇠를 계정에 안 등록했습니다 | ① 열쇠 만들기 ② **공개키**를 계정 설정에 등록 ③ 연결 시험 |
| 비밀번호를 넣으라는데 **계속 거부** | 비밀번호로는 안 됩니다. **토큰**이나 열쇠를 씁니다 | 계정 설정에서 접근 토큰을 만들어 비밀번호 자리에 넣습니다 |
| 예전에 되던 게 **갑자기 안 됨** | 토큰이 **만료**됐습니다 | 새로 만들고, 컴퓨터에 저장된 옛 토큰을 지웁니다 |
| **비공개** 저장소만 안 된다 | 토큰의 권한 범위에 비공개 저장소가 빠졌습니다 | 토큰을 다시 만들며 필요한 권한을 켭니다 |
| 회사 계정과 개인 계정이 **섞인다** | 컴퓨터에 저장된 인증 정보가 하나뿐이라 그렇습니다 | 저장된 인증 정보를 지우고 **쓸 계정으로 다시** 로그인 |
| **push가 거부**되고 파일이 크다는 말 | 100MB 넘는 파일은 못 올립니다 | 그 파일을 커밋에서 빼고 `.gitignore`에 넣습니다. **이미 커밋했으면 이력에서도 지워야** 합니다 |

> ⚠️ **여기서 가장 조심할 것** — 인증이 안 풀린다고 `--force`로 밀지 마세요. **남의 작업이 아니라 내 과거 작업이 사라집니다.** 되돌릴 방법은 Stage 4.5에 있습니다.

## 📚 카탈로그 — 증상으로 찾기

### AI 코딩 도구

| 증상 | 대개 이것 | 어떻게 |
|---|---|---|
| 명령이 **거부**된다 (permission denied) | 허용 목록에 그 명령이 없음 | 도구 설정의 허용 목록에 추가 → 도구 재시작 |
| 대화가 길어지자 **점점 이상해진다** | 앞의 결정을 잊고 이미 고친 걸 되돌립니다 | 다른 일이면 대화를 **새로** 시작. 같은 일이면 **압축.** **한 작업 = 한 대화**가 원칙 |
| **"끝났습니다"인데 안 끝남** | 자동 검증 훅이 통과 못 하는데 계속 재시도 | 멈추고 **사람이 로그를 직접** 봅니다. 훅에 **시도 횟수 제한**을 겁니다 |
| **지침 파일을 무시**한다 | 지침이 너무 길거나, 절대 규칙이 눈에 안 띔 | 지침을 짧게. 절대 규칙은 **"절대"라는 말로 명확히.** 진짜 절대 규칙은 **훅으로 강제** |
| 비용이 **갑자기 크게** 늘었다 | 큰 파일을 통째로 첨부 / 무거운 모델 / 생각을 너무 많이 시킴 | 가벼운 모델로 바꾸고, 파일은 **필요한 부분만** 붙입니다. 사용량 확인을 습관으로 |
| 외부 도구(MCP) **연결 실패** | 패키지를 못 찾거나 토큰 만료 | 터미널에서 그 명령을 **직접 실행**해 진짜 에러를 봅니다 |
| 자동 생성된 지침 파일이 **일반론뿐** | 자동 생성은 내 프로젝트를 모릅니다 | 지우고 **직접 씁니다.** 진짜 겪은 실수만 적습니다 |

### 데이터베이스

| 증상 | 대개 이것 | 어떻게 |
|---|---|---|
| 응답은 성공인데 **데이터가 빈 배열** | 행 단위 접근 정책이 전부 막고 있음 (기본이 차단) | 정책을 만듭니다. 표를 만들 때 **정책도 같이** 만드는 습관 |
| **다른 사람 데이터가 보인다** | 정책의 비교 대상 칸이 잘못됨 | 즉시 막고 다시 작성. **계정 두 개로 반드시 검증** |
| 파일 업로드가 **401** | 저장소 버킷에도 정책이 필요합니다 | 읽기·쓰기·수정·삭제 정책을 **네 개 다** 만듭니다 |
| 브라우저 콘솔에 **CORS 차단** | 브라우저에서 직접 부르고 있음 | **서버 쪽에서** 부르도록 바꿉니다 |
| **서비스 키를 저장소에 올렸다** | `.gitignore` 누락 | ① **키를 즉시 재발급** ② 파일 제외 ③ **이력에서도 제거.** 순서대로. 재발급이 먼저입니다 |

### 배포

| 증상 | 대개 이것 | 어떻게 |
|---|---|---|
| **"값이 필요합니다"** 류의 에러 (가장 흔함) | 배포 환경에 환경변수를 안 넣음 | 배포 서비스 대시보드에 넣고 **다시 배포** |
| 브라우저에서 환경변수가 **비어 있다** | 접두사 규칙을 안 지킴 | 화면에서 쓸 값에만 정해진 접두사를 붙입니다. **비밀값에는 절대 붙이지 않습니다** |
| 빌드 실패 — 타입 에러 | 내 컴퓨터에서는 검사 없이 돌았습니다 | 로그의 **첫 번째** 에러부터 고칩니다. 뒤엣것은 대개 파생입니다 |
| 서버 함수가 **시간 초과** | 오래 걸리는 작업을 요청 안에서 다 함 | 작업을 쪼개거나 **예약 실행**으로 옮깁니다 |
| 도메인 붙였는데 **인증서가 안 나옴** | DNS 설정이 아직 퍼지지 않음 | DNS 값을 다시 확인하고 기다립니다. 그래도 안 되면 도메인 등록처 설정 |
| 함수가 **404** | 파일 위치나 이름 규칙이 안 맞음 | 프레임워크의 폴더 규칙을 확인합니다 |

### 자동화 워크플로

| 증상 | 대개 이것 | 어떻게 |
|---|---|---|
| **도커에 연결할 수 없다** | 도커가 안 켜져 있음 | 도커를 실행합니다. **소켓을 컨테이너에 열어 주지는 마세요**(「보안」 절) |
| 워크플로가 **무한 반복**해 API를 폭주시킴 | 자기 자신을 다시 부르는 고리 | **실행 횟수 상한**을 먼저 걸고 고칩니다. 비용이 먼저 터집니다 |
| **429** — 너무 많이 불렀다는 응답 | 초당 호출 한도 초과 | 사이에 대기를 넣고, 한 번에 여러 건을 묶어 보냅니다 |
| 예약이 **엉뚱한 시간**에 돈다 | 시간대 설정이 다름 | 워크플로의 시간대를 **명시적으로** 지정합니다 |
| 워크플로 파일에 **비밀값이 그대로** | 값을 직접 적었습니다 | 자격증명 저장 기능으로 옮깁니다. **워크플로 파일은 내보내면 그대로 보입니다** |

### AI API

| 증상 | 대개 이것 | 어떻게 |
|---|---|---|
| **401** 인증 실패 | 키가 틀렸거나, 환경변수가 안 읽힘 | 키 앞뒤 공백·줄바꿈 확인. 배포 환경에도 넣었는지 |
| 청구액이 **예상의 몇 배** | 긴 프롬프트 반복 / 무거운 모델 / 재시도 고리 | **먼저 상한을 겁니다.** 그다음 원인을 찾습니다 |
| 응답이 **중간에 잘림** | 출력 길이 상한 | 상한을 올리거나 **나눠서** 요청합니다 |
| 자료 기반 답변이 **엉뚱하다** | 찾아온 문서가 질문과 무관 | 먼저 **무엇을 찾아왔는지** 확인합니다. 답이 아니라 검색이 문제인 경우가 많습니다 |
| 사용자가 **숨긴 지시문을 뽑아낸다** | 프롬프트 인젝션 | 시스템 지시에 비밀을 담지 않습니다. **비밀은 서버에 두고 모델에 넣지 않습니다** |

### 깃과 일반

| 증상 | 대개 이것 | 어떻게 |
|---|---|---|
| **`.env`가 올라갔다** | `.gitignore` 누락 | ① **모든 키 재발급** ② 파일 제외 ③ 이력 제거. **재발급이 항상 먼저** |
| **충돌**이 났다 | 같은 줄을 둘이 고침 | 표시된 부분에서 남길 쪽을 고릅니다. AI에게 **양쪽 의도를 설명**하면 잘 도와줍니다 |
| 잘못된 커밋을 만들었다 | — | **아직 안 밀었으면** 로컬에서 되돌리고, **이미 밀었으면** 되돌리는 커밋을 새로 만듭니다 (Stage 4.5) |
| 날린 것 같다 | — | **먼저 `reflog`를 봅니다.** 대개 아직 살아 있습니다 |

## 📘 말 풀이

**웹훅(webhook)**
바깥 서비스가 **일이 생기면 내 서버 주소로 알려 주는 전화.** 결제가 끝났을 때 결제 회사가 내 서버에 거는 전화라고 생각하면 됩니다. 내 서버 주소가 바깥에서 닿을 수 있어야 걸립니다.

**환경변수**
코드 바깥에 따로 적어 두는 값. 키·비밀번호·주소처럼 **환경마다 달라지고 남에게 보이면 안 되는 것**을 여기 둡니다. 내 컴퓨터의 값은 배포 환경으로 **자동으로 따라가지 않습니다.**

**금고(vault)**
옵시디언이 여는 **폴더 하나.** 특별한 파일 형식이 아니라 그냥 마크다운 파일이 들어 있는 보통 폴더입니다.

## ⚠️ 자주 걸리는 함정

| 함정 | 왜 |
|---|---|
| **에러를 요약해서 전달** | 답이 대개 요약에서 잘려 나간 부분에 있습니다. **그대로 붙이세요** |
| **네 번째 시도** | 세 번 같으면 방법이 틀린 것입니다. 멈추고 되돌립니다 |
| **키가 새어 나갔는데 파일부터 지움** | **재발급이 먼저**입니다. 파일을 지워도 이미 나간 키는 살아 있습니다 |
| **금고를 지우면서 완전 삭제** | 휴지통으로 옮깁니다. 잘못 고른 폴더일 수 있습니다 |
| **`--force`로 밀기** | 내 과거 작업이 사라집니다 |
| **실서비스에서 바로 시험** | 테스트 모드와 개발용 키가 있는 이유입니다 |
| **비용 문제인데 원인부터 찾기** | **상한을 먼저 겁니다.** 원인은 그다음입니다 |
