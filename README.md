# 바이브마스터 버전2 — 웹서비스 개발

**직장인·비개발자 한 사람이 웹서비스 하나를 기획해서 만들고 내놓기까지.**
14장 96절. 앞 장에서 나온 것이 뒤 장의 재료가 됩니다.

## 무엇이 다른가

**절마다 다섯 칸이 붙습니다.**

| 칸 | 무엇 |
|---|---|
| 왜 이걸 하나 | 건너뛰면 뒤에서 무엇이 막히는지 |
| 📘 말 풀이 | 용어를 그 자리에서 두 줄로. 한 절에 셋을 넘지 않게 |
| ⚠️ 자주 걸리는 함정 | 실제로 걸린 자리만 |
| ⚡ 이렇게 하세요 | 그대로 따라 하면 돌아가는 것 |
| ✅ 됐는지 확인 | **화면에 무엇이 보이면 성공인가.** 예·아니오로 |

**자가 체크는 전부 예/아니오입니다.** "이해했나"는 체크가 아닙니다.
하나라도 «아니오»면 다음 장으로 가지 않고 그 절로 돌아갑니다.

**돌려 본 것만 「이렇게 해 봤습니다」로 적습니다.** 남의 사례와 직접 잰 것을 섞지 않습니다.
확인 못 한 값은 지어내지 않고 `[확인 필요]`로 둡니다 — **빈칸보다 나쁜 것이 틀린 값입니다.**

## 장

| 장 | 학습 목적 |
|---|---|
| 0 환경 | AI가 내 자료를 읽고 내 도구를 쓰게 하는 자리를 만든다 |
| 1 시장 | 만들기 전에 팔릴지 숫자로 답한다 |
| 2 명세 | 만들 것을 글로 먼저 정하고 AI가 매번 읽게 한다 |
| 3 컨텍스트·하네스 | 매번 설명하지 않게 만들고, 지켜야 할 것을 강제한다 |
| 4 디자인 | 감각이 아니라 규칙으로 만들고 AI 티를 지운다 |
| 4.5 버전 관리 | 되돌릴 수 있게 만든다. 그래야 과감히 시킨다 |
| 5 구현 | 시키고, 검증하고, 막히면 푼다 |
| 6 서버·인증·결제 | 남이 열 수 있는 주소를 만들고 돈 받는 길을 안다 |
| 7 배포·PR | 문 앞에 검사를 세운다 |
| 8 자율 운영 | 내가 없어도 돌고, 문제가 생기면 나를 부른다 |
| 9 지식 운영 | 한 번 한 일이 다음의 재료가 되게 한다 |
| 10 판매 | 만든 것을 남 앞에 내놓는 최소한 |
| 업무 자동화 | 회사 일의 반복을 덜어낸다 (별도 섹션) |
| 부록 | 법무·세무 · 보안 · 버전과 값 · 트러블슈팅 · 돈 없이 어디까지 |

## 굽는 법

```bash
python3 발행/build.py     # → 발행/바이브마스터v2.html 한 장
```

절 마크다운을 읽어 **한 장짜리 HTML**로 굽습니다. 검색은 페이지 안 자바스크립트로 돌고,
읽은 표시는 보는 사람 기기에만 남습니다. 서버도 로그인도 없습니다.

이 폴더는 **옵시디언 금고**이기도 합니다. 옵시디언에서 고치고 다시 구우면 그대로 반영됩니다.

## 문 앞의 검사

`.github/workflows/문지기.yml` 이 네 가지를 봅니다 — 발행이 되나 / 절마다 필수 칸이 있나 /
코드블록 짝이 맞나 / 비밀값이 섞이지 않았나.

> ⚠️ 작업 아이디(`jobs:` 아래 이름)에는 한글을 못 씁니다. 0초 만에 실패하고 로그도 안 남습니다.
> 보이는 이름(`name:`)만 한글로 씁니다.

## 여기 없는 것

`재료/`(원본 자료)와 `작업표.md`(작업 기록)는 이 저장소에 올리지 않습니다.
남의 저작물과 개인 기록이 섞여 있어 따로 보관합니다.
